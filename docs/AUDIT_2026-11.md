### Stage 3: medium features

**F3 side chat (`/side`).** A question beside the main chat that never enters its history.
- Server: `POST /api/conversations/:id/side { text }` → `modelTurnFor(registry, conv.modelId)` with the main chat's
  messages as context (read-only, no tools, no memory write) and the side question; streams the answer; nothing is
  appended to the session. Keep the side thread in memory per chat (lost on restart: say so).
- Web: `chat/SideChat.tsx`, a narrow panel (a sheet on the phone) opened by `/side` or a header button; its own box.
- Check: the main chat's event count is the same before and after; works while the main chat is answering (uses the
  engine's second slot: `parallel` ≥ 2, else it waits and says so).

**F6 file previews.** Word, Excel, PowerPoint, CSV, GLB in the chat and the Files panel.
- Needs libraries (ask Roee first, AGENTS.md): `mammoth` (docx → HTML), `xlsx` or `exceljs` (sheets), CSV needs none,
  GLB with `three` (already pulled in by nothing: check size, load lazily like Excalidraw). PowerPoint: text and
  pictures per slide only (no library renders it faithfully in a browser): say "open in PowerPoint" for the rest.
- Where: `FilePreview.tsx` switch by extension; HTML from mammoth goes through the same sanitizer as chat markdown.
- Security: previews run in the page: no scripts from the file, images only as blobs, a size cap (20 MB).

**F7 Git panel.** In code chats, beside Files.
- Server: `routes/git.ts` exists (status, diff, log). Add `stage`, `unstage`, `commit { message }`, `branches`,
  `checkout`; never `push --force`, `reset --hard` or history rewrites from the panel; every write asks like the
  agent's git tools do.
- Web: `chat/GitPanel.tsx`: changed files with letters (M/A/D), a diff view (reuse the chat's diff renderer), a
  message box with "Write it for me" (the chat model summarises the staged diff), Commit.

**F18 charts inside the answer.** A fenced block ```` ```chart ```` with JSON `{ type: "bar"|"line"|"pie", labels, series }`
rendered as SVG by `RichText` (no library); the system prompt gets one line telling the model about it. Mermaid
needs a library (large): only if Roee asks.

**F10 "Auto" approvals with a reviewer.** `PermissionMode` gets `"auto-review"`: before a tool call that would ask,
a small model (the helper model in Settings → Chats) gets the call and the last user message and answers
`allow | ask`; `allow` only for calls with `risk: "edit"` inside the project; anything else still asks. Log every
decision in the chat ("approved by the reviewer"). Scan it like a security feature: a prompt injection in a file must
not be able to talk the reviewer into `allow` (the reviewer never sees tool output, only the call).

**S2 keys at rest.** `apps/desktop` exposes `safeStorage.encryptString/decryptString` to the server through
`options` (like `options.notify`); `config.ts` writes `apiKey` as `enc:v1:<base64>` and reads both forms; on a
headless run (no Electron) keys stay as they are and Settings says so. Migration: on first save. Test: a config
written encrypted loads on the same machine, and a plain one still loads.

### Stage 4: big, each needs Roee's yes first

**F1 a model on the phone itself.** Research is not done: the app is Capacitor (a WebView), so the engine must be a
native plugin. Options to compare before building: (a) `llama.cpp` Android build behind a Capacitor plugin (GGUF,
Vulkan; what PocketPal does through llama.rn), (b) Google's LiteRT-LM (Gemma, NPU on newer chips; what AI Edge
Gallery and MemoryAI use). Skeleton: plugin `KesherLocalModel` with `download(url)`, `load(path)`,
`complete(messages) → stream`, `unload()`; the web side registers it as one more provider ("This phone") shown only
when the computer is not reachable; chats made offline sync to the computer as imported chats when it is back.
First step is a spike: Gemma 3 1B or Qwen3 1.7B on Roee's CPH2653, tokens per second and heat.

**F4 picture lanes without nodes.** Each lane is a ready-made ComfyUI flow (`comfy-flows.ts`, the pattern of
`music-ace-step-15`): inpaint with a mask (the image editor plugin already draws masks), remove background
(RMBG node: needs a custom node or a small model: check ComfyUI's built-ins first), upscale (built-in
`UpscaleModelLoader` + a 4x model, ~70 MB), image to video (Wan 2.2 I2V: large download). UI: on the Pictures page,
a row of lanes over the picture; each asks for what it needs and runs through `flows.run`. Start with upscale and
inpaint (small downloads), then background removal, then video.

**F19 two local models at once.** `LlamaEngine` is one process. A second `LlamaEngine` on its own port
(`config.engines.second`), registered as provider `llamacpp-2`; the guard (`start-engines.ts`) gets a third entry;
VRAM planning (`planGpus`) must fit both or refuse with numbers. Use: the helper model (titles, memory, the
reviewer of F10) stays loaded beside the main one. Only worth it on the 2-card plan or with a small helper.

export interface SideTurn { role: "user" | "assistant"; text: string }

}
