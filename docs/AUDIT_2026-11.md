## 5. Security: what else to check

Scans 1–76 are in SECURITY_REVIEW.md. New from this audit:

| # | What | Why | Status |
| --- | --- | --- | --- |
| S1 | An update with no sha512 in the release's feed is installed anyway ("installing without that check") | Should refuse, not skip the check | ✅ 0.6.235 (with a test) |
| S2 | Connection keys (OpenAI, Groq…) sit in config.json as plain text | Encrypt with the system's own protection (Windows DPAPI through Electron safeStorage); Locally Uncensored and LM Studio do the same or less, but it is cheap | ⬜ |
| S3 | The Android app allows navigation to any address (`allowNavigation: *`, needed for the user's own computer) | Confirm a link in a chat opens outside the app, and the native bridge answers only the paired computer (RemoteBridge has the rule; test it) | ⬜ |
| S4 | The installer is not signed (SignPath application waits) | Windows warns; a signed update channel (minisign) would also cover a taken-over release | ⬜ waits on SignPath |
| S5 | A yearly outside look: run a scanner (CodeQL runs; add `pnpm audit` gate ✅, Semgrep rules for Electron) | Our own scans miss what we do not think of | ⬜ |
