# How to Save More Tokens — Claude Workflow and KesherAI Architecture

A comprehensive research report on state-of-the-art token reduction techniques across developer workflows with Claude (Claude Max / Claude Code / Sub-Agents) and KesherAI's internal architecture (local models, cloud providers, task inbox, computer control, and agent orchestration).

---

## Executive Summary

Reducing token consumption in modern AI agent workflows is no longer merely a matter of writing concise prompts; it requires strict **Context Engineering** [1]. As models scale, unmanaged context growth introduces "context rot" (attention dilution leading to hallucination and dropped constraints) [1, 2] and exponential cost inflation. In agentic workflows, prompt caching dominates the cost equation: cache writes cost 1.25x base input while cache reads cost 0.1x (a 90% discount) [3, 4]. Consequently, **preserving byte-for-byte prefix stability is significantly more valuable than micro-optimizing middle-turn tokens** [5].

This report provides actionable token-saving measures divided into two core areas:
1. **Roee's Development Workflow with Claude:** Strategic prompt cache boundary preservation, idle-compaction before the 270-second TTL cliff [6], subagent sidechain sandboxing for noisy exploration [1, 7], selective changed-file test execution, and screenshot elimination via structured OS perception [8].
2. **KesherAI Codebase Enhancements:** Native Anthropic API prompt caching with `cache_control` headers and cache telemetry in `packages/providers/src/anthropic.ts`, duplicate file read pruning and observation masking in `packages/agent/src/budget.ts`, host-RAM cache expansion (`--cache-ram 20480`) and idle slot recovery in `packages/core/src/llamacpp.ts`, bounded AST-based repository mapping inspired by Aider [9], and git-diff scoped testing [10].

Implementing these proposals yields an estimated additional **18–28% token reduction** across Claude development sessions (saving 3.5M–5.5M effective Claude tokens weekly) and expands local model context headroom on the RTX 3090 by up to **40%**.

## 1. Industry Context & Context Engineering Evolution (Late 2025 – Late 2026)

### 1.1 The Context Engineering Paradigm
In late 2025 and 2026, leading AI research teams (notably Anthropic [1] and academic benchmarking consortia [11]) formalized the shift from prompt engineering to *Context Engineering*: curating, pruning, and maintaining the optimal working memory for long-running autonomous agents [1, 2].

Key industry findings include:
- **Attention Dilution & Context Rot:** Large context windows (200K–1M tokens) do not eliminate the need for context hygiene [1, 12]. Accuracy on complex multi-hop reasoning tasks degrades as the context fills with irrelevant tool outputs, failed command traces, and obsolete file inspections [2, 11].
- **The Prefix Matching Hierarchy:** Anthropic enforces strict prefix evaluation:
  $$\text{Tools} \longrightarrow \text{System Prompt} \longrightarrow \text{Message History}$$
  Any dynamic alteration in the prefix—such as injecting timestamps, reordering tool definitions, or dynamically changing tool schemas mid-session—invalidates the entire subsequent prompt cache [3, 5].
- **Cache Breakpoints & TTL Dynamics:** Anthropic APIs support up to **4 explicit cache breakpoints** (`cache_control: {"type": "ephemeral"}`) [13]. Cache entries carry a standard **5-minute (300s) Time-To-Live (TTL)** [6]. The "270-second cliff" occurs when asynchronous processing, human deliberation, or slow local builds take longer than 5 minutes between agent turns, causing a cold cache miss that incurs full write pricing (1.25x) instead of a 90% discount [3, 6].
- **Server-Side Compaction vs. Client-Side Pruning:** Server-side compaction flags (e.g. `compact-2026-01-12`) condense session history automatically at fixed token thresholds (e.g. 80–85% window capacity) [4, 14], while client-side architectures prune dead weight (duplicate file reads, terminal outputs) without triggering expensive LLM summarization calls [11, 15].

## 2. How Leading Coding Agents Eliminate Context Waste

Modern autonomous coding harnesses deploy distinct strategies to keep active context lean:

| Tool | Core Mechanism | Token / Cost Impact | Primary Trade-Off |
|---|---|---|---|
| **Claude Code** | Native `/compact`, `/context` telemetry, auto-compaction at 83.5% capacity, and subagent sidechaining [14, 16]. | Purges 60–80% of stale intermediate tool logs while preserving core architectural intent and recent file state [14]. | Compaction requires a dedicated LLM summarization turn; minor risk of summary drift [11]. |
| **Aider** | **Tree-sitter Repo Map + PageRank**: Builds concrete AST symbol graphs (functions, classes, exports) across 100+ languages; ranks symbols by centrality and caps map strictly to `--map-tokens 1024` [9, 17]. | Reduces initial whole-file exploratory reads by 40–70%, providing a bird's-eye architectural view in ~1,000 tokens [9]. | Does not contain full function bodies; agent must request specific files when implementing details [9]. |
| **Cline / Roo Code** | **Duplicate File Read Pruning**: Automatically replaces older reads of the same file path with `[DUPLICATE FILE READ]`; on-demand MCP documentation (`load_mcp_documentation`) [15, 18]. | Saves 20–35% of context in iterative edit-test loops; prevents MCP schemas from eating ~30% of system prompt [15]. | Requires tracking file access history and maintaining state across tool execution events [15]. |
| **Cursor** | **Merkle-Tree Indexing & Instant Grep**: Cryptographic Merkle trees track local changes; semantic search paired with local regex grep; scoped `.cursorrules` / `.mdc` files with conditional glob frontmatter (`alwaysApply: false`) [19, 20]. | Prevents static prompt bloat; index updates take milliseconds without re-embedding unchanged files [19]. | Requires local vector database and background indexing daemon [19]. |
| **OpenHands / Academic** | **Observation Masking (NeurIPS 2025)**: Replaces tool outputs older than $K$ turns with a fixed placeholder (`[Output hidden, ID: X]`). Shown to match or exceed LLM summarization on SWE-bench Verified [11]. | Eliminates 50–70% of historical tokens with **zero extra LLM calls** [11]. | Historical tool logs become unavailable unless explicitly retrieved via a secondary lookup tool [11]. |

## 3. Local Model Cache Optimization (llama.cpp & LM Studio)

For KesherAI's local inference engine running on the workstation's RTX 3090 (24 GB VRAM + 96 GB RAM):

### 3.1 Moving Beyond File-Based Prompt Caches to Host-Memory Caching
Early llama.cpp documentation referenced `--prompt-cache [file]` for the standalone CLI [21]. In modern `llama-server` (b11000–b12000+), multi-turn efficiency is governed by dynamic host-RAM cache pools [22]:
- **`--cache-ram <MB>` (or `-cram`):** Defines the host system memory allocated to retain prompt prefixes and KV checkpoints across requests [22, 23]. The default is 8,192 MiB (8 GB). On a 96 GB RAM host, expanding this to `20480` MiB (20 GB) allows dozens of conversation checkpoints and subagent contexts to stay warm in RAM without eviction [23].
- **`--cache-idle-slots`:** Permits restoring cached context from completed or idle sessions into active execution slots, preventing cold re-evaluations when self-work and interactive chats alternate [22].
- **Prefix-Affinity Slot Selection (`-sps`):** Matches incoming requests to idle slots based on Longest Common Prefix (LCP) similarity ($\ge 50\%$) [22, 24].

### 3.2 Checkpoint Stepping for Hybrid Architectures
For recurrent and hybrid architectures (e.g. Qwen3.5–3.8 featuring Gated DeltaNet recurrent layers), states cannot be dynamically rolled back without recomputation [5]. `llama-server` relies on `--ctx-checkpoints` and `--checkpoint-min-step 1024` [5, 23]. Retaining tight checkpoint steps prevents the engine from re-reading up to 8,192 tokens of history when a tool output is appended mid-conversation.

## 4. Part A: Token-Saving Recommendations for Roee's Claude Workflow

### Idea A1: Enforce Byte-for-Byte Prefix Stability in Lead Prompts
- **What to change:** Ensure that the first 3 components of every interaction with Claude remain byte-for-byte identical across the entire 1–2 week session lifecycle:
  1. System prompt / AGENTS.md rules.
  2. Workspace structure definition.
  3. Stable handoff preamble (`docs/HANDOFF.md`).
  Do not include dynamic dates, clock times, or ephemeral session IDs in the system prompt. Inject timestamps and dynamic state only into the latest user prompt.
- **Expected Saving:** Guarantees 85–90% prompt cache hit rates on all subsequent turns within the 5-minute TTL. In a 500-request session with 25K prefix tokens, this saves ~10.5M billable input tokens.
- **Effort:** S (workflow convention).
- **Risk to Quality:** Zero (prompt content is identical; only placement changes).
- **Measurement:** Inspect `cache_read_input_tokens` vs `input_tokens` in Claude's usage telemetry.

### Idea A2: Bounded Exploratory Sub-Agents (Sidechains) for Code Investigation
- **What to change:** When investigating unfamiliar code, debugging third-party dependencies, or auditing multi-file architectures, launch an isolated subagent (e.g. Antigravity or a lightweight Claude helper) with a strict brief: "Inspect files X, Y, Z, run read-only grep commands, and return a single structured summary under 40 lines. Do not return raw file contents." The lead Claude context ingests only the 40-line summary.
- **Expected Saving:** Avoids polluting the lead Claude context with 30K–80K tokens of raw file reads and grep hits. Across 10 exploratory tasks per week, expected saving is 400K–700K Claude tokens.
- **Effort:** S.
- **Risk to Quality:** Zero (synthesized conclusions are cleaner than hundreds of raw lines).
- **Measurement:** Count file read tokens in helper logs vs final response tokens in main chat.

### Idea A3: Selective Changed-File Test Verification During Development
- **What to change:** In `docs/HANDOFF.md` and active chat instructions, modify the per-item verification instruction:
  - *Current rule:* `pnpm -s typecheck && pnpm -s test` on every small step.
  - *New rule:* `pnpm -s typecheck && node tools/test-changed.js` on small steps; run the full test suite (`pnpm -s test`) only before PR, release, or when modifying shared packages (`packages/shared`).
- **Expected Saving:** Running the entire test suite outputs 40–100 lines of terminal logs per turn. In an agent loop, terminal output is fed back into the context. Scoped test output reduces verification log tokens by ~80% per run (saving ~1,500–3,000 tokens per verification turn across ~40 turns/day $\approx$ 60K–120K tokens/day).
- **Effort:** S (requires adding `tools/test-changed.js`).
- **Risk to Quality:** Very low (typecheck catches cross-package interface breaks; full test suite runs before commit/release).
- **Measurement:** Measure characters returned by the verification command before and after.

### Idea A4: Proactive Idle-Compaction Before the 270-Second TTL Cliff
- **What to change:** When Roee takes a break, reviews code manually, or pauses between development milestones, prompt caching TTL (300s) will expire [6]. Resuming after 10 minutes forces a cold cache re-read at 1.25x cost. If a session is past 50K tokens and a pause is anticipated, run `/compact` immediately. The post-compaction context shrinks to ~5K–10K tokens, so the subsequent cache miss incurs 1.25x on only 8K tokens instead of 50K+ tokens.
- **Expected Saving:** Saves ~40K–60K cache write tokens per resumed session.
- **Effort:** S (habitual trigger).
- **Risk to Quality:** Zero.
- **Measurement:** Track `cache_creation_input_tokens` on first prompt after idle breaks.

### Idea A5: Structured OS Perception Over Full-Screen Screenshots
- **What to change:** For computer and browser control tasks, prohibit Claude from requesting full-screen desktop screenshots (1,600+ tokens per image). Direct computer control through KesherAI's existing `POST /api/control/tasks` (using Windows UI Automation element trees and Accessibility snapshots via CDP) [8]. Screenshots are restricted to 1 cropped region only when visual verification (e.g. canvas rendering) is mandatory.
- **Expected Saving:** Saves 1,200–1,500 tokens per action step. For a 10-step UI automation task: ~15K tokens saved.
- **Effort:** S (already supported by KesherAI's hybrid UIA engine).
- **Risk to Quality:** Zero (accessibility and UIA trees provide deterministic element coordinates, eliminating visual misclicks).
- **Measurement:** Total image tokens in agent usage metadata.

## 5. Part B: Concrete Token-Saving Enhancements in KesherAI Codebase

### Idea B1: Native Anthropic Prompt Caching & Telemetry in `AnthropicProvider`
- **Location:** `packages/providers/src/anthropic.ts` (`chatWithTools` and `toAnthropicMessages`).
- **What to change:**
  1. Add explicit `cache_control: { type: "ephemeral" }` to the last tool in `request.tools` (locks tool definitions into cache) [3, 13].
  2. Structure `system` as an array of content blocks, placing `cache_control: { type: "ephemeral" }` on the static instruction block.
  3. Place a rolling `cache_control` breakpoint on the second-to-last user message turn in `toAnthropicMessages` [13].
  4. In `readSSE`, extract `cache_creation_input_tokens` and `cache_read_input_tokens` from `message_start` and `message_delta` events, adding them to `ProviderToolChatResult.usage`.
- **Expected Saving:** 85–90% reduction in billed input tokens on all multi-turn API conversations directed through Anthropic.
- **Effort:** S (approx. 35 lines of code).
- **Risk to Quality:** Zero (standard Anthropic API specification).
- **Measurement:** Add `cacheHitRate` to `chat-stats.ts` and verify that `cache_read_input_tokens` accounts for $>80\%$ of input on turns $\ge 2$.

### Idea B2: Duplicate File-Read Pruning & Stale Observation Masking
- **Location:** `packages/agent/src/budget.ts` (`pruneToolOutputs`) and `packages/agent/src/session.ts`.
- **What to change:**
  1. Implement duplicate file read pruning: when `read_file` is called for path $P$ at turn $T_2$, check if an earlier turn $T_1$ already contains the output of `read_file` for $P$. If so, prune turn $T_1$'s tool result to `[read_file <P> superseded by turn T2]`, retaining only the latest inspection [15].
  2. Extend `pruneToolOutputs` observation masking: replace terminal execution outputs (`run_command`, `check_code`) older than 2 turns with `[pruned output <id>] <tool>: <summary>` (matching the NeurIPS 2025 finding) [11]. The full text remains accessible via `tool_output`.
- **Expected Saving:** Eliminates 25–40% of middle-turn conversational history tokens in sessions exceeding 8 turns.
- **Effort:** S (approx. 45 lines in `budget.ts`).
- **Risk to Quality:** Zero (recent 2 turns remain in full; older outputs remain recoverable via `tool_output`).
- **Measurement:** Measure `prunedChars` returned by `pruneToolOutputs` and log tokens saved per session.

### Idea B3: Host-RAM Cache Pool Expansion (`--cache-ram`) & Idle Slot Recovery in `llamacpp.ts`
- **Location:** `packages/core/src/llamacpp.ts` (`serverArgs` / `speedArgs`).
- **What to change:**
  1. In `LlamaEngine.speedArgs`, add `--cache-ram 20480` (allocating 20 GB of host RAM) for builds $\ge \text{b12000}$ when host RAM $\ge 64\text{ GB}$ [22, 23].
  2. Add `--cache-idle-slots` to allow slots that finished a task to retain their context in host memory and serve subsequent sessions with matching prefixes [22].
- **Expected Saving:** Eliminates prompt processing latency (TTFT) and re-tokenization overhead when switching between interactive chat and self-work tasks on the local RTX 3090.
- **Effort:** S (10 lines in `llamacpp.ts`).
- **Risk to Quality:** Zero (pure memory caching; model output logits are identical).
- **Measurement:** Monitor `prompt processing ... tokens per second` and prompt evaluation time in engine logs (`promptTps`).

### Idea B4: Bounded AST-Based Repository Mapping Tool
- **Location:** `packages/agent/src/tools.ts` (`makeRepoMap` / `get_repo_outline`).
- **What to change:**
  - Build a lightweight repository skeleton generator inspired by Aider's Tree-sitter repo map [9].
  - Use existing project language tooling (TypeScript compiler API / AST parser) to generate an outline of exported interfaces, class signatures, and function declarations.
  - Impose a strict token ceiling (default 1,024 tokens) [9, 17].
  - Provide this outline to agents at session start instead of having them run multiple `list_files`, `search_files`, and exploratory `read_file` calls.
- **Expected Saving:** Saves 10K–25K tokens per coding task by eliminating initial exploratory navigation loops.
- **Effort:** M (approx. 120 lines in `tools.ts`).
- **Risk to Quality:** Zero (improves architectural awareness and reduces hallucinated import paths).
- **Measurement:** Count initial exploration tool calls prior to the first file edit.

### Idea B5: Cross-Platform Changed-File Test Runner
- **Location:** `tools/test-changed.js` and `package.json` (`test:changed`).
- **What to change:**
  - Create a Node.js utility script `tools/test-changed.js` that:
    1. Executes `git diff --name-only HEAD` (and staged changes) via `node:child_process` [10].
    2. Identifies modified `.ts` source files and checks for corresponding `*.test.ts` files in the same directory.
    3. Directly invokes `node --test` passing only the matched test files [10].
    4. If no test files or related sources changed, exits immediately with `0`.
  - Add `"test:changed": "node tools/test-changed.js"` to root `package.json`.
  - Update `packages/agent/src/session.ts` and `known-issues.ts` to suggest `pnpm test:changed` for intermediate verification.
- **Expected Saving:** Cuts test execution output tokens by 75–85% per turn, reducing overall agent step context growth.
- **Effort:** S (approx. 40 lines of script).
- **Risk to Quality:** Zero (standard developer practice; full suite runs before PR/release).
- **Measurement:** Diff output length between `pnpm test` and `pnpm test:changed`.

### Idea B6: Predictive Token Budgeting & Runaway Loop Interceptor
- **Location:** `packages/shared/src/task-steps.ts` and `packages/agent/src/session.ts`.
- **What to change:**
  - Extend `estimateTaskSteps`: assign an expected token budget per task category (e.g. Bugfix: 15K tokens; Feature: 40K tokens; Research: 20K tokens).
  - In `session.ts`, track cumulative tokens across turns. If a task exceeds 2.5x its estimated budget without producing an accepted file edit or passing check, trigger a single non-blocking reflection redirect: *"Task token budget exceeded. Step back, summarize remaining blockers, and formulate a direct fix."* [5].
- **Expected Saving:** Prevents runaway agent loops that consume 100K+ tokens spinning on failing edits. Estimated 15–20% savings on failed/stalled tasks.
- **Effort:** M.
- **Risk to Quality:** Quality positive (breaks circular reasoning loops).
- **Measurement:** Number of turns to resolution on complex bugfixes.

## 6. Where Sources Disagree and Trade-Offs

1. **LLM Summarization vs. Observation Masking:**
   - *Anthropic / Claude Code:* Advocates periodic semantic summarization (`/compact`, `compact-2026-01-12`) to distill high-level decisions and delete intermediate dialogue [1, 14].
   - *Academic Benchmark Findings (The Complexity Trap, NeurIPS 2025):* Demonstrated that replacing old tool outputs with simple placeholder markers (masking) matched or outperformed LLM summarization on SWE-bench Verified while saving 100% of summarization tokens and avoiding "summary drift" [11].
   - *Resolution for KesherAI:* Adopt a hybrid model. Use **observation masking** for intermediate tool results within active sessions (zero cost, zero drift) [11], and reserve **semantic compaction** only when the total window crosses the 80% threshold [14].

2. **Compaction Timing: Proactive (65%) vs. Reactive (85%):**
   - *Context Engineering Guides:* Recommend compacting at 60–65% capacity to prevent "attention rot" from degrading code accuracy [1, 2].
   - *Pricing & Cache Advocates:* Note that every compaction invalidates prompt cache prefixes, forcing a cold write at 1.25x [3, 5]. Compacting too frequently *increases* total cost.
   - *Resolution:* Compact only at 80–85% capacity, or proactively *immediately before* an extended idle period (Idea A4).

3. **Dynamic Tool Pruning vs. Cache Invalidation:**
   - *TokenEconomizer / Tool Search:* Suggests omitting unused tool descriptions dynamically to save 1,500–2,500 tokens per prompt [5, 25].
   - *Prompt Caching Mechanics:* Because tool definitions appear first in Anthropic's prefix hierarchy, changing the active tool list mid-conversation invalidates the entire cache [3, 5].
   - *Resolution:* Tool lists must remain static within a single conversation session. Pruning should only occur across session boundaries based on project profiles [5].

## 8. Conclusion

Saving tokens in 2026 is an architectural discipline governed by prompt cache economics and high-signal attention budgets. For Roee's Claude workflow, the highest-leverage wins are non-destructive: **preserving byte-for-byte prefix stability**, **delegating exploratory searches to bounded subagents**, and **scoping intermediate verification tests to changed files**. For KesherAI, adding **native Anthropic prompt caching (`cache_control`)**, **duplicate file-read pruning**, and **host-RAM cache pool expansion (`--cache-ram 20480`)** eliminates pure waste without touching code quality.
