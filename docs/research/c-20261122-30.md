# Research: Godot 4 Headless Scene Synthesis, ClassDB Reflection, and Native MCP Bridge for KesherAI

## Summary

This research establishes the complete architectural specification for a native Godot 4 headless bridge and Model Context Protocol (MCP) server for KesherAI. KesherAI's core product priority is enabling high-velocity game-engine workflows that operate seamlessly without requiring graphical editors to remain open—allowing local AI coding agents, remote web users, and mobile devices (at 390 px width) to inspect scenes, synthesize node hierarchies, attach scripts, and verify syntax offline.

Currently, KesherAI's Godot integration relies on an in-editor WebSocket addon (`integrations/godot/addons/kesher_bridge`) that requires the heavy graphical editor to be running on the host machine. By analyzing Godot 4.3 and 4.4 headless CLI capabilities (`--headless`, `--check-only`, `--import`, `--dump-extension-api`), reverse-engineering the `.tscn` Format 3 grammar and UID management schemes (`ResourceUID`, `.uid` sidecars), and mapping internal `ClassDB` reflection into compact JSON Schemas, we design a dual-mode bridge. This architecture provides an autonomous headless daemon for engine-less synthesis and validation alongside a unified stdio/WebSocket JSON-RPC 2.0 MCP server. The system guarantees atomic AST-level scene writes, bidirectional undo/redo safety, zero VRAM overhead when idling, and full compatibility across desktop and mobile workflows.

## 1. Godot 4.3/4.4 Headless CLI Capabilities

Godot 4 features extensive command-line interface (CLI) capabilities designed for continuous integration (CI/CD), automated asset imports, dedicated server execution, and static script verification [1, 3]. Harnessing these flags allows KesherAI to manipulate and validate projects without allocating graphical window contexts, rendering sub-systems, or audio drivers.

### 1.1 CLI Execution Modes and Automation Flags

The Godot binary supports multiple flags that govern window creation, process lifecycle, and engine subsystems:

| CLI Flag | Functionality in Godot 4.3 / 4.4 | Resource / Subsystem Impact |
| :--- | :--- | :--- |
| `--headless` | Disables display server, window manager, and audio server [1, 3]. | Zero OS window allocation, zero swapchain overhead; operates on headless servers or background daemons. |
| `--path <dir>` | Directs the engine to the target project directory containing `project.godot` [1]. | Bypasses project manager; isolates execution to the specified workspace. |
| `--editor` (`-e`) | Boots Godot in editor mode rather than game runtime [1]. | Initializes editor plugins, `EditorFileSystem`, and asset import pipelines [1]. |
| `--quit` (`-q`) | Exits immediately after the first main loop iteration [1]. | Prevents indefinite execution; ensures clean shutdown for one-shot batch tasks. |
| `--import` | Implicitly activates `--editor` and `--quit`, waiting for asset imports to finish before exiting [1]. | Rebuilds `.godot/` cache, indexes new/modified resources, and generates persistent UIDs. |
| `-s <path>` (`--script`) | Runs a standalone GDScript file inheriting `SceneTree` or `MainLoop` [1]. | Executes custom automation logic headlessly. |
| `--check-only` | Validates a script passed via `--script` for syntax/type errors without running it [1]. | Exits with status `0` on success or non-zero with stderr diagnostics on failure. |
| `--dump-extension-api` | Generates `extension_api.json` detailing the full engine ClassDB [2]. | Extracts classes, properties, methods, signals, enums, and constants for external bindings. |
| `--rendering-driver dummy` | Forces the dummy software rasterizer [1, 3]. | Avoids initializing Vulkan (Forward+/Mobile) or OpenGL drivers; eliminates GPU VRAM footprint. |

### 1.2 GDScript Verification and Syntax Checking

In Godot 4.3 and 4.4, script syntax and static typing can be verified from the command line without opening the editor [1]:
```bash
godot --headless --path <project_dir> --script res://scripts/player.gd --check-only
```
When executed with `--check-only`:
- The GDScript compiler parses the target script, validates static type hints, checks for unresolved symbols against built-in engine types, and validates inheritance trees.
- If errors exist, the engine logs compiler diagnostics to `stderr` and terminates with a non-zero exit code.
- If valid, the engine outputs no errors and exits immediately with code `0`.

For dynamic evaluation or partial hunk verification (e.g., verifying a snippet generated by an AI model before writing to disk), KesherAI can execute an ephemeral validation harness:
```gdscript
# res://addons/kesher_bridge/eval_script.gd
extends SceneTree

func _init() -> void:
    var args := OS.get_cmdline_user_args()
    if args.is_empty():
        quit(1)
        return
    var script_code := args[0]
    var script := GDScript.new()
    script.source_code = script_code
    var err := script.reload()
    if err != OK:
        printerr("GDScript validation error: ", err)
        quit(2)
        return
    print("VALID")
    quit(0)
```
Invoked via:
```bash
godot --headless --path <project_dir> -s res://addons/kesher_bridge/eval_script.gd -- "<code_string>"
```

### 1.3 Headless Scene Validation

Godot does not provide a native `--check-scene` flag in C++. Loading a corrupted `.tscn` file at game runtime typically prints error messages to `stdout`/`stderr` but may fail silently or fall back to missing placeholders.

To achieve robust scene validation, KesherAI utilizes a dedicated headless scene validator script. This runner executes inside Godot's runtime environment, leveraging `ResourceLoader` and `PackedScene.instantiate()` to verify:
1. **External Resource Resolution:** Verifies that all `[ext_resource]` dependencies exist on disk and match expected UIDs.
2. **Sub-Resource Deserialization:** Ensures built-in meshes, collision shapes, and materials possess valid parameters.
3. **ClassDB Instantiation:** Verifies that every declared node type exists in the active engine build or registered GDExtensions.
4. **Script Attachment & Compilation:** Compiles and attaches linked GDScript/C# files, verifying that export variables match node property assignments.
5. **Signal Connection Validity:** Verifies that all `[connection]` definitions point to existing source nodes, target nodes, and implemented methods.

```gdscript
# res://addons/kesher_bridge/validate_scene.gd
extends SceneTree

func _init() -> void:
    var args := OS.get_cmdline_user_args()
    if args.is_empty():
        printerr("Error: Missing scene path argument.")
        quit(1)
        return
    
    var scene_path := args[0]
    if not FileAccess.file_exists(scene_path):
        printerr("Error: Scene file does not exist: ", scene_path)
        quit(2)
        return
    
    var packed: PackedScene = ResourceLoader.load(scene_path, "PackedScene", ResourceLoader.CACHE_MODE_IGNORE)
    if packed == null or not packed.can_instantiate():
        printerr("Error: Failed to parse or load PackedScene: ", scene_path)
        quit(3)
        return
    
    var instance: Node = packed.instantiate(PackedScene.GEN_EDIT_STATE_INSTANCE)
    if instance == null:
        printerr("Error: Failed to instantiate scene root: ", scene_path)
        quit(4)
        return
    
    # Recursive structural check
    var error_count := 0
    error_count += _validate_node(instance)
    instance.free()
    
    if error_count > 0:
        printerr("Scene validation failed with ", error_count, " errors.")
        quit(5)
    else:
        print("SCENE_VALID: ", scene_path)
        quit(0)

func _validate_node(node: Node) -> int:
    var errors := 0
    var script = node.get_script()
    if script != null and not (script is Script):
        printerr("Invalid script attached to node: ", node.name)
        errors += 1
    
    for child in node.get_children():
        errors += _validate_node(child)
    return errors
```

- `--ignoreHeadlessMode`: Allows tests utilizing `SceneRunner` to bypass visual display server requirements without requiring an X11 virtual framebuffer (Xvfb) [10].

## 2. `.tscn` File Format Syntax, UID Management, and Safe External Manipulation

Godot's text scene format (`.tscn`, Format 3 in Godot 4.x) is human-readable and designed for version control friendliness [4]. However, external manipulation by AI code agents requires strict adherence to grammar, ID serialization, and UID caching invariants.

### 2.1 The `.tscn` Format 3 Grammar and Structure

A `.tscn` file consists of structured header blocks followed by key-value pairs representing Godot Variants [4]:

```ini
[gd_scene load_steps=4 format=3 uid="uid://c6f2a4b8k1m9p"]

[ext_resource type="Script" uid="uid://b7v2k8m3x1q4y" path="res://player.gd" id="1_abcde"]
[ext_resource type="PackedScene" uid="uid://d9v1x3k5m7p2q" path="res://weapon.tscn" id="2_fghij"]

[sub_resource type="BoxShape3D" id="BoxShape3D_1a2b3"]
size = Vector3(1, 2, 1)

[node name="Player" type="CharacterBody3D"]
script = ExtResource("1_abcde")

[node name="CollisionShape" type="CollisionShape3D" parent="."]
shape = SubResource("BoxShape3D_1a2b3")

[node name="WeaponMount" type="Node3D" parent="."]
transform = Transform3D(1, 0, 0, 0, 1, 0, 0, 0, 1, 0, 0.5, -0.5)

[node name="WeaponInstance" parent="WeaponMount" instance=ExtResource("2_fghij")]

[connection signal="health_depleted" from="." to="." method="_on_health_depleted"]

[editable path="WeaponMount/WeaponInstance"]
```

#### Structural Sections Breakdown:
1. **Scene Header (`[gd_scene]`):**
   - `format=3`: Serialization version for Godot 4.x [4].
   - `load_steps=N`: The exact number of sequential resource load steps required prior to instantiating nodes [4].
     $$\text{load\_steps} = 1 + \text{count}(\text{ext\_resource}) + \text{count}(\text{sub\_resource})$$
     If `load_steps` does not match the actual count of declared external and sub-resources, Godot logs warnings or fails to load downstream sub-resources properly.
   - `uid="uid://..."`: The global unique identifier of this scene file.
2. **External Resources (`[ext_resource]`):**
   - Declares dependencies located in other files (scripts, textures, audio, nested `.tscn` scenes).
   - Attributes: `type`, `uid`, `path`, and local reference `id` [4].
   - The local `id` is conventionally serialized as `<index>_<5char_hash>` (e.g., `1_abcde`) in Godot 4, though legacy integer IDs (`id=1`) remain syntactically valid.
3. **Internal Sub-Resources (`[sub_resource]`):**
   - Declares inline resources that exist only within this scene (e.g., collision shapes, unique materials, animation tracks).
   - Attributes: `type` and `id` (e.g., `id="BoxShape3D_1a2b3"`).
4. **Node Declarations (`[node]`):**
   - Declares hierarchy nodes. Root node has no `parent` attribute. Children specify relative parent paths: `parent="."` (direct child of root) or `parent="WeaponMount"`.
   - Node attributes include:
     - `name="..."`: Identifier of the node in the tree.
     - `type="..."`: Built-in engine class or registered GDExtension class.
     - `instance=ExtResource("...")`: References an instanced packed scene.
     - `unique_name_in_owner=true`: Exposes the node as a Scene Unique Node accessible via `%NodeName` in GDScript.
     - `unique_id="..."`: Introduced in Godot 4.6+ to track nodes across name changes and structural refactorings.
5. **Signal Connections (`[connection]`):**
   - Defines event bindings: `signal`, `from` (relative emitter path), `to` (relative receiver path), `method`, and optional `flags` or `binds` [4].
6. **Editable Children (`[editable]`):**
   - Enables property overrides on sub-nodes of instanced child scenes: `[editable path="Parent/ChildInstance"]` [4].

### 2.2 UID Architecture: Godot 4.3 vs 4.4+

Godot's `ResourceUID` system decouples project asset relationships from brittle filesystem paths, preventing broken references when files are moved or reorganized [4, 5].

```
+-----------------------------------------------------------------------+
| Godot ResourceUID System                                              |
+-----------------------------------------------------------------------+
|  Internal 64-bit Integer:   6360883855146557548                       |
|  Base36 Encoding:           d4n4ub6itg400                             |
|  Serialized Text URI:       uid://d4n4ub6itg400                       |
+-----------------------------------------------------------------------+
```

#### The Plain-Text Asset Evolution:
- **Prior to Godot 4.4:** Binary assets (textures, audio) and `.tscn`/`.tres` stored their `uid://` identifiers inside file headers or `.import` metadata files [5]. However, plain-text assets (`.gd`, `.cs`, `.gdshader`, `.gdshaderinc`) lacked internal metadata storage and were tracked strictly by raw `res://` paths [5]. Refactoring scripts outside the Godot editor broke all scene bindings.
- **Godot 4.4+ (.uid Sidecar Files):** Godot 4.4 introduced companion `.uid` sidecar files for all plain-text source files [5]:
  - `res://scripts/player.gd` $\rightarrow$ `res://scripts/player.gd.uid`
  - The sidecar contains a single UTF-8 line: `uid://c82j4l3r4k4n2` [5].
  - Scenes referencing the script store `uid="uid://c82j4l3r4k4n2"` in their `[ext_resource]` block alongside the fallback `path="res://scripts/player.gd"` [5].

#### UID Resolution Precedence:
When loading resources, Godot queries `ResourceUID`:
1. The engine checks the `uid://` URI against the project's internal cache (`.godot/uid_cache.bin`) [5].
2. If found, Godot resolves the asset from its cached filesystem path, even if the file was moved to another subfolder.
3. If the UID is not in the cache or resolves to a missing file, Godot falls back to the declared `path="res://..."` attribute and updates the UID cache [5].

### 2.3 Safe External Manipulation Rules for KesherAI

To guarantee that KesherAI's scene synthesis and modifications never corrupt project files, the following rules are enforced:

1. **Strict Format Invariants:**
   - Headers, resource blocks, and node blocks must remain cleanly separated by blank lines.
   - Key-value assignments must maintain Godot's exact serialization format (e.g., `transform = Transform3D(...)` with space around `=`).
2. **`load_steps` Recalculation:**
   - Whenever an `ext_resource` or `sub_resource` is inserted or deleted, KesherAI recalculates and updates the `load_steps` attribute on line 1.
3. **Deterministic Local ID Allocation:**
   - When generating new external resource references, KesherAI generates collision-free local IDs:
     $$\text{id} = (\text{highest\_index} + 1) + \text{"\_"} + \text{crypto\_hash5}()$$
4. **Sidecar Synchronization (Godot 4.4+):**
   - When creating a new `.gd` or `.gdshader` file, KesherAI generates a 64-bit random UID using standard Base36 encoding and writes the corresponding `.uid` sidecar file immediately.
5. **Atomic File Writes with Rolling Checkpoints:**
   - Direct writes to `.tscn` files are executed atomically: writing to a temporary file (`.tscn.tmp`) and renaming it via `fs.rename()`.
   - Before any file modification, KesherAI's `GameCheckpoints` subsystem creates an automated snapshot, allowing instant rollback from the chat or mobile interface.
6. **Headless Cache Refresh (`--import`):**
   - After creating or moving assets externally, KesherAI triggers a background headless import pass (`godot --headless --path <project> --import`), forcing Godot to index the new files and update `.godot/uid_cache.bin` cleanly.

## 3. ClassDB Reflection and Structured Tool Definitions for AI Code Agents

Godot's internal `ClassDB` is the central reflection registry containing metadata for all built-in C++ engine classes, properties, methods, signals, and constants, as well as registered GDExtension types [2, 6].

```
+--------------------------------------------------------------------------+
| Godot ClassDB Reflection Pipeline                                       |
+--------------------------------------------------------------------------+
|  Engine Binary:      godot --headless --dump-extension-api               |
|  Output:             extension_api.json (~8 MB raw)                      |
|                                                                          |
|  KesherAI Filter:    1. Filter PROPERTY_USAGE_EDITOR (flag 4)            |
|                      2. Exclude internal servers (RenderingServer, etc.) |
|                      3. Group by Node2D, Node3D, Control, Resource       |
|                                                                          |
|  Pruned Cache:       classdb-cache.json (~320 KB compressed)             |
|                                                                          |
|  AI Agent Tools:     godot_class_info (on-demand introspection)          |
|                      godot_synthesize_node (parameter-validated tool)    |
+--------------------------------------------------------------------------+
```

### 3.1 ClassDB Reflection Architecture

Godot provides two reflection extraction pathways:
1. **Static Binary Dump (`--dump-extension-api`):**
   Dumps `extension_api.json`, detailing all core classes, inheritance hierarchies, property getters/setters, method argument signatures, and enumeration bitmasks [2].
2. **Runtime Script Introspection (`ClassDB` Singleton):**
   Executed via GDScript:
   - `ClassDB.get_class_list()`: Returns all registered engine class names [6].
   - `ClassDB.get_parent_class(class_name)`: Returns the parent type in the inheritance hierarchy [6].
   - `ClassDB.can_instantiate(class_name)`: Determines if the class can be instantiated as a scene node or resource [6].
   - `ClassDB.class_get_property_list(class_name, no_inheritance)`: Returns an array of `PropertyInfo` dictionaries detailing property names, variant types, and property hints [6].
   - `ClassDB.class_get_method_list(class_name, no_inheritance)`: Returns method signatures and argument types [6].
   - `ClassDB.class_get_signal_list(class_name, no_inheritance)`: Returns signal definitions and payload parameters [6].

### 3.2 Token-Efficient Schema Pruning

The raw `extension_api.json` dump exceeds 8 megabytes, spanning over 800 classes and 12,000 methods. Exposing this raw dump to an LLM context exhausts the token budget and induces hallucinations.

KesherAI applies a three-stage filtering pipeline to generate a compact reflection index (`classdb-cache.json`):
1. **Property Usage Filtering:**
   Only properties with the `PROPERTY_USAGE_EDITOR` flag (`usage & 4 != 0`) are retained [6]. Properties flagged with `PROPERTY_USAGE_INTERNAL` (`usage & 8 != 0`) or names beginning with underscores are discarded.
2. **Instantiable Hierarchy Pruning:**
   Classes are categorized into functional subtrees: `Node3D`, `Node2D`, `Control`, and `Resource`. Low-level server singletons (`RenderingServer`, `AudioServer`, `PhysicsServer3D`) are excluded from scene synthesis schemas.
3. **Type Mapping to JSON Schema:**
   Godot Variant types are mapped to JSON Schema primitives:

| Godot Variant Type | Serialized Format in `.tscn` | JSON Schema Primitive / Validation Pattern |
| :--- | :--- | :--- |
| `TYPE_BOOL` | `true` / `false` | `{ "type": "boolean" }` |
| `TYPE_INT` | `123` | `{ "type": "integer" }` |
| `TYPE_FLOAT` | `12.34` | `{ "type": "number" }` |
| `TYPE_STRING` | `"text"` | `{ "type": "string" }` |
| `TYPE_VECTOR2` | `Vector2(x, y)` | `{ "type": "array", "items": { "type": "number" }, "minItems": 2, "maxItems": 2 }` |
| `TYPE_VECTOR3` | `Vector3(x, y, z)` | `{ "type": "array", "items": { "type": "number" }, "minItems": 3, "maxItems": 3 }` |
| `TYPE_COLOR` | `Color(r, g, b, a)` | `{ "type": "string", "pattern": "^Color\\([0-9., ]+\\)$" }` |
| `TYPE_TRANSFORM3D` | `Transform3D(...)` | `{ "type": "array", "items": { "type": "number" }, "minItems": 12, "maxItems": 12 }` |
| `TYPE_OBJECT` | `ExtResource("...")` | `{ "type": "string", "pattern": "^res://.*" }` |

## 4. WebSocket & stdio JSON-RPC Bridge Protocol

To unify editor-less background execution with active graphical editing, KesherAI implements a dual-mode communication architecture governed by the standard JSON-RPC 2.0 protocol [7].

```
+--------------------------------------------------------------------------+
| KesherAI Godot Bridge Architecture                                       |
+--------------------------------------------------------------------------+
|                                                                          |
|  [KesherAI Core / Agent / MCP Server]                                    |
|         |                                  |                             |
|         | (Mode A: Editor Open)            | (Mode B: Editor Closed)     |
|         v                                  v                             |
|  WebSocket Link                   Child Process Pipe                     |
|  ws://127.0.0.1:7420/api/godot/ws  godot --headless -s headless_bridge.gd|
|         |                                  |                             |
|         v                                  v                             |
|  [Godot Editor (GUI)]             [Godot Headless Daemon]                |
|  - EditorUndoRedoManager          - Direct AST Parsing                   |
|  - Visual Viewport Screenshots    - Scene/Script Validation              |
|  - In-Editor Play Testing         - GUT / GdUnit4 Execution              |
+--------------------------------------------------------------------------+
```

### 4.1 Topology and Transport Architecture

The bridge operates in two coordinated modes:
- **Mode A (In-Editor GUI Mode):**
  When Roee opens the Godot editor, the `kesher_bridge.gd` plugin connects via an outbound WebSocket client to KesherAI at `ws://127.0.0.1:7420/api/godot/ws`. Every modification committed in this mode uses Godot's `EditorUndoRedoManager`, allowing immediate Ctrl+Z rollback in the editor window.
- **Mode B (Headless Daemon Mode):**
  When the editor is closed, KesherAI spawns a lightweight headless background runner:
  ```bash
  godot --headless --path <project_dir> -s res://addons/kesher_bridge/headless_bridge.gd
  ```
  Communication occurs via newline-delimited JSON-RPC 2.0 over standard I/O (`stdio`) or a loopback WebSocket.

#### Stdio Transport Implementation Details:
In Godot 4.4+, standard input can be read directly via `OS.read_string_from_stdin()` [8]. Because `read_string_from_stdin()` is a blocking call, the headless bridge runs the read loop on a dedicated worker `Thread`, communicating with the main loop via a thread-safe mutex and command queue:

```gdscript
# res://addons/kesher_bridge/headless_bridge.gd
extends SceneTree

var _thread := Thread.new()
var _mutex := Mutex.new()
var _queue: Array[Dictionary] = []
var _running := true
var _json_rpc := JSONRPC.new()

func _init() -> void:
    _thread.start(_stdin_worker)

func _process(_delta: float) -> bool:
    _mutex.lock()
    var batch := _queue.duplicate()
    _queue.clear()
    _mutex.unlock()
    
    for req in batch:
        _handle_request(req)
    return not _running

func _stdin_worker() -> void:
    while _running:
        var line := OS.read_string_from_stdin(65536).strip_edges()
        if line.is_empty():
            continue
        var parsed = JSON.parse_string(line)
        if typeof(parsed) == TYPE_DICTIONARY:
            _mutex.lock()
            _queue.append(parsed)
            _mutex.unlock()

func _handle_request(req: Dictionary) -> void:
    var id = req.get("id", null)
    var method: String = req.get("method", "")
    var params: Dictionary = req.get("params", {})
    
    var result = _dispatch(method, params)
    var resp := {
        "jsonrpc": "2.0",
        "id": id
    }
    if typeof(result) == TYPE_DICTIONARY and result.has("error"):
        resp["error"] = {"code": -32000, "message": result.error}
    else:
        resp["result"] = result
    
    print(JSON.stringify(resp))

func _dispatch(method: String, params: Dictionary):
    match method:
        "ping": return "pong"
        "validate_scene": return _validate_scene(params.get("path", ""))
        "validate_script": return _validate_script(params.get("path", ""))
        "shutdown":
            _running = false
            return "ok"
        _: return {"error": "Method not found: " + method}
```

### 4.2 JSON-RPC 2.0 Protocol Specification

All requests, responses, and notifications conform strictly to the JSON-RPC 2.0 specification [7].

#### 1. Method Request Frame:
```json
{
  "jsonrpc": "2.0",
  "id": "req-001",
  "method": "scene/validate",
  "params": {
    "scenePath": "res://scenes/main.tscn"
  }
}
```

#### 2. Success Response Frame:
```json
{
  "jsonrpc": "2.0",
  "id": "req-001",
  "result": {
    "valid": true,
    "nodeCount": 18,
    "unresolvedResources": [],
    "warnings": []
  }
}
```

#### 3. Error Response Frame:
```json
{
  "jsonrpc": "2.0",
```

The MCP server exposes the following standardized tools:
- `godot_scene_read`: Reads and parses a `.tscn` file into a structured JSON AST.
- `godot_scene_synthesize`: Atomically synthesizes or edits a `.tscn` file with ClassDB parameter validation.
- `godot_script_check`: Headlessly validates GDScript syntax and typing using `--check-only`.
- `godot_scene_validate`: Headlessly loads and instantiates a scene in the engine runtime to detect broken dependencies.
- `godot_class_lookup`: Queries property, method, and signal metadata for any ClassDB type.
- `godot_run_tests`: Executes GUT or GdUnit4 test suites headlessly and returns structured pass/fail metrics.

### 4.4 State Synchronization & Conflict Resolution

When editing scenes while Godot is closed, KesherAI records the modification timestamp (`mtime`) and a content hash of the target `.tscn` file. 

When the user subsequently launches the Godot graphical editor:
1. KesherAI's background bridge detects the editor connection.
2. The addon triggers `EditorFileSystem.scan()`, forcing Godot to reload modified files from disk without displaying external conflict dialogues.
3. If the user had unsaved changes in the editor before KesherAI wrote an offline modification, the bridge compares the file hash with the stand-in snapshot, flagging any conflicting node paths in the chat and preserving both versions in `GameCheckpoints`.

## 5. Usability for Roee: Remote Workflows, Mobile (390 px), and Hardware Guardrails

### 5.1 Zero-Headroom Mobile Usability (390 px Width)
Roee frequently manages game projects remotely from a phone. Opening the full Godot GUI over remote desktop is bandwidth-heavy and unusable on a mobile touch screen. 

With the headless bridge and `.tscn` synthesizer:
- The phone interface displays the **Scene Stand-In View** (`apps/web/src/pages/GodotPage.tsx`), rendering lightweight 2D/3D representations of the scene tree.
- Roee can tap to reposition objects, add child nodes, or trigger test runs directly from mobile touch controls.
- Changes execute as headless AST edits on the PC; when he sits down at the desktop and opens Godot, the scene is already updated and verified.

### 5.2 GPU & VRAM Budgeting Guardrails
Local AI development on consumer hardware requires strict VRAM management:
- Running Godot's Forward+ or Mobile rendering server in the background consumes 400–1,200 MB of VRAM.
- When local chat models (Qwen 3.6 27B / DictaLM 3.0) or ComfyUI generation jobs are running, this background VRAM consumption can cause out-of-memory (OOM) crashes.
- KesherAI's headless Godot daemon runs with `--rendering-driver dummy`, consuming **0 MB VRAM** and less than **75 MB of system RAM**.
- The daemon automatically sleeps when idle for more than 5 minutes and shuts down cleanly during heavy model generation passes.

## Conclusion

A native Godot 4 headless bridge transforms KesherAI into a full-fledged engine copilot capable of operating without the Godot graphical editor open. By combining Godot's headless CLI flags (`--headless`, `--check-only`, `--import`) with strict `.tscn` Format 3 AST synthesis, Base36 UID management, pruned `ClassDB` reflection caching, and a JSON-RPC 2.0 bridge, KesherAI provides safe, atomic, and undoable scene manipulation across desktop and mobile devices.

### Immediate Implementation Roadmap
1. **Phase 1 (AST Engine):** Upgrade `packages/core/src/tscn.ts` from simple regex transform replacements to a full AST-based reader/writer supporting `[ext_resource]`, `[sub_resource]`, `load_steps`, and UID sidecars.
2. **Phase 2 (Headless Validator):** Implement `packages/core/src/godot-cli.ts` wrapping `godot --headless` commands for `--check-only` script parsing and headless scene instantiation.
3. **Phase 3 (ClassDB Indexer):** Add an automated one-click extraction script that generates compressed `classdb-cache.json` using `--dump-extension-api`.
4. **Phase 4 (MCP Server):** Ship the native Godot MCP preset in `packages/core/src/mcp.ts` and update `integrations/godot/addons/kesher_bridge` with dual-mode headless/GUI support.
