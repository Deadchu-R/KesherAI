# A Free Backup Path from Phone to PC When the Hub Is Down: Tailscale, Cloudflare Tunnel, and WebRTC P2P

## Summary

KesherAI's remote connectivity between the Android phone and the host PC relies primarily on the Kesher Cloud hub—a Cloudflare Worker coupled with a SQLite-backed Durable Object running on Cloudflare's Workers Free plan. When the hub reached Cloudflare's free daily quota of 100,000 SQL rows written, all state-persisting operations failed with HTTP 503 (`hub-storage-limit`), disconnecting the phone from the PC until the 00:00 UTC quota reset.

This research evaluates five zero-cost remote access technologies—Tailscale, Cloudflare Tunnel, WebRTC Peer-to-Peer (P2P), ZeroTier, and ngrok—alongside proven real-world architectures from LM Studio (`lms link`), Home Assistant, Syncthing, and Moonlight/Parsec. 

The investigation concludes that the optimal architecture for KesherAI and Roee is a **two-tiered zero-cost backup system**:
1. **Primary Zero-Install Fallback (Application Layer): Ephemeral WebRTC DataChannel** using the hub (or a free stateless WebSocket worker) strictly for in-memory SDP signalling without SQLite writes, paired with free public STUN (`stun:stun.l.google.com:19302`) and Metered.ca Open Relay (20 GB/month free TURN) for 100% CGNAT traversal.
2. **Robust Infrastructure Fallback (Network Layer): Tailscale Personal Mesh** with Tailscale Serve / MagicDNS. By following LM Studio's paradigm and integrating Tailscale detection into KesherAI's desktop app, Roee benefits from unlimited peer-to-peer WireGuard connections that bypass Cloudflare entirely with zero bandwidth limits and zero router configuration.

## Root Cause Analysis: The Hub Outage

KesherAI's hub architecture (`apps/hub/src/hub-do.ts` and `packages/shared/src/hub-protocol.ts`) utilizes a single Cloudflare Durable Object named `"owner"` backed by an embedded SQLite database. On Cloudflare's Workers Free tier, Durable Objects impose strict daily operational ceilings [1]:
* **SQL Rows Written:** **100,000 rows per day** (hard cap).
* **SQL Rows Read:** **5,000,000 rows per day**.
* **Storage Capacity:** **5 GB** total.
* **Quota Reset Window:** Exactly **00:00 UTC** [1].

In normal operation, the hub logs every presence heartbeat (`agentBeatMs: 25_000`), device status transition, pending approval, audit line, and batched agent activity event (`agentEventsTotal: 2000`) to SQLite. When heavy coding agent tasks or multiple agent runs fire concurrently, transaction volume rapidly exhausts the 100,000 SQL row write allowance. 

Once exhausted, Cloudflare's storage API throws quota exceptions (`storageCode(e) === "limit"`), triggering the hub's guard:
```typescript
return json({ error: "hub-storage-limit", message: "Daily storage quota reached." }, 503);
```
Although existing WebSocket connections can technically relay messages in memory via `ctx.getWebSockets()` [1], any reconnect, token rotation, ticket exchange (`POST /api/ticket`), or new pairing attempt fails immediately. Because `hub-client.ts` schedules its next retry for after UTC midnight (`afterUtcMidnight`), the phone app remains completely locked out for hours.

## Detailed Technology Breakdown

### 1. Tailscale (Personal Plan)

* **Architecture & Mechanics:** Tailscale establishes an encrypted WireGuard mesh network between the user's devices. A lightweight coordination server coordinates key exchange without ever touching or seeing decrypted payload traffic [2]. Devices obtain a static private IP in the CGNAT `100.64.0.0/10` range and a private DNS name via MagicDNS (e.g., `kesher-pc.tailnet-name.ts.net`) [2].
* **Tailscale Serve vs. Tailscale Funnel:**
  * `tailscale serve`: Exposes a local port (e.g., `127.0.0.1:4000`) exclusively to the private tailnet using internal HTTPS with automatic TLS certificates [3]. It operates without bandwidth caps or throttling [3].
  * `tailscale funnel`: Exposes a local service to the public internet via a public `*.ts.net` proxy [3]. Tailscale enforces **undocumented, non-configurable bandwidth throttling** on Funnel ("a funnel, not a hose") and restricts ports to 443, 8443, and 10000 [3]. 
  * *KesherAI Recommendation:* KesherAI should **never use Funnel** for remote access; it should use direct tailnet routing or `tailscale serve`, which are completely unrestricted and private [2, 3].
* **Setup Effort for Roee:** Roee installs Tailscale on Windows and Android, logging in with his existing Google account on both. The PC and phone join the same tailnet automatically.
* **Security:** True end-to-end WireGuard encryption. The PC's KesherAI port is invisible to the public internet; only devices authenticated to Roee's Google-backed tailnet can send packets.
* **Free Plan Limits:** Completely free for non-commercial use; supports up to 6 users and unlimited personal devices [2].
* **Mobile Networks & CGNAT:** Direct peer-to-peer UDP hole-punching succeeds in ~85-90% of cellular scenarios. If both the cellular carrier and home ISP utilize strict symmetric NAT, Tailscale automatically and transparently routes through its encrypted global DERP relay servers without user action [2].
* **Automation in KesherAI:** KesherAI desktop checks if Tailscale is installed (querying the local daemon via `tailscale.exe status --json` or `127.0.0.1:41112`). It extracts the PC's Tailscale IPv4 address (`100.x.y.z`) and MagicDNS FQDN. When Roee generates a pairing QR code in **Settings → Phone**, KesherAI includes this Tailscale address in the QR payload.

### 2. Cloudflare Tunnel (`cloudflared` + Cloudflare Access)

* **Architecture & Mechanics:** The `cloudflared` daemon runs on the host PC and establishes four persistent outbound connections to the nearest Cloudflare edge PoPs over HTTP/2 or QUIC [4]. Cloudflare Access sits in front of the hostname, enforcing identity authentication before passing traffic through the tunnel [4].
* **Durable Object Quota Elimination:** Cloudflare Tunnel operates strictly as an edge reverse proxy. It **does not utilize Workers KV, D1, or Durable Object SQLite storage**, completely eliminating the 100,000 SQL row write bottleneck [1, 4].
* **Setup Friction:** Setting up Cloudflare Tunnel and Access has the highest friction of any option:
  1. Roee must own a custom domain (e.g., `roee-kesher.com`).
  2. The domain's DNS nameservers must be pointed to Cloudflare [4].
  3. Setting up a Cloudflare Zero Trust organization requires **submitting a valid credit card on file**, even though the free tier covers up to 50 users [4].
  4. Manual configuration of Cloudflare Access policies, service tokens, and Google OAuth IdP integration is required [4].
* **Security:** TLS terminates at Cloudflare's edge. Cloudflare decrypts and inspects the HTTP headers and session cookies before forwarding traffic to `cloudflared`. However, KesherAI's application-layer encryption (`SealedEnvelope` AES-GCM) ensures that task specs, approvals, and board commands remain unreadable by Cloudflare.
* **Automation in KesherAI:** Very difficult to automate with a single button because provisioning a tunnel and Access application programmatically requires high-privilege Cloudflare API tokens (`Zero Trust:Edit`, `DNS:Edit`) and an existing active zone [4].

---

### 3. WebRTC Peer-to-Peer (Hub Signalling + Free STUN/TURN)

* **Architecture & Mechanics:** The PC and phone establish a direct peer-to-peer `RTCDataChannel` using WebRTC (SCTP over DTLS over UDP) [5]. 
* **Zero-Storage Signalling:** WebRTC requires signalling solely to exchange initial session descriptions (SDP Offer/Answer) and ICE candidates [5]. In KesherAI's hub, this can be implemented as an **ephemeral in-memory WebSocket relay**. Unlike task queues and presence history, signalling messages are transient: the Durable Object forwards them via `ws.send()` to the peer socket without performing any SQLite `INSERT` or `UPDATE` queries [1]. Even if the hub's SQLite storage is disabled, in-memory WebSocket forwarding remains functional [1].
* **NAT Traversal & Free STUN/TURN:**
  * **STUN:** Resolves public IP/port bindings for devices behind full-cone or restricted-cone NAT. Free public STUN servers—such as Google's `stun:stun.l.google.com:19302` or Cloudflare's `stun.cloudflare.com`—are completely free, highly reliable, and unlimited [5, 6].
  * **Symmetric NAT Challenge:** Mobile cellular data networks (e.g., 4G/5G CGNAT) typically assign symmetric NAT mappings. When both mobile phone and home broadband are behind symmetric NAT, STUN cannot punch through, causing direct P2P connections to fail in 10-15% of cases [5].
  * **Free TURN Relay Solutions:**
    1. **Metered.ca Open Relay:** Offers **20 GB per month of free TURN relay traffic** running on standard web ports (TCP/UDP 80 and 443) to bypass restrictive firewalls [5]. Because KesherAI transfers lightweight JSON tasks and status frames (typically <15 KB per turn), 20 GB easily accommodates tens of thousands of remote sessions per month [5].
    2. **Cloudflare Realtime TURN:** Provides a massive **1,000 GB (1 TB) free monthly allowance**, but requires a credit card on file to activate [6].
* **Setup Effort for Roee:** **Zero configuration.** Everything is handled internally by KesherAI's codebase using browser/Node WebRTC APIs (`RTCPeerConnection`).
* **Battery & Mobile Data:** Maintaining an open WebRTC connection requires periodic ICE keep-alive packets and DTLS heartbeats. If left running continuously in the background on mobile data, it can prevent cellular radio dormancy and increase battery drain (5-8% per day) [5]. Therefore, the data channel should only be established on-demand when the app is active or when an urgent approval arrives.

---

### 4. ZeroTier (Basic Free Plan)

* **Architecture & Mechanics:** ZeroTier operates as an open-source virtual network hypervisor, implementing a virtual Layer 2 Ethernet switch (VL2) across the public internet [7].
* **Free Plan Limits:** ZeroTier recently restructured its free tier to **strictly 10 connected devices per account, 1 network, and 1 network administrator** [7]. While 10 nodes is adequate for a single user, it is a rigid limit compared to Tailscale's unlimited devices [2, 7].
* **Setup Friction:** Roee must create a ZeroTier Central account, create a network to generate a 16-character Network 10, install ZeroTier One on both devices, join the network, and log into the ZeroTier web console to manually check "Authorize" for each node [7].
* **Android Battery Overhead:** Because ZeroTier emulates a Layer 2 Ethernet switch, it processes virtual ARP broadcasts, DHCP packets, and multicast discovery traffic. On Android, this broadcast chatter frequently triggers CPU wake-locks, resulting in measurably worse battery life than WireGuard-based solutions like Tailscale [2, 7].

---

### 5. ngrok (Free Tier)

* **Architecture & Mechanics:** ngrok runs an agent on the PC that opens a secure reverse proxy tunnel to ngrok's globally distributed cloud ingress nodes [8].
* **Disqualifying Free Tier Limitations:**
  * **1 GB per Month Data Transfer Limit:** ngrok enforces a strict 1 GB/month egress cap on free accounts [8].
  * **20,000 HTTP Requests per Month:** Equivalent to roughly 660 requests per day [8]. A phone app polling for presence or streaming agent steps via Server-Sent Events (SSE) will exhaust this monthly limit in days.
  * **Anti-Phishing Browser Interstitial:** On free accounts, any browser-based HTTP request displays a mandatory interstitial warning page ("You are about to visit an ngrok-free endpoint...") requiring a manual button click [8]. This page breaks programmatic WebView and API handshakes unless explicit bypass headers (`ngrok-skip-browser-warning`) are injected into every request [8].
* **Verdict:** Unsuitable as a reliable backup path for KesherAI.

## Industry Reference Implementations

### 1. LM Studio (`lms link` over Tailscale)
Faced with the exact same objective—allowing users on laptops and mobile phones (the *Locally* app) to reach their home GPU desktop without port forwarding or subscription servers—LM Studio partnered directly with Tailscale to launch **LM Link** [9].
* **Technical Integration:** LM Studio embedded Tailscale's `tsnet` library directly into its core desktop binary (`llmster`) [9]. `tsnet` is an open-source Go package that runs a full Tailscale node entirely in user-space without creating virtual network adapters or modifying the operating system's kernel routing tables [9].
* **User Flow:** Roee signs in to his account inside LM Studio. The app communicates with Tailscale's coordination API to join an isolated tailnet, and models running on the home PC immediately appear in the mobile app as if they were local [9].
* **Data Privacy:** Payloads (prompts, completions, tokens) travel strictly peer-to-peer over WireGuard; Tailscale and LM Studio servers never observe model inputs or outputs [9].

### 2. Home Assistant (Dual-Path Remote Architecture)
Home Assistant addresses remote access across millions of smart homes using multiple strategies:
* **Nabu Casa (Home Assistant Cloud):** A paid ($6.50/month) managed dual-tunnel relay.
* **Community Free Standards:** Tailscale and Cloudflare Tunnel add-ons are the dominant free solutions. The community overwhelmingly favors Tailscale because it functions behind CGNAT without purchasing a domain or exposing public web ports [11].
* **Companion App Automatic Failover:** The Home Assistant mobile companion app configures two distinct URLs [11]:
  1. *Internal Connection URL:* Local LAN address (`http://192.168.1.x:8123`) validated against local Wi-Fi SSIDs.
  2. *External Connection URL:* Remote address (Tailscale MagicDNS or Cloudflare Tunnel).
  * *Failover Algorithm:* When the mobile app opens or detects a network transition, it issues a health-check request to the Internal URL with an aggressive **2.0-second timeout**. If unreachable, it seamlessly switches to the External URL without prompting the user [11].

### 3. Syncthing (Global Discovery + Community Relay Pool)
Syncthing continuously synchronizes data between devices with zero central storage and no accounts [10]:
1. **Local Discovery:** Broadcasts UDP packets on the local subnet [10].
2. **Global Discovery:** Nodes announce their cryptographic Device ID and external IP/port to public global discovery servers (`discovery.syncthing.net`) [10].
3. **NAT Traversal:** Attempts UPnP/NAT-PMP port mapping and STUN-like hole punching [10].
4. **Relay Pool Fallback (`strelaysrv`):** When direct P2P is blocked by symmetric NAT, Syncthing routes traffic through public volunteer-operated relays in the Syncthing Relay Pool (`relays.syncthing.net`) [10].
5. **Zero-Trust Security:** Data passing through community relays is end-to-end encrypted with TLS (Block Exchange Protocol). Relay operators only see encrypted byte streams and cannot inspect file names or content [10].

### 4. Parsec / Moonlight + Sunshine
* **Parsec:** Uses a custom UDP protocol (BUD). Parsec's backend handles authentication and coordinates STUN-based UDP hole punching to stream 60 FPS video directly between PC and client.
* **Moonlight & Sunshine:** For playing games remotely across the internet behind CGNAT, the official Moonlight documentation explicitly discourages opening router ports and recommends installing **Tailscale or ZeroTier**, which eliminates NAT issues with zero packet forwarding configuration.

## Recommended Architecture for KesherAI

To guarantee that Roee never experiences downtime when the Cloudflare hub exhausts its daily quota, KesherAI should implement a **hybrid failover architecture**:

```
                       +---------------------------------------+
                       |           Phone Companion App         |
                       +---------------------------------------+
                                           |
                +--------------------------+--------------------------+
                |                          |                          |
       [Priority 1: LAN]          [Priority 2: Cloud Hub]    [Priority 3: Tailscale / WebRTC]
                |                          |                          |
      Local Wi-Fi Ping (<1.5s)     Cloudflare Hub (DO)        Direct WireGuard Mesh / TURN
                |                          |                          |
    http://192.168.1.x:4000      https://hub.workers.dev    http://100.x.y.z:4000
                |                          |                          |
                v                          v                          v
      +-----------------------------------------------------------------------+
      |                           Host PC (KesherAI)                          |
      +-----------------------------------------------------------------------+
```

### 1. In-App Setup Automation (The "One-Button" Experience)

1. **Desktop Auto-Detection:**
   * In `packages/core`, KesherAI checks for a local Tailscale installation by querying `tailscale.exe status --json` or verifying the presence of network interfaces matching `100.*.*.*`.
   * If Tailscale is active, KesherAI reads the Tailscale IPv4 address (`tailscaleIp`) and MagicDNS hostname (`magicDns`).
   * In **Settings → Phone**, a toggle labeled **"Tailscale Backup Path"** appears enabled by default.
2. **Enhanced Pairing QR Code:**
   * Currently, the pairing QR code contains a single URL (`http://<local-ip>:4000/?token=...`).
   * KesherAI upgrades the QR payload to a multi-endpoint JSON descriptor:
     ```json
     {
       "v": 2,
       "name": "Roee-Desktop",
       "token": "kd_xxxxxxxxxxxx",
       "endpoints": {
         "local": "http://192.168.1.50:4000",
         "hub": "https://kesher-hub.example.workers.dev",
         "tailscale": "http://100.85.120.45:4000"
       }
     }
     ```
3. **Android Pairing:**
   * When Roee scans the QR code using the Android app's barcode scanner (`apps/android/www/index.html`), the app stores all three endpoints in local preferences (`localStorage`).

### 2. Automatic Path Selection & Failover Algorithm

The Android app implements an automatic waterfall selection algorithm:

1. **Step 1: Local Network Probe (Fast Timeout)**
   * When the app opens, it dispatches a lightweight `GET /api/health` request to `endpoints.local` with an `AbortController` timeout of **1,200 ms**.
   * If the probe succeeds (HTTP 200), the app binds directly to `endpoints.local`. (Fastest response, zero mobile data usage, zero cloud quota consumption).
2. **Step 2: Kesher Cloud Hub Check**
   * If the local probe times out (indicating Roee is outside on mobile data), the app connects to `endpoints.hub`.
   * Under normal conditions, WebSocket communication and task dispatch proceed through the hub.
3. **Step 3: Instant Quota / Error Failover**
   * If `endpoints.hub` returns HTTP 503 (`hub-storage-limit` or `hub-limit`), encounters repeated WebSocket disconnections, or fails to respond within **2,500 ms**, the app immediately switches active transport to `endpoints.tailscale`.
   * If the Tailscale client is active on Roee's phone, the connection to `http://100.x.y.z:4000` succeeds instantly over WireGuard.
4. **Step 4: UI Transparency**
   * The top status bar displays an icon reflecting the active path:
     * `🟢 Local Wi-Fi` (Direct LAN)
     * `☁️ Kesher Cloud` (Hub Relay)
     * `⚡ Tailscale P2P` (Encrypted Backup Mesh)

### 3. Hub Optimizations to Prevent Quota Outages

To prevent the hub from hitting Cloudflare's 100,000 SQL row limit in the first place:
1. **Stateless Presence:** Keep live device presence heartbeats (`ping` / `agentBeatMs`) exclusively in Durable Object memory (`this.state`), rather than updating SQLite rows on every beat [1].
2. **Batched Audit Writes:** Flush agent event history to SQLite only once per minute or upon task completion, rather than on every individual sub-agent activity frame [1].
3. **Stateless WebRTC Signalling:** Add an open, ephemeral WebSocket endpoint (`/ws/signal`) to `worker.ts` that immediately forwards JSON SDP offer/answer messages between paired device IDs without touching the Durable Object's SQLite storage [1, 5].

## Conclusion

Cloudflare's free Durable Object storage limit of 100,000 daily SQL row writes makes relying solely on SQLite persistence vulnerable to unexpected lockouts during heavy agent workloads.

Among all potential backup paths:
* **ngrok** is disqualified by severe bandwidth (1 GB/mo) and request caps (20,000/mo) [8].
* **ZeroTier** is viable but constrained by a 10-node ceiling, higher Android battery overhead, and manual web console approvals [7].
* **Cloudflare Tunnel** eliminates storage limits but introduces high setup friction, requiring a custom domain, nameserver migration, and a credit card for Zero Trust setup [4].
* **WebRTC P2P** provides the cleanest zero-install application-level fallback when coupled with free STUN and Metered.ca TURN (20 GB/mo free) [5].
* **Tailscale** represents the most robust, zero-cost, network-level remote access solution [2]. With unlimited personal devices, zero bandwidth limits inside the tailnet, military-grade WireGuard encryption, and automated detection via KesherAI's pairing QR code, Tailscale guarantees that Roee will never be locked out from his PC [2, 9].
