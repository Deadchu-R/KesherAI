# KesherAI Speed and Lightweight Shortlist

This report provides a ranked shortlist of performance and footprint optimizations for KesherAI (Electron, Fastify/Node.js, React UI, llama.cpp, ComfyUI, RTX 3090, Ryzen 9 9950X3D, Windows). 

## Ranked Shortlist of Changes

### 1. Idle Unload of Local llama.cpp Models
* **Expected Gain:** Frees significant VRAM/RAM when AI engines are idle, preventing Windows memory pressure on the RTX 3090.
* **Cost:** Low development cost (implementing a timeout handler or auto-unload hook in Node.js/Fastify using `node-llama-cpp` or a proxy approach similar to `llama-swap`) [7, 12].
* **What to Measure First:** Baseline VRAM usage via Windows Task Manager / nvidia-smi while KesherAI sits idle for 5, 10, and 30 minutes.

### 2. React UI Route and Component Lazy Loading
* **Expected Gain:** Faster initial app window appearance and lower initial startup memory [1].
* **Cost:** Low to medium (splitting large route chunks using `React.lazy` and `Suspense` inside the Electron renderer) [1].
* **What to Measure First:** Electron startup time (time-to-interactive) and initial renderer heap size using Chrome DevTools Performance and Memory tabs.

### 3. Native Rust Add-on via `napi-rs` for Heavy File Indexing/Log Search
* **Expected Gain:** Eliminates JavaScript main-thread stutter during heavy disk operations, log searches, or differential file scans by offloading heavy loops to compiled Rust threads [19].
* **Cost:** Medium-high (writing/integrating a small `napi-rs` module for core string/file operations) [19].
* **What to Measure First:** CPU spike duration and main thread blocking time during file searches or large log indexing actions using Chrome DevTools.

### 4. Electron Main Window Optimization & Deferred Background Tasks
* **Expected Gain:** Snappier launch experience (~2-second target) by utilizing hidden window creation (`show: false` and `ready-to-show`) and deferring analytics/updates via `setImmediate` [1].
* **Cost:** Very low (configuration tweak in main.js/ts).
* **What to Measure First:** Cold-start time from process spawn to visible UI render [1].

---

## Concrete Tasks

1. **Implement Idle Unload Logic:** Add an inactivity timeout (e.g., 10 minutes) inside the Fastify/Node backend to safely unload inactive `node-llama-cpp` or external router sessions and reclaim VRAM [7, 12].
2. **Apply React Route Splitting:** Wrap non-critical dashboard/settings/report views in `React.lazy()` and `<Suspense>` within the React UI layout [1].
3. **Configure Deferred Window Show:** Update the Electron main process initialization to instantiate `BrowserWindow({ show: false })` and trigger `.show()` only on the `ready-to-show` event [1].
4. **Benchmark Core Loop with DevTools:** Record a baseline CPU and memory profile in Electron DevTools during startup and file indexing to quantify before/after gains for the shortlist tasks [1].
