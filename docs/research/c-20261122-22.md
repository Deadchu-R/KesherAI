# Technical Architecture: Real-Time Local Voice-to-Engine Pipeline for KesherAI (Hebrew & English)

### Summary
This research report defines the technical architecture for an ultra-low-latency, local voice-to-engine pipeline designed for Roee's use with KesherAI. The system targets sub-300ms audio-to-text latency on an RTX 3090, balancing bilingual command requirements (Hebrew and English) against lightweight local execution. It integrates Silero VAD for zero GPU idle consumption, evaluates Whisper.cpp versus Moonshine ONNX for speech-to-text, maps bilingual phrases into engine actions, and utilizes Kokoro-82M for local audio confirmation receipts.

## Local Speech-to-Text (STT) Runtime & Bilingual Evaluation
To achieve target speeds on an RTX 3090, the pipeline must choose between Whisper.cpp variants and Moonshine ONNX:
* **Whisper.cpp (`large-v3-turbo` vs `base`/`small`):** Whisper natively supports 99 languages, making it the required choice for bilingual Hebrew and English transcription. While `whisper large-v3-turbo` or `small` variants can leverage GPU acceleration via CUDA, standard Whisper models carry overhead by padding audio clips to 30-second blocks [1]. 
* **Moonshine ONNX WebGPU:** Moonshine is highly optimized for edge devices, showing rapid execution (e.g., `moonshine/base` at ~9x real-time on CPU with a ~600MB RAM footprint) [1]. However, **Moonshine is English-only**, and its language field is explicitly ignored [1]. 
* **Runtime Verdict:** Because the use case mandates bilingual Hebrew and English command processing, **Moonshine ONNX cannot be used as the primary STT model** unless restricted strictly to English [1]. Whisper.cpp (or a dedicated multilingual model) must be utilized to capture Hebrew phrases like *"תוסיף אור אדום מעל השחקן"*.

## Background Listening Loop & Voice Activity Detection (VAD)
To ensure zero GPU idle consumption and avoid continuous polling overhead, the pipeline adopts a hybrid background listening loop using **Silero VAD ONNX** (such as via `silero-vad-lite`) [18]:
* **Mechanism:** The VAD wrapper runs completely locally via ONNX Runtime (CPU execution) with zero dependencies, embedding the Silero streaming model (v6.2.3) directly [18].
* **Resource Management:** Audio is processed in rigid 32ms chunks (512 samples for 16kHz, mono 32-bit float PCM normalized to $[-1, 1]$) [18]. Because it relies on CPU-bound ONNX execution and maintains recurrent states internally, the GPU draws zero power during silence, satisfying the zero-GPU-idle requirement [18].
* **Push-to-Talk (PTT) Alternative:** PTT can bypass VAD entirely by opening the audio stream only upon a hardware key press, completely eliminating background processing overhead if preferred.

## Command Classification Schema & Engine Mapping
Spoken natural language commands from both languages must be translated deterministically into engine actions (C#, Blueprints, or editor commands) for KesherAI:
* **Hebrew Example Input:** *"תוסיף אור אדום מעל השחקן"* 
* **English Example Input:** *"Add a point light above the player"*
* **Schema Design:** Once text is emitted by the STT layer, a lightweight local intent parser or regular expression / local LLM router maps the semantic payload into a structured JSON action command:
  ```json
  {
    "action": "spawn_actor",
    "params": {
      "type": "PointLight",
      "color": "red",
      "target": "player",
      "location": "above"
    }
  }
  ```
* **Engine Execution:** This JSON payload is piped directly into KesherAI's backend tool registry via local IPC or a C# editor plugin hook to execute the corresponding Blueprints or native editor manipulation scripts.

## Spoken Feedback & TTS Integration
To deliver brief audio confirmation receipts back to Roee without network latency, lightweight local text-to-speech engines were evaluated:
* **Kokoro-82M:** An 82-million parameter open-weight model (StyleTTS 2 architecture + ISTFTNet vocoder) licensed under Apache 2.0 [2]. It weights under ~350MB, outputs clean 24kHz audio, runs comfortably on a CPU, and requires `espeak-ng` [2]. It supports 8 languages (including American/British English, French, Spanish, and Mandarin) via a simple Python API (`KPipeline`) [2]. 
* **Piper TTS & Chatterbox Multilingual:** Piper is known as a speed king for local CPU inference, whereas Chatterbox and Kokoro offer alternative audio profiles. 
* **TTS Selection:** **Kokoro-82M** is selected for the confirmation receipt module due to its permissive Apache 2.0 commercial license, tiny memory footprint, and high-quality 24kHz audio generation for short receipt phrases [2].

## Conclusion
The architecture successfully reconciles the multi-faceted technical requirements: **Silero VAD ONNX** guarantees zero GPU consumption during idle silence; **Whisper.cpp** fulfills the mandatory bilingual requirement for Hebrew and English (whereas Moonshine ONNX is restricted to English [1]); structured JSON schema mapping translates localized commands into KesherAI C#/Blueprint actions; and **Kokoro-82M** provides rapid, lightweight local audio confirmations under an Apache 2.0 license [2].
