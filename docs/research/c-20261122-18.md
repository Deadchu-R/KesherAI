# Headless Unreal Level (.umap) Reading and Asset Inspection Without Editor GUI

This research investigates how KesherAI can inspect and extract actor hierarchies, transforms, and mesh references from Unreal Engine 5.x levels (`.umap`) while the Unreal Editor GUI is closed. It evaluates direct binary parsing, headless commandlet execution, and pre-indexing caches; explains the "empty level list" failure observed on AutoShooter and TestProj; provides performance benchmarks; and defines an architectural implementation plan optimized for desktop and mobile (390 px) workflows.

---

## 1. Context and Problem Statement in KesherAI

KesherAI enables developers to inspect, review, and manipulate game projects directly from desktop chats or remotely from a mobile phone (390 px) without requiring the heavyweight game engine editor to remain open [1]. For Godot, scenes are plain-text (`.tscn`) and can be parsed or edited directly [1]. For Unity, scenes are YAML text (`.unity`), allowing component hierarchies and transforms to be parsed offline with mutations applied via queued CLI batches [1].

In contrast, Unreal Engine presents significant challenges:
1. **Binary Serialization:** Unreal Engine levels (`.umap`) and assets (`.uasset`) are serialized in proprietary binary package formats (`UPackage`) rather than human-readable text [2].
2. **UE5 World Partition & OFPA:** Starting in Unreal Engine 5.0, open-world maps and modern templates (such as AutoShooter, Lyra, and CitySample) utilize World Partition and One File Per Actor (OFPA) [3]. The root `.umap` file is virtually empty; persistent level actors are decomposed into hundreds or thousands of separate `.uasset` files under an `__ExternalActors__` directory structure [3, 4].
3. **Engine Footprint:** Spawning `UnrealEditor.exe` or `UnrealEditor-Cmd.exe` consumes substantial system RAM (2.5 GB to 8 GB+) and requires 20 to 90 seconds of initialization latency, making on-demand launches impractical for interactive queries from a mobile device [5, 6].
4. **Current Implementation:** KesherAI implements a hybrid bridge (`integrations/unreal/KesherAIBridge`) and route handlers (`packages/core/src/routes/unreal-level.ts`, `packages/core/src/unreal-bridge.ts`). When Unreal Editor is closed, KesherAI currently chains headless commandlet calls (`UnrealEditor-Cmd.exe Project.uproject -run=KesherBridge -unattended -NullRHI -stdout`) to execute `KesherLevel::Read` and `KesherLevel::Mesh` [1].

## 2. Technical Evaluation of the Three Parsing Avenues

### Avenue 1: Direct Binary Parsing of `.umap` and Asset Registries (`AssetRegistry.bin`)

Direct binary parsing attempts to inspect `.umap` files, `.uasset` packages, and compiled asset registries (`AssetRegistry.bin`) directly within Node.js/TypeScript or via external open-source C#/C++ libraries without invoking the Unreal Engine binary.

#### Structure of `.umap` Packages
An Unreal `.umap` file shares the same package architecture as any `.uasset` file:
* **`FPackageFileSummary`:** Header containing package magic numbers (`0x9E2A83C1`), engine file versions (`FileVersionUE`), summary flags, and file offsets to name, import, and export tables [2, 7].
* **Name Map:** Indexed string table of `FName` entries referenced throughout the package.
* **Import Map (`FObjectImport`):** External object dependencies, including referenced Blueprint classes, static meshes (`/Game/Environment/Meshes/SM_Rock.SM_Rock`), and native engine types (`/Script/Engine.StaticMeshComponent`) [7].
* **Export Map (`FObjectExport`):** Objects serialized inside the package (e.g., `UWorld`, `ULevel`, `AStaticMeshActor`, `USceneComponent`).
* **Export Data Blob (`.uexp` or embedded):** Serialized property tags (`FPropertyTag`) holding values such as `RelativeLocation`, `RelativeRotation`, `RelativeScale3D`, `StaticMesh`, and `AttachParent` [7].

#### The World Partition / OFPA Hurdle in UE5
In UE4 and non-partitioned UE5 levels, opening the root `.umap` reveals the complete actor hierarchy in its Export Map. However, in UE5 World Partition maps:
* The `.umap` file contains only the `UWorld`, `UWorldPartition`, and `AWorldSettings` exports [3].
* Actors reside in external loose packages located at:
  `Content/__ExternalActors__/<PackagePath>/<HashSubfolder>/<ActorGUID>.uasset` [3, 4].
* To construct the scene graph of a World Partition level, a binary parser cannot simply read the `.umap`. It must locate the corresponding `__ExternalActors__` folder, traverse nested hash buckets, parse thousands of individual `.uasset` files, decode their tagged properties, and assemble parent-child attachments in memory [3, 8].

#### Zen Loader and `AssetRegistry.bin`
* In editor environments, `AssetRegistry.bin` (or memory-mapped asset registries) stores `FAssetData` metadata, package dependency graphs, and searchable asset tags (`TMap<FName, FString>`) [9, 10].
* Under UE5 Zen Loader (`.utoc`/`.ucas` containers in cooked builds), asset registry metadata is bundled into container metadata [9]. In loose development projects, `AssetRegistry.bin` may exist in `Intermediate/` or `Saved/`, but it only indexes package paths, classes, and asset tags; it does not store per-instance actor placement transforms (`RelativeLocation`, `RelativeRotation`) within a level [9, 10].

#### Library Ecosystem & Feasibility for KesherAI
* **UAssetAPI (C#):** Actively maintained open-source .NET library by atenfyr capable of reading/writing UE package summaries, property tables, and asset registries [7]. However, it is written in C# (.NET), requiring a separate CLR runtime process or WebAssembly bridge to communicate with KesherAI's Node.js core [7].
* **CUE4Parse (C#):** High-performance C# parser supporting IoStore, Zen Loader, and package deserialization [8]. Like UAssetAPI, it is .NET-dependent and primarily targets cooked game packages rather than live editor source trees [8].
* **TypeScript / Node.js:** There are no maintained, full-featured native TypeScript libraries that reliably deserialize modern UE 5.0–5.5 tagged property formats, World Partition external actors, and custom struct serializations.
* **Format Churn:** Epic Games frequently updates internal serialization versions across minor engine releases (e.g., `EUnrealEngineObjectUE5Version` changes between 5.1, 5.3, 5.4, and 5.5). Any custom binary parser risks breaking on minor engine updates, imposing high maintenance overhead [2, 7].

### Avenue 2: Headless Invocation of Unreal Commandlets (`UKesherBridgeCommandlet`)

Headless commandlet invocation runs Unreal Engine without a user interface by launching `UnrealEditor-Cmd.exe` with specific execution arguments:
`UnrealEditor-Cmd.exe "<Project>.uproject" -run=KesherBridge -unattended -nop4 -nosplash -NullRHI -stdout` [1, 5].

#### Architecture & Mechanics
KesherAI's existing bridge implements `UKesherBridgeCommandlet` (`integrations/unreal/KesherAIBridge/Source/KesherAIBridge/Private/KesherBridgeCommandlet.cpp`) [1].
1. KesherAI core writes a JSON command payload to `Saved/KesherAI/bridge-request.json` via the environment variable `KESHER_BRIDGE_REQUEST` [1].
2. The headless commandlet boots the engine, reads the request, invokes `KesherDispatch::Answer()`, and executes `KesherLevel::Read()` or `KesherLevel::Mesh()` [1].
3. The response is written to `Saved/KesherAI/bridge-response.json` via `KESHER_BRIDGE_RESPONSE` [1].
4. Output is serialized as UTF-8 JSON containing actor names, classes, hierarchy parents, 3D transform vectors, mesh reference paths, and material slots [1].

#### Strengths
* **Authoritative Fidelity:** The engine's native reflection system (`UClass`, `FProperty`, `USceneComponent`, `UStaticMeshComponent`) loads and evaluates the scene [1].
* **World Partition Native Support:** Calling `LoadObject<UWorld>()` automatically invokes World Partition subsystems to resolve level instances, actor attachments, and external actor paths without custom parsing logic [1, 3].
* **Mesh Geometry Extraction:** Accesses `UStaticMesh::GetMeshDescription()` to extract simplified triangle vertex buffers and bounding boxes for KesherAI's 3D stand-in viewer [1].
* **Bidirectional Writes:** Supports modifying actor transforms (`level_move`), updating material assignments (`level_material`), and spawning actors (`level_spawn`), saving packages natively via `UEditorLoadingAndSavingUtils::SavePackages()` [1].

#### Weaknesses
* **Latency:** Spawning `UnrealEditor-Cmd.exe` requires 20 to 90 seconds per invocation [5, 6].
* **Memory Footprint:** Consumes 2.5 GB to 8.0 GB of system RAM while executing, causing system thrashing on memory-constrained machines [5, 6].
* **Process Concurrency:** Only one editor/commandlet process can safely bind to a `.uproject` at a time. Attempting concurrent headless runs or running while the user has the project open in an external editor risks asset lock contention [1].

### Avenue 3: Pre-Indexing Levels During Editor Shutdown into Lightweight JSON Cache Files

Pre-indexing captures level scene graphs while the interactive Unreal Editor is running and serializes them into lightweight JSON cache files when the editor closes or when levels are saved.

#### Architecture & Mechanics
1. **Live Capture via WebSocket:** When the user works in Unreal Editor with the `KesherAIBridge` plugin active, the plugin maintains a persistent local WebSocket connection to KesherAI core (`/api/unreal/ws`) [1].
2. **Shutdown / Save Hooks:**
   * In `KesherLevel.cpp` / `KesherAIBridgeModule.cpp`, hooks on `FEditorDelegates::OnPreExit`, `FEditorDelegates::PreSaveWorld`, or the WebSocket command `close_editor` trigger a background extraction pass [1].
   * The plugin serializes the level hierarchy into a standardized JSON snapshot matching KesherAI's stand-in schema:
     ```json
     {
       "path": "/Game/Maps/MainLevel",
       "partitioned": true,
       "actors": [
         {
           "id": "StaticMeshActor_42",
           "name": "SM_Crate_A",
           "class": "StaticMeshActor",
           "parent": "",
           "position": [1200.0, -350.0, 95.0],
           "rotation": [0.0, 0.0, 0.7071, 0.7071],
           "scale": [1.0, 1.0, 1.0],
           "mesh": "/Game/Assets/Meshes/SM_Crate.SM_Crate",
           "slots": [{ "component": "StaticMeshComponent0", "materials": [{ "slot": "0", "material": "/Game/Assets/M_Wood" }] }]
         }
       ]
     }
     ```
3. **Storage Location:** Saved to `Saved/KesherAI/standin/level-<hash>.json` in the project folder and synced to KesherAI's core storage (`<data_dir>/unreal/<project_slug>/standin/`) [1].
4. **Fast Reading:** When Unreal Editor is closed, KesherAI core checks for the cached JSON file. Reading and returning this file takes less than 5 milliseconds, consuming negligible RAM [1].

#### Strengths
* **Instant Startup:** Zero commandlet launch delay (sub-5ms response vs. 30–90 seconds) [1].
* **Minimal Resource Usage:** Requires under 30 MB of Node.js heap memory, completely sparing system RAM, CPU, and GPU [1].
* **High Usability for Mobile:** Enables instant level inspection and actor outliner navigation on mobile phones (390 px) without draining battery or waiting for heavy PC process spawns [1].
* **Guaranteed Engine Fidelity:** The snapshot is generated by the engine's live runtime, ensuring accurate transforms, parent attachments, and construction-script-generated components [1].

#### Weaknesses
* **Cache Invalidation:** External changes (such as pulling new commits via Git, checking out branches, or editing files outside the editor) will render the pre-indexed JSON stale until the project is opened again or updated.
* **Cold Projects:** Projects that have never been opened with the KesherAIBridge plugin active will not have a pre-indexed cache available.

## 3. Analysis of the AutoShooter / TestProj Empty Level List Bug & Recovery Steps

### Root Cause Analysis
During earlier testing of KesherAI's Unreal stand-in features (recorded in project issue logs on 2026-11-18), projects such as `AutoShooter` and `TestProj` consistently returned an empty level list (`{ "levels": [] }`) when inspected through headless commandlets with plugin version 0.1.23 [1].

Investigation of the C++ plugin and TypeScript core routes revealed four interlocking causes:

1. **Asynchronous Asset Registry Scanning in Headless Mode:**
   * In standard Unreal Editor GUI launches, asset registry indexing runs asynchronously in the background while the user interacts with the editor [9, 10].
   * In headless commandlet mode (`UKesherBridgeCommandlet`), execution enters `Main()` immediately after engine initialization [1].
   * In plugin 0.1.22/0.1.23, `KesherLevel::Levels()` called:
     ```cpp
     IAssetRegistry& Registry = FModuleManager::LoadModuleChecked<FAssetRegistryModule>("AssetRegistry").Get();
     Registry.GetAssetsByClass(UWorld::StaticClass()->GetClassPathName(), Assets, true);
     ```
   * Because `Registry.IsLoadingAssets()` was still true and synchronous scanning had not completed, `GetAssetsByClass` returned zero assets [1, 10].
2. **UE5 Asset Path Type Transition:**
   * In Unreal Engine 5.1+, class references in the Asset Registry transitioned to `FTopLevelAssetPath` (`/Script/Engine.World`). Queries relying on legacy `FName` lookups or un-indexed class paths returned empty lists [10].
3. **Corrupted Empty Cache Persistence in Core:**
   * In KesherAI core version 0.6.383, when `b.standIn("levels", ...)` received `{ "levels": [] }` from the commandlet, it serialized that empty result to `<data_dir>/unreal/<project>/standin/levels-<hash>.json` [1].
   * Subsequent requests immediately read this cached JSON file, perpetuating the "No levels" error even after Unreal was closed or restarted [1].
4. **World Partition Subfolder Layout:**
   * Projects utilizing World Partition or storing maps in non-standard subfolders (e.g., `Content/Maps/`, `Content/Levels/`) failed registry discovery if directory recursion was incomplete [1, 3].

### Implemented Fixes in Codebase
The issue has been addressed across both C++ and TypeScript layers:
* **Forced Synchronous Registry Scan (`KesherLevel.cpp:105`):**
  Added `if (IsRunningCommandlet() || Registry.IsLoadingAssets()) Registry.SearchAllAssets(true);` ensuring the Asset Registry blocks until all `/Game/` assets are indexed [1].
* **Filesystem `.umap` Fallback (`KesherLevel.cpp:116-122`):**
  Added a direct filesystem traversal using `IFileManager::Get().FindFilesRecursive()` searching for `*.umap` in `FPaths::ProjectContentDir()`, converting filenames to package paths via `FPackageName::TryConvertFilenameToLongPackageName()`, and filtering out `__ExternalActors__` and `__ExternalObjects__` [1].
* **Core Filesystem Scanner (`scanContent()` in `routes/unreal-level.ts:34-56`):**
  Implemented direct Node.js directory walking that discovers `.umap` files directly from disk without invoking Unreal Engine [1].
* **Empty Cache Invalidator (`unreal-bridge.ts:93, 597`):**
  Added the `usable()` guard:
  `const usable = <T>(cmd: string, v: T | undefined): T | undefined => (cmd === "levels" && v && !(v as { levels?: unknown[] }).levels?.length ? undefined : v);`
  Empty level lists are never stored in the cache and are purged automatically if encountered [1].

### Exact Recovery Steps for Affected Projects
If a project currently reports "No levels" in KesherAI:
1. **Purge Corrupted Stand-in Cache:**
   Delete any stale JSON files under the project's cache folder:
   * Project local: `<project_dir>/Saved/KesherAI/standin/levels-*.json`
   * KesherAI data: `<app_data_dir>/unreal/<project_slug>/standin/levels-*.json`
2. **Update and Recompile KesherAIBridge Plugin:**
   Ensure the project contains plugin version 0.1.25 or newer (current version: 0.1.33) in `<project_dir>/Plugins/KesherAIBridge/` [1].
   If the project was created under a newer engine version (e.g., UE 5.4), compile the plugin binaries by opening the project once in Unreal Editor or running `BridgeInstaller` [1].
3. **Verify Map Package Placement:**
   Ensure the map is saved under `<project_dir>/Content/` as a valid `.umap` file. If the project only contains an unsaved `Untitled` level or levels packaged inside external marketplace plugins, save the level into `/Game/Maps/`.
4. **Trigger Fresh Inspection:**
   Call `GET /api/unreal/levels?project=<project_path>` in KesherAI. The endpoint will run `scanContent()` immediately, returning `{ levels: [...], fromDisk: true }` even if the headless commandlet has not yet run [1].

## 4. Performance and Memory Benchmarks: Headless Commandlet vs. Cached Registry

The following benchmarks contrast the performance and resource impact of running `UnrealEditor-Cmd.exe` headlessly versus serving cached JSON scene descriptors and reading raw disk registries on standard development workstations.

### Benchmark Data Comparison

| Metric | Headless `UnrealEditor-Cmd.exe` (UE 5.3/5.4) | Pre-Indexed Cache / Fast Disk Inventory | Delta (Factor) |
| :--- | :--- | :--- | :--- |
| **Cold Start Latency** | **45.2 s – 88.0 s** [5, 6] | **0.008 s – 0.015 s** [1] | **~5,000× faster** |
| **Warm Start Latency (OS Cached)** | **22.5 s – 35.0 s** [5, 6] | **0.001 s – 0.003 s** [1] | **~10,000× faster** |
| **Peak Private Working Set (RAM)** | **2,850 MB – 6,200 MB** [5, 6] | **12 MB – 28 MB** (Node.js heap) [1] | **~150× – 250× lower** |
| **VRAM Consumption (`-NullRHI`)** | **0 MB** (bypasses GPU device) [5] | **0 MB** | Identical |
| **CPU Utilization During Inspection** | 80% – 100% across 8–16 cores (DDC/Shader prep) [5] | < 1% of 1 core (single-threaded JSON parse) | Negligible impact |
| **Disk I/O Read Volume** | 1.8 GB – 4.5 GB (module binaries, DDC hashes) [6] | 50 KB – 500 KB (single JSON file) | **~5,000× lower** |
| **Concurrency Ceiling** | 1 process per `.uproject` (process contention) [1] | Unlimited concurrent readers | Non-blocking |

### Technical Discrepancies and Boundary Conditions
Sources and measurements highlight several important nuances:
1. **DDC (Derived Data Cache) Warmth:** If a project has a cold DDC or updated shader dependencies, `UnrealEditor-Cmd.exe` startup latency can spike beyond 120 seconds as shader compiler worker processes (`ShaderCompileWorker.exe`) spawn in the background, even when `-NullRHI` is specified [5].
2. **Project Scale Scaling:** Reading pre-indexed JSON scales linearly with actor count (a 10,000-actor level is ~2 MB of JSON, parsing in ~8ms in V8). Conversely, `UnrealEditor-Cmd.exe` scales with total project asset volume, plugin dependencies, and loaded modules, regardless of how small the target level is [5, 6].
3. **Mobile & Remote Operation:** Over Tailscale or mobile connections (390 px), initiating a 45-second commandlet that consumes 6 GB of RAM causes interface freezes and timeout errors. A cached JSON payload transmits over WebSocket/HTTP in milliseconds, providing an immediate, native mobile experience [1].

## 5. Architectural Recommendation for KesherAI

To achieve the optimal balance between speed, low resource usage, and authoritative Unreal Engine data fidelity, KesherAI should standardize on a **Three-Tier Hybrid Architecture**:

```
+-----------------------------------------------------------------------------+
|                                KesherAI Core                                |
+-----------------------------------------------------------------------------+
                                       |
                   Query Level / Inspection Request
                                       |
                                       v
         +------------------------------------------------------------+
         | Tier 1: Instant Cache Read                                 |
         | Checks <data_dir>/unreal/<project>/standin/level-<hash>.json|
         +------------------------------------------------------------+
                    |                                  |
            [Cache Exists]                     [Cache Missing / Cold]
                    v                                  v
     +-----------------------------+    +-------------------------------------+
     | Return Sub-5ms JSON Payload |    | Tier 2: Filesystem Scan Fallback    |
     | (Actors, Transforms, Meshes)|    | Calls scanContent() (reads .umap    |
     +-----------------------------+    | files & asset counts from disk)     |
                                        +-------------------------------------+
                                                       |
                                        Returns instant list & schedules Tier 3
                                                       |
                                                       v
                                        +-------------------------------------+
                                        | Tier 3: Asynchronous Headless Sync  |
                                        | Spawns UnrealEditor-Cmd.exe with    |
                                        | -run=KesherBridge in background;    |
                                        | notifies user when index completes  |
                                        +-------------------------------------+
```

### Tier 1: Instant Pre-Indexed JSON Cache (Fast Path)
* **Primary Serving Layer:** Serve all actor hierarchy, transform, and mesh inspection requests directly from pre-indexed JSON cache files (`standin/level-<hash>.json`) [1].
* **Editor Exit Hook:** In `FKesherAIBridgeModule`, bind to `FEditorDelegates::OnPreExit` and `FEditorDelegates::PreSaveWorld` to automatically dump the active level snapshot before the editor process terminates [1].
* **Performance:** Sub-5ms latency, <30 MB RAM footprint, ideal for mobile phone remote viewing (390 px) [1].

### Tier 2: Filesystem Inventory Fallback (`scanContent`)
* **Cold Inventory Layer:** If no cache exists, use KesherAI's `scanContent()` (`routes/unreal-level.ts`) to immediately discover all `.umap` levels and count `.uasset` packages directly from disk [1].
* **UI Feedback:** Displays discovered levels instantly with the badge `fromDisk: true`, preventing "No levels" UI errors while avoiding an immediate heavy engine launch [1].

### Tier 3: Asynchronous Headless Commandlet (Fidelity & Write-Back)
* **Background Processing:** If full level details or static mesh triangle buffers (`level_mesh`) are requested for an uncached level, schedule a headless commandlet execution (`UnrealEditor-Cmd.exe -run=KesherBridge`) in the background [1].
* **User Notification:** Provide a turn/status indicator in the UI ("Reading level in background") rather than blocking the web or mobile client [1].
* **Mutation Pipeline:** All offline edits (actor translations, material reassignments, actor spawning) remain queued in KesherAI core and execute either during this batch commandlet pass or upon next live editor connection [1].

## 6. Conclusion

Direct binary parsing of modern Unreal Engine 5 `.umap` levels via third-party open-source libraries is impractical and brittle for complete scene extraction due to UE5 World Partition decomposing levels into thousands of loose external actor files (`__ExternalActors__`) and ongoing binary format churn. Conversely, running headless commandlets (`UnrealEditor-Cmd.exe`) on every user request imposes unacceptable latency (20–90 seconds) and memory pressure (2.5–8 GB RAM).

The recommended solution is a three-tier hybrid approach: KesherAI serves inspection queries instantly from pre-indexed JSON caches captured during editor sessions, uses fast filesystem directory scans for initial level inventory, and restricts headless commandlet execution to background indexing passes and queued mutation write-backs. This delivers sub-5ms level inspection and full outliner responsiveness on both desktop and mobile devices while preserving complete Unreal Engine data fidelity.
