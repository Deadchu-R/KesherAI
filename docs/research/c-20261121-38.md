### 2. Composer, Attachments, and Steerability

#### Modern Input Paradigms
A main chat composer must handle multi-modal inputs seamlessly:
- **Attachment Pipeline:** Users frequently drop images, log files, PDFs, audio snippets, or code files into the chat. The composer must instantly create a thumbnail chip with MIME-type detection, token impact estimation, and a quick-remove button. Images destined for local vision-language models (e.g., Qwen3.5-VL) require client-side resizing (preserving aspect ratio up to 1568px long-edge) to prevent VRAM spikes.
- **Mid-Turn Queueing and Steering:** When an agent is executing long reasoning chains or running terminal tools, disabling the send button frustrates users. Following the benchmark established by Cursor and Jan [3, 4]:
  1. *Default Queue Mode:* Any message submitted while the engine is busy is placed in an editable `QueueChip` beneath the active turn.
  2. *Steer Mode (`Alt+Enter`):* Injects the user prompt directly into the agent session at the next tool boundary (`injectSteer`), bypassing the full queue.
  3. *Two-Stage Stop:* The first tap on "Stop" halts pending queued messages; a second tap terminates the active generation or tool process.

### 3. Streaming, Progress Feedback, and Tool Call Visibility

#### Real-Time Telemetry and Token Smoothing
Raw HTTP chunk streaming causes visual jitter when token chunks arrive unevenly. Leading desktop clients implement client-side requestAnimationFrame smoothing buffers:
- **Token Smoothing Buffer:** Incoming Server-Sent Events (SSE) chunks are placed into a micro-queue and consumed at a steady cadence (e.g., 20–60 tokens/second for local models), eliminating text "jumping".
- **Turn Telemetry:** Users require immediate feedback on model state. Above the generated output, a dedicated status line displays:
  - *Phase Indicators:* `טוען מודל... (כ-12 שניות)` (Loading model) -> `חושב... (4.2 שניות)` (Reasoning) -> `מריץ כלי: web_search` (Executing tool) -> `מזרים תשובה` (Streaming response).
  - *Performance Metrics:* Tokens generated, elapsed duration, and effective generation speed (`24.5 tok/s`).

#### Transparent Tool Call Formatting
Instead of dumping raw JSON payloads into the conversation, tool invocations must render as compact, expandable cards (`Activity` items):
- **Header Line:** Displays an icon representing the tool domain (Search, Terminal, Game Engine, Audio, File System), the localized tool title, execution status (Spinner, Success Checkmark, or Error Warning), and elapsed time.
- **Preview Summary:** A human-readable single-line summary (e.g., `חיפוש בקוד: "HandlePlayerMovement"` or `יצירת תמונה: "Cyberpunk street, 4k"`).
- **Expandable Drawer:** Clicking reveals formatted parameters and returned outputs with syntax highlighting, avoiding unstructured JSON blocks.

### 4. Approvals and Security Boundaries

Autonomous agent execution requires strict human-in-the-loop gating for state-changing operations:
- **Risk Categorization:**
  - *Tier 1 (Read-Only / Safe):* File reading, workspace grepping, local web searches, inspector reads. Executed automatically without blocking.
  - *Tier 2 (Workspace Modifications):* File edits, new asset creation, scene node property updates. Governed by session preferences (Ask Every Time vs. Auto-Approve Inside Workspace).
  - *Tier 3 (External / Dangerous):* Shell command execution, file deletions, remote network calls, system configuration changes. Always requires explicit approval.
- **Approval Card Design:**
  - Identifies which agent or sub-agent requested the action (e.g., `סוכן בנייה` vs. `סוכן ראשי`).
  - Presents a clear visual diff for file edits or the exact command line with its working directory.
  - One-click actions: **Approve Once**, **Always Allow in This Session**, **Reject with Feedback** (opens inline input to tell the agent why it was denied).

### 6. Model Picking, Auto-Routing, and Speed Optimizations

#### Two-Stage Auto-Routing Pipeline
KesherAI's "✨ Auto" model selector must prevent unnecessary heavy model swaps while ensuring task-appropriate capabilities:
1. **Deterministic Rule Filter (< 1 ms):**
   - Pure image prompts (`צייר לי...`, `generate image`) -> Route to ComfyUI / image pipeline.
   - Pure audio prompts (`צור שיר...`, `make a beat`) -> Route to Audio / music pipeline.
   - Long Hebrew creative writing / poetry -> Route to Hebrew-specialist LLM (DictaLM).
2. **Tiny Router Classifier (< 50 ms):**
   - For general prompts, a small 2B parameter model (e.g., Qwen3.5 2B router running beside the main model) evaluates intent and required tools.
   - Emits a concise routing token: `CODE`, `RESEARCH`, `FAST_CHAT`, `VISION`.
   - Prevents model thrashing by enforcing a 3-turn stability hysteresis (retaining the loaded model unless a strong capability shift occurs).

#### Local LLM Speed Optimizations (llama.cpp)
To match cloud responsiveness locally:
- **Prefix / Prompt Caching:** Modern `llama.cpp` retains the KV cache of static prompt prefixes (system instructions, tool declarations, project guidelines) across turns [11]. When the conversation prefix remains unmodified, Time to First Token (TTFT) drops from seconds to under 80 milliseconds.
- **Speculative Decoding / Prompt Lookup:**
  - *N-Gram Prompt Lookup Decoding (`ngram-simple` / `ngram-map-k`):* Employs context string pattern matching to speculate upcoming tokens without requiring an auxiliary draft model [12]. Yields a **1.4x to 2.0x decoding speedup** on code, repetitive text, and formatted outputs with zero added VRAM overhead.
  - *Dual-Model Speculative Decoding:* Pairing a 27B/32B base model with an aligned 1.5B draft model yields substantial throughput gains when memory bandwidth is the primary bottleneck [11].
- **KV Cache Quantization:** Enabling FP8 (`f8_e4m3`) or Q8_0 KV cache reduces attention memory consumption by up to 50%, allowing 32k+ token contexts to fit comfortably into consumer VRAM (e.g., RTX 3090/4090) without context spilling [11].

### 7. Bilingual Hebrew-English (RTL/LTR) BiDi Typography

#### Unicode Bidirectional Challenges in LLM Interfaces
Mixed Hebrew-English conversations represent an extreme stress test for web rendering. Common failures include:
- English words or function names reversing sentence order.
- Punctuation (periods, closing parentheses) jumping from the left edge of a Hebrew sentence to the right edge.
- Code blocks inheriting RTL paragraph direction, scrambling indentation and Latin syntax.

#### Technical Solutions for Rock-Solid BiDi Rendering
1. **Dynamic Message Directionality (`dir="auto"`):**
   - Every message container, markdown paragraph (`<p>`), and list item (`<li>`) must be tagged with `dir="auto"`. This instructs the browser's Unicode Bidirectional Algorithm (UBA) to evaluate the first strong directional character and align the paragraph accordingly (`start` aligns right for Hebrew, left for English) [9, 10].
2. **CSS Logical Properties:**
   - Eliminate all physical direction rules (`margin-left`, `padding-right`, `left`, `right`). Use logical properties exclusively: `margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `text-align: start` [9].
3. **Strict LTR Isolation for Code and Technical Tokens:**
   - Preformatted code blocks (`<pre><code>`), inline code tokens (`` `foo_bar()` ``), file paths, and terminal outputs must be explicitly forced to LTR:
     ```css
     pre, code, .code-token, .file-path {
       direction: ltr !important;
       text-align: left !important;
       unicode-bidi: isolate;
     }
     ```
   - Wrapping inline technical terms and dynamic tool variables in `<bdi>` (Bidirectional Isolation) elements prevents Latin identifiers from corrupting the surrounding Hebrew text stream [9].
4. **Weak Punctuation Boundary Safeguards:**
   - When an English token terminates a Hebrew sentence, trailing periods and exclamation marks frequently snap to the wrong side. Inserting a zero-width Right-to-Left Mark (`&rlm;` / `\u200F`) immediately after trailing punctuation guarantees correct visual anchoring.

### 4. Blueprint and Visual Scripting Generation

#### Unreal Blueprint Text Format vs. Native Reflection
When developers copy Blueprint nodes in Unreal, the clipboard receives a proprietary textual serialization format [23]:
```text
Begin Object Class=K2Node_CallFunction Name="K2Node_CallFunction_0"
   FunctionReference=(MemberParent=Class'/Script/Engine.GameplayStatics',MemberName="SpawnEmitterAtLocation")
   NodePosX=1200
   NodePosY=450
   CustomProperties Pin (PinId=...,PinName="execute",Direction="EGPD_Input")
   CustomProperties Pin (PinId=...,PinName="then",Direction="EGPD_Output")
End Object
```
- **The Clipboard Problem:** While raw text can theoretically be pasted into an active graph, LLMs frequently produce subtle syntax deviations, mismatched pin GUIDs, or outdated function names that cause Unreal Editor to crash or reject the paste [23].
- **KesherAI's Solution:**
  1. *Text Translation Layer (`blueprintToCode`):* KesherAI converts complex Blueprint node spaghetti into readable, structured pseudo-code or TypeScript equivalents so language models can reason about execution paths without token bloat [21].
  2. *Bridge Injection API:* When creating or modifying nodes, the bridge executes native Unreal C++ reflection (`UK2Node`, `UEdGraphSchema_K2`), validating pin types, function signatures, and execution flow before establishing connections in the graph [21].

#### Unity Visual Scripting (Script Graphs & State Graphs)
- Unity stores Script Graphs as JSON/YAML assets containing serializable unit nodes, value ports, and flow connections.
- KesherAI provides bidirectional compilation: converting C# MonoBehaviour logic into Unity Script Graphs (`.asset`), allowing non-programming artists to inspect AI-generated gameplay mechanics visually.

### 5. C# and C++ Code Synthesis with Engine Metaprogramming

Writing engine-compliant code is drastically more complex than writing standard C# or C++:
- **Unreal C++ Constraints:**
  - Must strictly honor Unreal Header Tool (UHT) macros: `UCLASS()`, `USTRUCT()`, `UPROPERTY(EditAnywhere, BlueprintReadWrite, Category="Gameplay")`, and `GENERATED_BODY()`.
  - Garbage collection compliance: using `TObjectPtr<T>` for raw object references and `TWeakObjectPtr<T>` for non-owning references to avoid memory leaks.
  - Module linking: verifying that required modules (e.g., `UMG`, `EnhancedInput`, `Niagara`) are correctly declared in the project's `<Project>.Build.cs` file.
  - *Automated Error Resolution:* When compilation fails, `parseCodeErrors.ts` captures MSVC/Clang output, isolates specific missing includes or UHT macro errors, and prompts the coding agent with precise compiler diagnostics [21, 24].
- **Unity C# Optimization:**
  - Enforces MonoBehaviour execution hierarchy (avoiding expensive `GetComponent` or `FindObjectOfType` calls inside `Update()`).
  - Implements object pooling patterns for high-frequency spawns (bullets, particles).
  - Integrates Unity's Job System and Burst Compiler (`[BurstCompile]`) for performance-critical mathematics.

### 2. Local Engine Architecture, VRAM Budgeting, and Resource Lifecycle

Running multiple high-capacity models (large language models, diffusion models, speech engines) on consumer hardware requires precise resource scheduling:

```
+---------------------------------------------------------------------------------+
|                                GPU Guard & VRAM Arbiter                         |
|  - Reserves 1.5 GB Headroom for Windows DWM & Game Engines                      |
|  - Fits Models via llama-fit-params: Splits layers (VRAM) & experts (RAM)       |
+---------------------------------------------------------------------------------+
          |                                  |                              |
          v                                  v                              v
+-----------------------+          +--------------------+        +--------------------+
|  llama.cpp Instance   |          | Managed ComfyUI    |        | Python Sidecars    |
| - Chat / Code Model   |          | - Flux / SDXL      |        | - Kokoro 82M TTS   |
| - Idle Timeout: 10m   |          | - Wan 2.2 Video    |        | - whisper.cpp      |
| - Host Prompt Caching |          | - Idle Timeout: 5m |        | - Idle Timeout: 5m |
+-----------------------+          +--------------------+        +--------------------+
```

#### Load-on-Demand and Idle Garbage Collection
- **The Idle Lifecycle:** Rather than keeping all engines resident in VRAM, KesherAI enforces strict idle unload timeouts configured in `Settings > Computer`:
  - *Main Chat Model (llama.cpp):* Unloads after 10 minutes of inactivity.
  - *Text Embeddings (bge / nomic):* Unloads after 5 minutes.
  - *ComfyUI & Diffusion Checkpoints:* Unloads after 5 minutes.
  - *Speech Translator (TranslateGemma):* Unloads after 5 minutes [7].
- **GPU Guard & Margin Allocation:**
  - Game developers regularly run Unreal Engine, Unity, or Blender alongside their AI assistant.
  - GPU Guard monitors active VRAM usage via `nvml` / Direct3D APIs. It dynamically reserves an editable safety margin (default 1.5 GB) so that background engine viewport redraws never trigger out-of-memory driver crashes [7].
- **Model Fitting (`llama-fit-params`):**
  - Before launching a large model, KesherAI calculates optimal layer distribution: allocating maximal attention layers to GPU VRAM and spilling remaining Mixture-of-Experts (MoE) weights or feed-forward blocks into system RAM.
- **Near-Frontier Local MoE Execution (DeepSeek V4-Flash):**
  - Target architecture: Running DeepSeek V4-Flash (284B MoE, 13B active) locally on a dual-GPU setup (e.g., dual RTX 3090 24GB + 128GB RAM).
  - Layers split across both GPUs via peer-to-peer NVLink / PCIe data transfers, with expert tensors paged dynamically from fast host memory [7].
- **Hebrew-to-English Fast Translation Pipeline:**
  - Modern image and video diffusion models (Flux, Wan 2.2) fail completely when prompted in Hebrew.
  - KesherAI routes Hebrew media requests through an ultra-fast on-demand translator (TranslateGemma 4B or local Gemini Flash key) [7].
  - The refined English prompt drives the diffusion workflow, while the localized Hebrew translation is rendered under the result card (`Prompt used: ...`).
