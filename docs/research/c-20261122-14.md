# Node-Based Material and Shader Editor in KesherAI for Unity, Unreal, and Web

## Summary

This research establishes an end-to-end architectural blueprint for integrating a node-based material and shader editor into KesherAI's existing Three.js 3D viewport (`plugins/model-editor`), delivering unified cross-engine authoring for Unity (Shader Graph) and Unreal Engine 5 (Material Editor / Substrate), as well as WebGL/WebGPU live preview.

The primary finding is that rather than adopting heavyweight external web graph libraries (React Flow, Rete.js, LiteGraph) or binding directly to engine-locked formats, KesherAI should extend its existing native canvas engine (`BlueprintCanvas.tsx`) and document model (`VsDoc` / `unity-vs.ts` / `unreal-bp.ts`) into a common material intermediate representation (`MaterialDoc`). This intermediate representation aligns with the Academy Software Foundation (ASWF) **OpenPBR Surface** and **MaterialX** standard node vocabulary. 

For runtime preview, KesherAI maps `MaterialDoc` in-browser to modern Three.js (0.181+) **Three Shading Language (TSL)** and `MeshPhysicalNodeMaterial`, achieving instant parameter tuning and 15–30 ms DAG hot-reloads. For export when game engines are closed, KesherAI generates deterministic Newline-Delimited JSON (NDJSON) `.shadergraph` assets for Unity URP/HDRP, and invokes Unreal Engine's headless `UKesherBridgeCommandlet` to execute `UMaterialEditingLibrary` C++ routines, producing compiled `.uasset` materials with zero manual artist intervention.

## 1. Engine Shader Systems and Graph Serialization

### 1.1 Unity Shader Graph

#### Node Taxonomy and Capabilities
Unity Shader Graph (introduced with the Scriptable Render Pipeline in Unity 2018 and standard in Unity 2021 LTS through Unity 6) organizes nodes into distinct functional categories:
* **Input Nodes:** Properties exposed to the Material Inspector (Float, Vector2/3/4, Color with HDR support, Texture2D, Cubemap, Boolean, Matrix), constant nodes, and procedural coordinate inputs (UV, Vertex Position, Object/World/View Normal, Tangent, Bitangent, Screen Position, View Direction, Camera, Time, Face Sign).
* **Math & Logic Nodes:** Basic arithmetic (Add, Subtract, Multiply, Divide, Power, Square Root), trigonometry (Sin, Cos, Tan, Asin, Acos, Atan, Atan2), vector operations (Dot, Cross, Normalize, Length, Distance, Reflect, Transform), interpolation/clamping (Lerp, Clamp, Remap, Smoothstep, Saturate), and conditional comparison (Branch, Comparison, Is NaN, All, Any).
* **Artistic & Processing Nodes:** Color adjustments (Contrast, Hue, Saturation, Invert Colors, Replace Color), blend modes (Burn, Darken, Difference, Dodge, Multiply, Overlay, Screen), channel manipulation (Combine, Split, Swizzle), and normal map processing (Normal From Height, Normal Blend, Normal Unpack).
* **Procedural & Patterns:** Checkerboard, Noise (Simple/Value, Gradient/Perlin, Voronoi), Shapes (Rectangle, Rounded Rectangle, Polygon, Ellipse).
* **Block Nodes (Master Stack):** The modern Shader Graph (Unity 2020.2+) replaces monolithic Master Nodes (PBR Master, Unlit Master) with a modular **Master Stack** split into **Vertex Context** (`VertexDescription.Position`, `Normal`, `Tangent`) and **Fragment Context** (`SurfaceDescription.BaseColor`, `NormalTS`, `Metallic`, `Smoothness`, `Emission`, `Occlusion`, `Alpha`, `AlphaClipThreshold`).

#### File Format: Newline-Delimited JSON (NDJSON)
Although saved with the `.shadergraph` extension, the asset is **not a single JSON document tree** [1, 2]. Attempting to parse it with a single standard JSON parser (`JSON.parse()`) fails because the file consists of multiple independent, newline-delimited JSON objects [2].

Each line in the `.shadergraph` file defines an internal entity serialized with:
* `"m_SGVersion"`: Schema revision number.
* `"m_Type"`: Fully qualified C# type (e.g., `UnityEditor.ShaderGraph.GraphData`, `UnityEditor.ShaderGraph.MultiplyNode`, `UnityEditor.ShaderGraph.BlockNode`).
* `"m_ObjectId"`: A 32-character hexadecimal GUID uniquely identifying the object.

A root entity of type `UnityEditor.ShaderGraph.GraphData` links the graph together using GUID arrays:
```json
{
  "m_SGVersion": 3,
  "m_Type": "UnityEditor.ShaderGraph.GraphData",
  "m_ObjectId": "6be04d91c14b474dba284633243b86be",
  "m_Properties": [{ "m_Id": "1a28c0dff07441c5a3acddf1c20e9d10" }],
  "m_Nodes": [
    { "m_Id": "b918a7a14a9a4ef2868b222e1678873f" },
    { "m_Id": "31d96e355b424bedbe58486e90f0ae9e" }
  ],
  "m_Edges": [
    {
      "m_OutputSlot": { "m_Node": { "m_Id": "b918a7a14a9a4ef2868b222e1678873f" }, "m_SlotId": 0 },
      "m_InputSlot": { "m_Node": { "m_Id": "31d96e355b424bedbe58486e90f0ae9e" }, "m_SlotId": 1 }
    }
  ],
  "m_VertexContext": { "m_Position": { "x": 0.0, "y": 0.0 }, "m_Blocks": [...] },
  "m_FragmentContext": { "m_Position": { "x": 0.0, "y": 200.0 }, "m_Blocks": [...] },
  "m_ActiveTargets": [{ "m_Id": "c9284fa0348a43fca10291040854ad58" }]
}
```

#### Targets and SubTargets (URP vs HDRP vs BiRP)
Pipeline configuration is stored in target objects referenced by `m_ActiveTargets`:
* **Universal Render Pipeline (URP):** Uses `UnityEditor.Rendering.Universal.ShaderGraph.UniversalTarget` combined with `UniversalLitSubTarget` or `UniversalUnlitSubTarget`. Settings include `surfaceType` (0 = Opaque, 1 = Transparent), `blendMode` (0 = Alpha, 1 = Premultiply, 2 = Additive, 3 = Multiply), `alphaClip`, and workflow model (Metallic vs Specular).
* **High Definition Render Pipeline (HDRP):** Uses `HDTarget` combined with `HDLitSubTarget`. Exposes advanced blocks such as `CoatMask`, `CoatSmoothness`, `DiffusionProfile`, `SubsurfaceMask`, and `Thickness`.
* **Built-in Render Pipeline:** Uses `BuiltInTarget`.

#### Sub Graphs (`.shadersubgraph`)
A Sub Graph is a reusable module saved with the `.shadersubgraph` extension [3]. 
* **Blackboard Inputs:** Every property declared on the Sub Graph's Blackboard translates into an input port on the resulting Sub Graph Node when instantiated in a parent graph.
* **Output Node:** Instead of a Master Stack, a Sub Graph terminates in an `UnityEditor.ShaderGraph.SubGraphOutputNode` containing user-configured output slots (e.g., Vector3 Normal, Float Mask) [3].
* Sub Graphs allow nesting complex math (such as triplanar projection, multi-octave noise, or parallax occlusion) into tidy reusable units.

### 1.2 Unreal Engine Material Editor

#### Node Taxonomy and Expression Architecture
Unreal Engine's Material Editor operates as an Abstract Syntax Tree (AST) compiler generating Unreal Shading Language (USF) and translating down to HLSL/DirectX or SPIR-V/Vulkan. All nodes derive from the base C++ class `UMaterialExpression`:
* **Parameters:** `UMaterialExpressionScalarParameter`, `UMaterialExpressionVectorParameter`, `UMaterialExpressionTextureSampleParameter2D`, `UMaterialExpressionStaticBoolParameter`.
* **Math & Utilities:** `UMaterialExpressionAdd`, `Multiply`, `Divide`, `Subtract`, `LinearInterpolate` (Lerp), `Clamp`, `Power`, `DotProduct`, `CrossProduct`, `Normalize`, `ComponentMask`, `AppendVector`, `Panner`, `Rotator`.
* **Textures & Coordinates:** `UMaterialExpressionTextureSample`, `UMaterialExpressionTextureCoordinate` (TexCoord), `UMaterialExpressionVertexNormalWS`, `UMaterialExpressionCameraVectorWS`, `UMaterialExpressionFresnel`.
* **Substrate (UE 5.8+):** Replaces legacy monolithic GBuffer shading models with modular BSDF nodes: `Substrate Slab BSDF`, `Substrate Volumetric Fog Cloud BSDF`, `Substrate Eye BSDF`, composed via `Substrate Horizontal Blend` and `Substrate Vertical Layer`.

#### Material Functions and Material Instances
* **Material Functions (`UMaterialFunction`):** Reusable expression graphs encapsulating node sub-networks. Inputs are created via `UMaterialExpressionFunctionInput` and outputs via `UMaterialExpressionFunctionOutput`. In consumer materials, these are referenced by `UMaterialExpressionMaterialFunctionCall`.
* **Material Instance Constant (`UMaterialInstanceConstant`):** A child asset deriving from a parent `UMaterial`. It avoids full shader recompilation by providing lightweight uniform parameter overrides (`ScalarParameterValues`, `VectorParameterValues`, `TextureParameterValues`) [4, 5].

#### Programmatic Material Creation via Python and C++
Unreal Engine provides `UMaterialEditingLibrary` (part of the `EditorScriptingUtilities` engine module) [4]. Both Python and C++ can instantiate, wire, and compile materials programmatically [4, 5]:

```python
import unreal

asset_tools = unreal.AssetToolsHelpers.get_asset_tools()
mat = asset_tools.create_asset("M_KesherPBR", "/Game/Materials", unreal.Material, unreal.MaterialFactoryNew())
lib = unreal.MaterialEditingLibrary

# 1. Create expression nodes
base_color = lib.create_material_expression(mat, unreal.MaterialExpressionVectorParameter, -400, 0)
base_color.set_editor_property("parameter_name", "BaseColor")
base_color.set_editor_property("default_value", unreal.LinearColor(0.8, 0.2, 0.1, 1.0))

roughness = lib.create_material_expression(mat, unreal.MaterialExpressionScalarParameter, -400, 200)
roughness.set_editor_property("parameter_name", "Roughness")
roughness.set_editor_property("default_value", 0.45)

# 2. Connect to material root properties
lib.connect_material_property(base_color, "", unreal.MaterialProperty.MP_BASE_COLOR)
lib.connect_material_property(roughness, "", unreal.MaterialProperty.MP_ROUGHNESS)

# 3. Recompile material shaders
lib.recompile_material(mat)
unreal.EditorAssetLibrary.save_asset(mat.get_path_name())
```

In native C++, the identical operations are executed directly against `UMaterial` and `UMaterialEditorOnlyData` [5]:
```cpp
UMaterial* Material = NewObject<UMaterial>(Package, *AssetName, RF_Public | RF_Standalone);
UMaterialEditorOnlyData* EdData = Material->GetEditorOnlyData();

UMaterialExpressionVectorParameter* ColorNode = NewObject<UMaterialExpressionVectorParameter>(Material);
ColorNode->ParameterName = TEXT("BaseColor");
ColorNode->DefaultValue = FLinearColor(0.8f, 0.2f, 0.1f, 1.0f);
ColorNode->MaterialExpressionEditorX = -400;
ColorNode->MaterialExpressionEditorY = 0;
Material->GetExpressions().Add(ColorNode);

EdData->BaseColor.Connect(0, ColorNode);
Material->PreEditChange(nullptr);
Material->PostEditChange();
FGlobalComponentRecreateRenderStateContext Recreate;
```

### 1.3 Blender Shader Nodes

Blender's shading pipeline is centered on `ShaderNodeTree` evaluated by Cycles (path tracer) and EEVEE-Next (real-time rasterizer/raytracer).
* **The Principled BSDF (`ShaderNodeBsdfPrincipled`):** In Blender 4.0+, the Principled BSDF was overhauled into a layered energy-conserving standard aligned with OpenPBR:
  * **Base:** Color, Metallic, Roughness, IOR, Alpha, Normal.
  * **Subsurface:** Weight, Radius, Scale, IOR, Anisotropy.
  * **Specular:** Specular IOR Level, Tint, Anisotropic, Anisotropic Rotation, Tangent.
  * **Transmission:** Weight.
  * **Coat:** Weight, Roughness, IOR, Tint, Normal.
  * **Sheen:** Weight, Roughness, Tint.
  * **Emission:** Color, Strength.
* **Socket Types:** Sockets are strongly typed: `NodeSocketFloat` (gray), `NodeSocketVector` (dark blue), `NodeSocketColor` (yellow), and `NodeSocketShader` (green).
* **Math & Utilities:** `ShaderNodeMath` (Float operations), `ShaderNodeVectorMath` (Vector operations), `ShaderNodeMix` (unified node for Float, Vector, and Color mixing), and `ShaderNodeValToRGB` (ColorRamp).

### 1.4 Godot 4 Visual Shaders

Godot 4.x represents visual shaders via the `VisualShader` resource saved as human-readable `.tres` text [6, 7].
* **Resource Structure:** The file consists of `[sub_resource]` blocks for each node (`VisualShaderNodeColorConstant`, `VisualShaderNodeFloatOp`, `VisualShaderNodeTexture`, `VisualShaderNodeInput`) followed by a master `[resource]` block [6].
* **Connection Syntax:** Nodes are wired within the `[resource]` block using a flat `PackedInt32Array` grouped by shader stage (`vertex`, `fragment`, `light`) [6, 7]:
  ```gdscript
  nodes/fragment/connections = PackedInt32Array(2, 0, 0, 0, 3, 0, 2, 0)
  ```
  This array packs quadruplets: `(from_node_id, from_port, to_node_id, to_port)` [6].
* **Node ID 0:** Node `0` is always implicitly the master output block of the respective shader stage (exposing `ALBEDO`, `ALPHA`, `METALLIC`, `ROUGHNESS`, `EMISSION`, `NORMAL_MAP`, `CLEARCOAT`).

## 2. Universal Standards and Three.js Runtime

### 2.1 MaterialX and OpenPBR Surface

#### The ASWF OpenPBR Specification
MaterialX is an open standard created by Lucasfilm and governed by the Academy Software Foundation (ASWF) [8, 9]. To solve the proliferation of divergent PBR models across software packages (Autodesk Standard Surface, Adobe Standard Material, Disney BRDF), Adobe and Autodesk partnered under ASWF to release **OpenPBR Surface** [8, 10]. OpenPBR defines an open, physically verified specification covering:
1. **Base:** Dielectric substrate with diffuse/metal reflection.
2. **Specular:** Rough dielectric/conductor reflection with generalized Fresnel.
3. **Transmission:** Volumetric absorption and refraction.
4. **Subsurface:** BSSRDF multi-layer scattering.
5. **Coat:** Independent clearcoat dielectric layer with custom IOR and roughness.
6. **Fuzz:** Microfiber sheen model for cloth/peach-fuzz.
7. **Emission:** Physical emissive radiance.

#### XML (`.mtlx`) vs JSON Interchange
The canonical MaterialX file format is XML (`.mtlx`) [9]:
```xml
<?xml version="1.0"?>
<materialx version="1.38">
  <nodegraph name="NG_Wood">
    <image name="tex_color" type="color3">
      <input name="file" type="filename" value="wood_base.png"/>
    </image>
    <output name="out_color" type="color3" nodename="tex_color"/>
  </nodegraph>
  <open_pbr_surface name="M_Wood" type="surfaceshader">
    <input name="base_color" type="color3" nodegraph="NG_Wood" output="out_color"/>
    <input name="specular_roughness" type="float" value="0.35"/>
  </open_pbr_surface>
</materialx>
```
To enable native Web and API transmission, community standards (such as `materialxjson` [11] and `@materialxjs/json` [12]) provide a 1:1 bidirectional JSON representation (`application/mtlx+json`), preserving coordinates (`xpos`, `ypos`), socket types, and sub-graph namespaces.

#### DCC and Engine Adoption
* **Unreal Engine:** Natively imports `.mtlx` documents and USD stages containing MaterialX networks [9]. In UE 5.5–5.8 with Substrate enabled, MaterialX graphs map into Substrate nodes with high fidelity.
* **Unity:** Unity HDRP features native MaterialX package integrations and USD importers that convert MaterialX networks to Unity Shader Graphs.
* **Three.js:** Ships with `MaterialXLoader` in `three/addons/loaders/MaterialXLoader.js`, which parses `.mtlx` XML and maps the graph into Three.js TSL nodes [13, 14].

### 2.2 Three.js TSL and NodeMaterial

Three.js (0.181+) introduces **Three Shading Language (TSL)** and a unified **NodeMaterial** pipeline [14, 15]. TSL replaces legacy string-concatenation GLSL (`ShaderMaterial` / `onBeforeCompile`) with a type-safe JavaScript AST that compiles dynamically to **WGSL** for WebGPU and **GLSL 3.00 ES** for WebGL 2 [14, 15, 16].

#### Core Node Materials and Property Sockets
* **`MeshPhysicalNodeMaterial` / `MeshStandardNodeMaterial`:** Exposes dynamic node properties [16]:
  * `material.colorNode`: Base color RGB / RGBA node.
  * `material.metalnessNode`: Scalar float node.
  * `material.roughnessNode`: Scalar float node.
  * `material.normalNode`: Tangent-space normal vector node.
  * `material.emissiveNode`: Emissive color RGB node.
  * `material.clearcoatNode` & `material.clearcoatRoughnessNode`: Clearcoat layers.
  * `material.transmissionNode`: Refractive transmission float.
  * `material.positionNode`: Vertex position offset node (runs in vertex stage).

#### Compositional Syntax
TSL nodes support method chaining and operator overloading [14, 16]:
```javascript
import { uniform, texture, uv, sin, timerLocal, mix, vec3 } from 'three/tsl';

// Dynamic TSL graph
const time = timerLocal();
const animatedUV = uv().add(vec3(time.mul(0.1), 0, 0));
const baseMap = texture(colorTexture, animatedUV);
const tint = uniform(new THREE.Color(0.2, 0.6, 1.0));
const finalColor = baseMap.rgb.mul(tint);

material.colorNode = finalColor;
material.roughnessNode = sin(time).mul(0.2).add(0.5);
```

#### Live Evaluation and Hot-Reload Performance
* **Uniform Updates:** When a user tweaks a slider (e.g., color, roughness scalar, tiling scale), updating the `uniform.value` modifies the GPU buffer directly. Rendering updates occur at 60–120 fps with **0 ms recompilation overhead**.
* **Topology Changes:** When wires are reconnected or nodes are added/deleted, re-assigning node sockets and triggering `material.needsUpdate = true` causes the TSL compiler to reconstruct the shader DAG and compile a new GPU pipeline. In modern Chromium/WebKit browsers, this takes **12 to 35 milliseconds**, eliminating the 1–3 second freezes historically associated with Unity or Unreal shader compilation.

## 4. AI Helpers: Generative Material Graphs and PBR Textures

### 4.1 Text-to-Material Graph Generation

Generative AI material creation operates at two tiers:
1. **Direct HLSL/Shader Code Generation:** Asking an LLM to generate raw HLSL or GLSL code is straightforward, but produces black-box code that artists cannot interactively tune or map across engines [20].
2. **Abstract Syntax Tree (AST) / Tool-Calling Generation:** The optimal method prompts the LLM to output structured graph mutations using KesherAI's operation vocabulary (`add`, `connect`, `set_pin`). 

#### Example LLM Tool Schema (`material_edit_graph`)
```json
{
  "name": "material_edit_graph",
  "description": "Mutate the material graph using structured node operations.",
  "parameters": {
    "type": "object",
    "properties": {
      "path": { "type": "string", "description": "Material asset path." },
      "operations": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": {
            "op": { "type": "string", "enum": ["add", "connect", "set_pin", "delete", "comment"] },
            "type": { "type": "string" },
            "node": { "type": "string" },
            "from": { "type": "string" },
            "fromPin": { "type": "string" },
            "to": { "type": "string" },
            "toPin": { "type": "string" },
            "value": { "type": "string" }
          },
          "required": ["op"]
        }
      }
    },
    "required": ["path", "operations"]
  }
}
```

When a user prompts: *"Create a sci-fi rusted iron with peeling orange paint"*, the LLM emits:
* `TextureSample` (Base Color), `TextureSample` (Rust Albedo).
* `PerlinNoise` with high frequency + `Contrast` node to form a peeling mask.
* `Lerp` node blending Rust Albedo into Paint Albedo.
* `Lerp` node driving Roughness (paint = 0.3, rust = 0.85).
* `Lerp` node driving Metallic (paint = 0.0, rust = 0.9).
* Connections plugged into the Master PBR output block.

### 4.2 Image-to-PBR Texture Extraction

Converting a single RGB photo or 2D concept image into game-ready PBR maps involves four automated neural and algorithmic pipeline stages [21, 22]:

```
[ Input Image (2D Photo/Concept) ]
               │
               ▼
┌─────────────────────────────────┐
│ Stage 1: De-Lighting (Shadow/   │  Stripping baked-in highlights & directional
│ Highlight Removal)              │  lighting using intrinsic decomposition models.
└─────────────────────────────────┘
               │
               ├──────────────────────────────────────────────┐
               ▼                                              ▼
┌─────────────────────────────────┐            ┌─────────────────────────────────┐
│ Stage 2: Normal & Height        │            │ Stage 3: Roughness & Metallic   │
│ Estimation (DeepBump / Marigold)│            │ Decomposition                   │
│ Tangent normal vector + height  │            │ Isolating micro-gloss & specular│
│ displacement extraction.        │            │ reflections via color/contrast. │
└─────────────────────────────────┘            └─────────────────────────────────┘
               │                                              │
               └──────────────────────┬───────────────────────┘
                                      │
                                      ▼
                       ┌─────────────────────────────────┐
                       │ Stage 4: AO & Channel Packing   │
                       │ Ambient occlusion from height;  │
                       │ ORM channel packing (UE/Unity). │
                       └─────────────────────────────────┘
```

1. **De-Lighting (Shadow Removal):** Photographs have baked-in directional sunlight and shadows. De-lighting models (such as Marigold intrinsic lighting decomposition or diffusion inpainters) remove directional luminance gradients to create a flat Albedo map [21, 22].
2. **Normal & Height Estimation:**
   * **DeepBump:** A fast, lightweight convolutional model trained specifically to differentiate surface relief from printed color patterns [23]. It executes in < 250 ms on CPU/local GPU.
   * **Marigold Normal:** A diffusion-based monocular normal estimator capable of resolving microscopic surface relief and fabric weaves at 2K–4K resolution [22].
3. **Roughness & Metallic Inference:** Segmenting dielectric vs metallic surfaces using color heuristics (high-luminance neutral reflections indicate metals; colored diffuse indicates dielectrics) and calculating specular variance to generate the Roughness map [24].
4. **Ambient Occlusion & Channel Packing:** Deriving an Ambient Occlusion map from the height map by raymarching a local hemispherical horizon, followed by channel packing into the industry-standard **ORM texture** (R = Ambient Occlusion, G = Roughness, B = Metallic) [21].

## 5. KesherAI Material Architecture and Implementation Blueprint

### 5.1 Common Graph Intermediate Representation: `MaterialDoc`

KesherAI extends its proven `VsDoc` schema (`packages/shared/src/unity-vs.ts`) into a typed material document specification:

```typescript
export interface MaterialPin {
  name: string;
  label?: string;
  dir: "in" | "out";
  type: "float" | "vec2" | "vec3" | "vec4" | "color" | "texture2d" | "sampler" | "bool";
  default?: string | number | number[];
  links?: string[]; // "targetNodeId:targetPinName"
}

export interface MaterialNode {
  id: string;
  title: string;
  category: "master" | "math" | "vector" | "texture" | "coordinates" | "utility" | "parameter";
  class: string; // e.g. "PbrMaster", "Add", "TextureSample", "Fresnel", "Noise"
  x: number;
  y: number;
  pins: MaterialPin[];
  properties?: Record<string, unknown>; // e.g. texture path, default constant
}

export interface MaterialDoc {
  path: string;
  name: string;
  shadingModel: "lit_pbr" | "unlit" | "clearcoat" | "subsurface" | "translucent";
  twoSided?: boolean;
  blendMode?: "opaque" | "masked" | "transparent";
  parameters: Array<{ name: string; type: string; default: unknown }>;
  nodes: MaterialNode[];
}
```

#### Universal Node Vocabulary
The core node set maps directly to ASWF OpenPBR and Three.js TSL:
1. **Master Output (`PbrMaster`):** Inputs: `BaseColor`, `Metallic`, `Roughness`, `NormalTS`, `Emission`, `Occlusion`, `Alpha`, `Clearcoat`, `ClearcoatRoughness`, `Transmission`, `VertexOffset`.
2. **Math:** `Add`, `Subtract`, `Multiply`, `Divide`, `Power`, `Sqrt`, `Abs`, `Min`, `Max`, `Clamp`, `Lerp`, `Step`, `Smoothstep`, `Sin`, `Cos`.
3. **Vector:** `Dot`, `Cross`, `Normalize`, `Length`, `SplitVector`, `CombineVector`, `Transform`.
4. **Coordinates:** `TexCoord`, `TilingOffset`, `Panner`, `Rotator`, `WorldPosition`, `WorldNormal`, `ViewDirection`, `Fresnel`.
5. **Textures:** `TextureSample2D`, `NormalUnpack`, `Triplanar`.
6. **Procedural:** `PerlinNoise`, `VoronoiNoise`, `Checkerboard`.
7. **Parameters:** `ScalarParameter`, `VectorParameter`, `TextureParameter`.

### 5.2 Real-Time Three.js Viewport Integration

In `plugins/model-editor`, materials on the loaded 3D model (`GLTF`/`GLB`) are bound to a dynamic `MeshPhysicalNodeMaterial`:

```javascript
import * as THREE from 'three';
import { color, float, vec2, vec3, vec4, texture, uv, uniform, mix, timerLocal } from 'three/tsl';

export class MaterialPreviewBridge {
  constructor(mesh, materialDoc) {
    this.mesh = mesh;
    this.doc = materialDoc;
    this.material = new THREE.MeshPhysicalNodeMaterial();
    this.uniforms = new Map();
    this.rebuildGraph();
    this.mesh.material = this.material;
  }

  // Rebuilds the TSL node DAG from MaterialDoc
  rebuildGraph() {
    const nodeOutputMap = new Map();

    // 1. Traverse nodes topologically from parameters/constants to master
    for (const node of this.topologicalSort(this.doc.nodes)) {
      if (node.class === "ScalarParameter") {
        const u = uniform(float(node.properties.value ?? 0.0));
        this.uniforms.set(node.id, u);
        nodeOutputMap.set(`${node.id}:out`, u);
      } else if (node.class === "Multiply") {
        const inA = this.resolveInput(node, "a", nodeOutputMap);
        const inB = this.resolveInput(node, "b", nodeOutputMap);
        nodeOutputMap.set(`${node.id}:out`, inA.mul(inB));
      } else if (node.class === "TextureSample") {
        const uvCoord = this.resolveInput(node, "uv", nodeOutputMap) || uv();
        const texMap = this.loadTexture(node.properties.path);
        const s = texture(texMap, uvCoord);
        nodeOutputMap.set(`${node.id}:rgb`, s.rgb);
        nodeOutputMap.set(`${node.id}:a`, s.a);
      } else if (node.class === "PbrMaster") {
        // Wire outputs to Three.js NodeMaterial sockets
        if (this.hasInput(node, "BaseColor")) this.material.colorNode = this.resolveInput(node, "BaseColor", nodeOutputMap);
        if (this.hasInput(node, "Roughness")) this.material.roughnessNode = this.resolveInput(node, "Roughness", nodeOutputMap);
        if (this.hasInput(node, "Metallic")) this.material.metalnessNode = this.resolveInput(node, "Metallic", nodeOutputMap);
        if (this.hasInput(node, "NormalTS")) this.material.normalNode = this.resolveInput(node, "NormalTS", nodeOutputMap);
        if (this.hasInput(node, "Emission")) this.material.emissiveNode = this.resolveInput(node, "Emission", nodeOutputMap);
      }
    }
    this.material.needsUpdate = true;
  }

  // Live uniform updates (slider changes) run with 0ms compilation cost
  setParameter(nodeId, val) {
    const u = this.uniforms.get(nodeId);
    if (u) u.value = val;
  }
}
```

### 5.3 Headless Unity Export Pipeline

KesherAI can export to Unity using two complementary pathways:

#### Pathway A: Deterministic Offline NDJSON Generation (Zero Engine Overhead)
Because Unity's `.shadergraph` is text-based NDJSON, KesherAI writes the file directly to the project's `Assets/Shaders/` folder:
1. Generate GUIDs for `GraphData`, each `BlockNode`, node expressions, and edges.
2. Serialize the `UniversalTarget` block configured with `UniversalLitSubTarget`.
3. Emit BlockNodes for Fragment (`BaseColor`, `Metallic`, `Smoothness`, `NormalTS`, etc.). Notice that **Roughness is converted to Smoothness (`Smoothness = 1.0 - Roughness`)** [1].
4. Emit expression JSON lines and edge connection entries.
When the user subsequently launches Unity, Unity's `ShaderGraphImporter` immediately recognizes and imports the asset.

#### Pathway B: Batch Verification via `com.kesherai.bridge`
When Unity verification is required with Unity closed, KesherAI runs Unity in batch mode:
```cmd
Unity.exe -batchmode -projectPath "<project>" -executeMethod KesherAI.Bridge.KesherCommands.Batch -kesherBatchFile "batch.json" -quit
```
The bridge verifies that the shader compiles without error and returns any diagnostic shader compiler messages.

### 5.4 Headless Unreal Export Pipeline

Because Unreal `.uasset` files are binary serialized, writing raw `.uasset` files on disk without Unreal is unstable. Instead, KesherAI leverages its existing **`UKesherBridgeCommandlet`** (`integrations/unreal/KesherAIBridge/Source/KesherAIBridge/Private/KesherBridgeCommandlet.cpp`):

```
┌─────────────────────────────────┐
│ KesherAI Core / Chat Session    │
└─────────────────────────────────┘
               │ Writes JSON request to KESHER_BRIDGE_REQUEST
               ▼
┌─────────────────────────────────────────────────────────────┐
│ Headless Execution:                                         │
│ UnrealEditor.exe "<Project>.uproject" -run=KesherBridge     │
└─────────────────────────────────────────────────────────────┘
               │ Reads request in UKesherBridgeCommandlet::Main
               ▼
┌─────────────────────────────────────────────────────────────┐
│ KesherDispatch::Answer -> Material Builder                  │
│ 1. UMaterialEditingLibrary::CreateMaterial()                │
│ 2. Spawns UMaterialExpression nodes                         │
│ 3. ConnectMaterialExpressions() & ConnectMaterialProperty() │
│ 4. RecompileMaterial() & SavePackage()                      │
└─────────────────────────────────────────────────────────────┘
               │ Writes JSON response to KESHER_BRIDGE_RESPONSE
               ▼
┌─────────────────────────────────┐
│ KesherAI Bridge completes sync  │
└─────────────────────────────────┘
```

When Unreal is already open, the identical payload is sent over the live HTTP/WebSocket bridge, modifying the open asset live in the Unreal viewport.

### 5.5 Cross-Engine Impedance Mismatches

Not all shader features map 1:1 across platforms. KesherAI must handle and visually display these differences:

| Shader Feature | Unity Shader Graph (URP) | Unreal Engine 5 | Three.js TSL (Web) | KesherAI Handling & Visual Indicator |
| :--- | :--- | :--- | :--- | :--- |
| **Normal Map Green Channel** | OpenGL standard (+Y up) | DirectX standard (-Y down) | OpenGL standard (+Y up) | **Auto-conversion:** Invert Green channel (`1.0 - G`) upon Unreal export. Badge: `[ ⇅ Normal Y Inverted ]`. |
| **Surface Roughness** | Uses **Smoothness** (`1.0 - Roughness`) | Uses **Roughness** (`0 = smooth`) | Uses **Roughness** (`0 = smooth`) | **Auto-conversion:** Insert `OneMinus` node for Unity export. Badge: `[ ⟲ Roughness Inverted ]`. |
| **Custom Code Nodes** | HLSL (`CustomFunctionNode`) | HLSL/USF (`MaterialExpressionCustom`) | JavaScript / WGSL AST | **Warning:** Custom HLSL does not cross-compile to WebGPU automatically. Badge: `[ ⚠️ Custom HLSL: Preview Fallback ]`. |
| **Subsurface Scattering** | HDRP only (via Diffusion Profile); URP approximation | Subsurface Profile / Substrate | Subsurface / Transmission emulation | **Warning:** SSS requires engine-specific asset binding. Badge: `[ ⚠️ Subsurface: URP Fallback ]`. |
| **Parallax Occlusion (POM)** | POM SubGraph | `ParallaxOcclusionMapping` Material Function | Expensive loop in fragment shader | **Warning:** High performance impact on mobile web. Badge: `[ ℹ️ Parallax: Heavy Mobile ]`. |
| **Scene Color / Depth** | Requires `Camera Opaque Texture` in URP Pipeline Asset | `SceneTexture:SceneColor` / `SceneDepth` | Requires manual render pass target | **Warning:** Requires engine render pipeline feature flags enabled. Badge: `[ ⚠️ Requires Scene Texture ]`. |

#### Visual Indicators in the KesherAI Canvas
* **Green Indicator:** Node is 100% universal (evaluates identically in WebGL, Unity, and Unreal).
* **Blue Indicator:** Node auto-converts cleanly (e.g., Roughness/Smoothness inversion or Normal Y flip).
* **Amber Indicator:** Node is engine-specific or requires custom pipeline settings. Clicking the badge opens a quick-fix popover explaining the exact engine prerequisite.

### 5.6 Chat and AI Integration

The conversational AI agent in KesherAI interacts with the material editor through dedicated tools registered in `packages/core/src/routes/engine.ts` and `packages/agent/src/tools.ts`:

1. **`material_read(path)`:** Summarizes the material graph as declarative code, listing parameters, active texture maps, mathematical relationships, and master output bindings.
2. **`material_edit(path, prompt)`:** Invokes the LLM to generate atomic operations (`add`, `connect`, `set_pin`, `delete`), executes them against the in-memory `MaterialDoc`, updates the Three.js viewport immediately, and queues them for Unity/Unreal synchronization.
3. **`material_bake_pbr(imagePath, targetMaterialPath)`:** Runs local AI models (DeepBump / Marigold / intrinsic decomposition) on an uploaded image, generates the PBR map set (Albedo, Normal, Roughness, AO), and automatically connects them to a new PBR material.
4. **`material_export(path, targetEngine)`:** Triggers the headless export pipeline to generate either a Unity `.shadergraph` asset or an Unreal `.uasset` material.

## Conclusion

Building a cross-engine node-based material editor inside KesherAI is entirely feasible and architecturally natural. Rather than adding third-party web libraries or building engine-specific silos, KesherAI should extend its existing `BlueprintCanvas.tsx` with an ASWF OpenPBR-compatible `MaterialDoc` intermediate representation. 

This yields three major advantages:
1. **Zero New UI Dependencies:** Reuses KesherAI's existing canvas, keyboard shortcuts, undo system, and mobile touch support.
2. **Instant Hot-Reload:** Uses modern Three.js TSL and `MeshPhysicalNodeMaterial` for 0 ms slider updates and 15–35 ms DAG compilation in the 3D viewport.
3. **Headless Engine Export:** Generates deterministic NDJSON `.shadergraph` files for Unity, and leverages the existing `UKesherBridgeCommandlet` for Unreal Engine, delivering native assets without requiring open editor windows.

### Open Questions for Future Work
* **HLSL Transpilation to WGSL:** Evaluating whether an automated shader AST parser (such as Naga or Slang WebAssembly) should be vendored to allow user-written HLSL custom function nodes to preview inside Three.js WebGPU without manual TSL reimplementation.
* **Substrate Advanced Layering:** Expanding the `MaterialDoc` schema to support multi-layer Substrate BSDF graphs as Unreal Engine 5.8+ finalizes Substrate as its default material pipeline.
