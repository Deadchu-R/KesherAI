# 3D Editor to Blender/Max/Maya Level: Modifiers, UV, Sculpt, Rigging, Animation, and AI 3D

## Summary

This research establishes the comprehensive engineering blueprint for transforming KesherAI's existing Three.js 3D editor plugin (`plugins/model-editor/`) and Unity/Unreal scene stand-in into a production-grade 3D authoring environment approaching core Digital Content Creation (DCC) workflows found in **Blender 4.4/4.5**, **Autodesk 3ds Max 2025/2026**, and **Autodesk Maya 2025/2026**. KesherAI operates under a unique local-first architectural envelope: an Electron desktop application running a Node.js core server on a developer workstation (equipped with an RTX 3090 24 GB GPU, Ryzen CPU, local `llama.cpp`, `sd.cpp`, and ComfyUI daemons), fully accessible remotely from a mobile smartphone over a constrained 390 px viewport in both Hebrew and English (`L(he, en)`).

While KesherAI's initial 3D editor provides basic scene navigation, transform gizmos, simple cloned-mesh array/mirror modifiers, a rudimentary box-projection UV generator, primitive brush paint on `CanvasTexture`, and external Blender file round-tripping, professional game development demands five non-negotiable in-engine capabilities:
1. **Procedural Modifier Stack:** Non-destructive geometry evaluation with watertight CSG Booleans powered by the `manifold-3d` WebAssembly (WASM) kernel, Catmull-Clark subdivision, chamfer/bevel, decimation, and solidify modifiers.
2. **Interactive UV Unwrapping & 2D UV Viewport:** Automated seam-based chart parameterization and packing via `xatlas.js` / `xatlas-three` (WASM in Web Workers), coupled with an interactive 2D canvas for island editing and bidirectional sync with KesherAI's image editor.
3. **Sculpting Engine:** Dynamic local mesh deformation with spatial BVH acceleration, brush falloff curves (Grab, Smooth, Inflate, Flatten, Crease), pen-pressure sensitivity, and mobile-optimized touch controls.
4. **Rigging, Skinning, and Inverse Kinematics (IK):** `THREE.SkinnedMesh` and `THREE.Skeleton` hierarchy generation, interactive weight painting with normalization tables, runtime `CCDIKSolver` / FABRIK, and one-click auto-rigging using the local open-source **UniRig** model via ComfyUI.
5. **Timeline, Keyframe Animation, and glTF Export:** Docked Dope Sheet and Bézier curve Graph Editor, multi-track `THREE.KeyframeTrack` authoring, and complete binary `.glb` export supporting skeletal hierarchies, morph targets, skinning buffers, and glTF PBR material extensions.

## 1. Baseline: KesherAI's Existing 3D Architecture and Limitations

### 1.1 Current Architecture (`plugins/model-editor/`)
KesherAI's current 3D editor plugin is implemented as a buildless web application running inside an Electron webview or iframe:
- **Core Runtime:** Vendored Three.js r181 (`three@0.181.0`) with `WebGLRenderer`, `ACESFilmicToneMapping`, `OrbitControls`, and `TransformControls` (`plugins/model-editor/ui/editor.js`).
- **Scene Hierarchy & Stand-In:** Blender-style Outliner tree with fold/unfold, visibility toggles, and isolation (`/` key). Serves as a live stand-in for Unity scenes (`routes/unity-scene.ts`), Godot scenes (`godot.saveScene`), and Unreal levels (`unreal-frame.js`), parsing scene hierarchies and writing transform changes back to project files.
- **Modifiers Implementation:** Three hard-coded operations (`mirror`, `array`, `smooth`) in `applyMods()`. These do not alter underlying vertex buffers non-destructively through a geometry pipeline; instead, they generate child duplicates in a temporary `THREE.Group` named `"⚙ modifiers"` with negative scale or offset positions.
- **UV Generation:** Primitive axis-aligned bounding box projection (`ensureUV()`), which slices vertex coordinates across a 3x2 grid of box faces. It produces heavy texture stretching and discontinuous seams on organic or curved topology.
- **Texture Painting:** Raycasting against `BufferGeometry` triangles (`paintRay()`), mapping hit UV coordinates to a dynamic 2D HTML5 canvas (`CanvasTexture`), and updating Three.js standard material slots (`map`, `roughnessMap`, `normalMap`).
- **Material Graph:** Node-based shader graph editor (`plugins/model-editor/ui/material-graph.js`) with ~30 mathematical, procedural, and PBR nodes compiling down to custom Three.js shader injections or exporting to Unity URP Shader Graph.
- **AI Integrations:** Text-to-3D and image-to-3D bridges via ComfyUI endpoints: Hunyuan3D 2 (geometry shape only), TRELLIS.2 (geometry with PBR textures), StableProjectorz-style 4-view projection painting (`model.paint` with SD 1.5 + ControlNet depth), and semantic part segmentation (`model.parts.segment` using P3-SAM).
- **Blender Round-Trip:** External bridge (`files.openInBlender`) that writes the active scene to a `.glb`, spawns the desktop Blender executable, monitors file `mtime`, and reloads the scene when the user saves in Blender.

### 1.2 The Gap to Blender, 3ds Max, and Maya Basics
The existing editor functions primarily as an asset inspector, transform placer, and AI generation staging ground. It lacks the generative geometric and temporal authoring capabilities of primary DCC suites:
- **No Mesh Booleans or Procedural Topology:** Users cannot cut holes, combine shapes, bevel edges, or thicken surfaces without opening external software.
- **No Real UV Workspace:** UV coordinates cannot be inspected, relaxed, pinned, or repacked.
- **No Sculpting Tools:** Vertices cannot be pushed, pulled, smoothed, or carved directly.
- **No Rigging or Deformation:** Characters and articulated models are strictly static rigid meshes; skeletons, bones, and skin weights cannot be authored, previewed, or edited.
- **No Animation Timeline:** Keyframes cannot be set, interpolated, or exported into animated glTF assets.

## 2. The Modifier Stack: Lessons from 3ds Max 2026 and Blender 4.5

### 2.1 Industry State of the Art (2025–2026)
- **Autodesk 3ds Max 2025/2026:** Remains the benchmark for parametric modifier stacks. The 2025.3 and 2026 releases delivered massive performance overhauls: the Array modifier is 50%–210% faster, the Boolean modifier is 20%–50% faster, and the newly introduced "Preserve Stack Position" toggle retains modifier focus during complex scene navigation [1, 2]. 3ds Max maintains an explicit geometry evaluation pipeline where each modifier takes an incoming geometry stream (vertices, edges, faces, UV channels, normals, selection sets), evaluates a procedural operator, and passes a modified stream up the stack [1].
- **Blender 4.4/4.5:** Unified the modifier stack with Geometry Nodes. Node groups can act as standard modifiers with exposed UI inputs, while native modifiers (Subdivision Surface, Boolean, Solidify, Bevel, Decimate) operate on the internal `BKE_modifier` C++ evaluation pipeline with dependency-graph caching [3, 4].
- **Comparison & Disagreements in Desktop DCCs:** 3ds Max relies heavily on selection-passing modifiers (e.g., `Volume Select`, `Poly Select`) that restrict subsequent modifiers to specific vertex or polygon subsets. In contrast, Blender separates modifier evaluation from edit-mode vertex groups, increasingly moving toward Geometry Nodes attribute fields [3]. For KesherAI, adopting 3ds Max's linear stack metaphor with Blender's modifier taxonomy provides the cleanest user experience.

### 2.2 Constructive Solid Geometry (CSG) Booleans: `manifold-3d` vs `three-bvh-csg`
A critical architectural decision for web-based 3D modeling is the Boolean evaluation engine:

| Metric / Feature | `three-bvh-csg` (Pure JS/TS) | `manifold-3d` (C++ WASM) |
| :--- | :--- | :--- |
| **Runtime Engine** | JavaScript / TypeScript | WebAssembly (Emscripten) [5] |
| **Watertight Guarantee** | No (prone to non-manifold edges, T-junctions, coplanar holes) [6] | **Yes (strict topological 2-manifold guarantees)** [5, 7] |
| **Performance (100k tris)** | ~450–1200 ms (CPU JS bottleneck) | **~35–90 ms (SIMD-accelerated C++)** [5, 7] |
| **Coplanar / Degenerate Faces** | Often crashes or produces zero-area inverted triangles [6] | Handled robustly via exact arithmetic & perturbation [5] |
| **Binary Overhead** | 0 KB (already in JS bundle) | ~400 KB gzipped WASM module [5] |
| **Memory Management** | Automatic JS Garbage Collection | Explicit WASM heap deallocation (`.delete()`) [5] |
| **3D Printing / Game Ready** | Requires external mesh cleanup | Strictly manifold, zero non-manifold edges [5, 7] |

**Architectural Recommendation:** KesherAI must adopt **`manifold-3d` (WASM)**. In game development (Unity/Unreal) and 3D printing, non-manifold geometry, self-intersections, and open boundaries cause fatal physics and lighting bake failures. `manifold-3d` guarantees that Boolean operations (`Union`, `Difference`, `Intersection`) produce clean, watertight meshes [5].

### 2.3 Proposed Non-Destructive Modifier Pipeline for KesherAI
Rather than duplicating meshes into visual groups, the editor must implement a true procedural geometry pipeline:
```
[Base BufferGeometry] (Immutable source asset)
         │
         ▼
[Modifier 1: Mirror / Array] ──► evaluates cloned vertices & transforms
         │
         ▼
[Modifier 2: Boolean (Manifold WASM)] ──► evaluates CSG against target mesh
         │
         ▼
[Modifier 3: Bevel / Chamfer or Subsurf] ──► refines topology
         │
         ▼
[Modifier 4: Decimate (SimplifyModifier)] ──► LOD reduction to poly budget
         │
         ▼
[Evaluated BufferGeometry] ──► uploaded to GPU via DynamicDrawUsage
```

1. **Stack Data Structure:** Each `THREE.Mesh` stores a `userData.modifiers = ModifierNode[]` array. Each node defines `{ id, kind, enabled, params, dirty }`.
2. **Dirty Flag Propagation:** When a parameter changes (e.g., Array count or Boolean operand position), only downstream modifiers from the edited index re-evaluate.
3. **Core Modifiers to Support:**
   - **Mirror:** Mirrors across X, Y, or Z plane with vertex merging along the symmetry seam.
   - **Array:** Linear, radial, or curve-following distribution with parametric spacing and rotation offsets.
   - **Boolean:** Union, Difference, Intersection against any other scene object via `manifold-3d`.
   - **Solidify:** Extrudes faces along vertex normals with configurable thickness and rim generation.
   - **Bevel / Chamfer:** Splits sharp edges based on dihedral angle threshold, inserting intermediate rounding facets.
   - **Decimate / Simplify:** Poly-reduction using quadratic error metrics (`SimplifyModifier`) to hit explicit triangle budgets.
   - **Subdivision Surface:** Catmull-Clark or Loop subdivision for surface smoothing.

## 3. UV Unwrapping & 2D UV Editing: From Box Projection to `xatlas.js`

### 3.1 Industry Standards: Blender vs Maya vs 3ds Max UV Toolsets
- **Blender 4.x:** Features Least Squares Conformal Maps (LSCM) and Angle-Based Flattening (ABF++). Artists mark seams (`Ctrl+E` -> Mark Seam), unwrap islands, and pack them using a non-overlapping bin-packing algorithm with configurable margin buffers.
- **Autodesk Maya 2025/2026:** Employs the Unfold3D algorithm (conformal energy minimization), accompanied by interactive tools: UV Pinning, Symmetrize UVs, Straighten Shells, and automated distortion heatmaps (blue = compressed, red = stretched) [8].
- **Autodesk 3ds Max 2026:** Features the modernized `Unwrap UVW` modifier with Peel Mode (LSCM), automated packing, and multi-tile UDIM management [1].

### 3.2 Automated WebAssembly Unwrapping: `xatlas.js`
KesherAI's current box projection (`ensureUV`) is insufficient for organic models, game props, or AI-generated meshes (TRELLIS/Hunyuan). The industry standard for automated parameterization is **xatlas** (the open-source C++ evolution of thekla_atlas) [9, 10]:
- **`xatlas.js` / `xatlas-three`:** Compiles the C++ xatlas engine into a lightweight WebAssembly binary (~250 KB) that runs inside a browser Web Worker [9, 10].
- **Core Capabilities:**
  1. *Chart Generation:* Automatically detects high-curvature boundaries and segments the 3D surface into planar developable topological charts [9].
  2. *Parameterization:* Flattens each 3D chart into 2D UV coordinates while minimizing angular and areal distortion [9].
  3. *Atlas Packing:* Efficiently packs dozens of independent UV charts into a normalized [0, 1] texture space using an empty-space bin-packing algorithm, respecting user-defined margins to eliminate mipmap bleeding [9, 10].
- **Performance:** Evaluates a 50,000-triangle mesh in 150–350 ms inside a Web Worker, avoiding any UI thread frame drops [9, 10].

### 3.3 Interactive 2D UV Viewport Implementation
KesherAI must incorporate a dedicated 2D UV layout canvas:
1. **Docked UV Workspace:** A split-view canvas displaying the 2D UV layout alongside the 3D viewport (similar to Blender's UV Editor / 3D Viewport split).
2. **Interactive Seam Marking in 3D:** Selecting edges in the 3D viewport with an edge-selection brush; pressing `U` -> "Mark Seam" stores edge indices in `mesh.userData.seams`. Running `Unwrap` feeds these cut seams directly into `xatlas.js` as forced chart boundaries [9].
3. **2D Island Manipulation:** Utilizing standard 2D transform operations (translate, rotate, scale, flip) on individual UV islands, with magnetic snapping to canvas borders and adjacent island edges.
4. **Distortion Heatmap Shader:** A diagnostic preview mode comparing 3D triangle surface area to 2D UV triangle area, rendering green for zero distortion, red for stretched texels, and blue for compressed texels.
5. **Bidirectional Texture Sync:** KesherAI already supports `editor.handoff` to `plugins/image-editor/`. With `xatlas.js`, the editor exports a high-resolution UV wireframe guide layer, allowing the user to paint textures in the 2D image editor and have them instantly reflect on the 3D model in real time.

## 4. Sculpting Basics in WebGL/WebGPU: Brushes, BVH, and Touch Interaction

### 4.1 Lessons from Desktop & Mobile Sculpting
- **Nomad Sculpt (iPad / Android):** The undisputed benchmark for mobile touch sculpting [11, 12]. Achieves high performance through native C++ and OpenGL/Metal compute shaders, dynamic topology remeshing, and an uncluttered UI designed around thumb sliders for brush Radius and Intensity [11, 13]. Key navigation gestures: one-finger background drag to orbit, two-finger drag to pan, two-finger pinch to zoom, two-finger tap to undo, and three-finger tap to redo [11, 12].
- **SculptGL (Stéphane Ginier):** Open-source WebGL sculpting application demonstrating that client-side JavaScript can perform responsive sculpting up to ~300k vertices using spatial octrees and localized typed-array mutations.
- **Blender 4.5 Sculpt Mode:** Emphasizes Dyntopo (Dynamic Topology) with PBVH (Partitioned Bounding Volume Hierarchy) acceleration, allowing real-time edge splitting and collapsing under brush strokes without requiring a global remesh [4].
- **Three.js WebGPU Sculptor:** Modern Three.js includes `examples/jsm/misc/Sculptor.js` and `webgpu_sculpt.html`, demonstrating real-time mesh deformation and dynamic adaptation under a brush cursor [14].

### 4.2 Brush Math and Spatial Acceleration
Direct vertex iteration over an entire mesh during a pointer stroke is prohibitive on mobile devices ($O(N)$ per move event). A professional sculpt architecture requires:

```
Pointer Down / Move Event
         │
         ▼
[Raycast against Mesh BVH] ──► Identifies hit point P and surface normal N
         │
         ▼
[BVH Radius Query] ──► Extracts only vertices within sphere(P, Radius)
         │
         ▼
[Compute Falloff Weight] ──► w = smoothstep(1.0, 0.0, dist / Radius)
         │
         ▼
[Apply Brush Deformation Vector]
   • Grab: Δv = dragDelta * w
   • Smooth: Δv = (averageNeighborPos - v) * w * Intensity
   • Inflate: Δv = N * w * Intensity
   • Crease: Pinch toward stroke curve + push into surface
         │
         ▼
[Mark Buffer Sub-Range Dirty] ──► position.needsUpdate = true
```

1. **Spatial Acceleration:** Implement `three-mesh-bvh` to query vertices inside the brush influence sphere in $O(\log N)$ time.
2. **Core Brushes for KesherAI:**
   - **Grab / Move:** Translates vertices within the sphere by the screen-projected pointer displacement vector, decaying to zero at the perimeter.
   - **Smooth:** Relaxes vertices toward the Laplacian center of their topological 1-ring neighbors, smoothing out sharp facets and noise.
   - **Inflate / Deflate:** Displaces vertices along their respective vertex normals ($v' = v \pm N_v \cdot w \cdot \text{intensity}$).
   - **Clay / Flatten:** Projects vertices toward a plane defined by the hit normal, building up volume like physical sculpting clay.
   - **Crease / Pinch:** Pulls vertices inward toward the center of the brush ray while depressing vertices along the center line, creating sharp folds and creases.
3. **Dynamic Topology vs Fixed-Grid Sculpting:**
   - *Fixed-Grid Deformation:* Modifies existing vertex positions without altering the index buffer. Ideal for light character tweaks, facial expressions, and clothing adjustments on low-to-medium poly game meshes ($\le 100\text{k}$ tris).
   - *Dynamic Remeshing (WASM):* When a surface is pulled too far, triangles stretch and lose detail. Integrating a WASM remesher (such as instant-meshes or QuadriFlow) allows users to press "Remesh" with a target edge length, rebuilding clean quad/triangle topology on demand.

### 4.3 Mobile Sculpting UX (390 px Viewport)
On mobile smartphones, screen real estate is at a premium:
- **Thumb-Accessible Sliders:** Anchor dual vertical floating sliders on the left or right edge of the screen: top slider for brush **Radius** (1–100 px), bottom slider for brush **Intensity** (0–100%), matching Nomad Sculpt's layout [11, 13].
- **Gesture Disambiguation:**
  - One-finger drag on model $\rightarrow$ Sculpt stroke.
  - One-finger drag on empty background $\rightarrow$ Orbit camera [11, 12].
  - Two-finger drag $\rightarrow$ Pan camera [11, 12].
  - Two-finger pinch $\rightarrow$ Zoom camera [11, 12].
  - Two-finger double-tap $\rightarrow$ Undo [11, 12].
  - Three-finger tap $\rightarrow$ Redo [11, 12].
- **Stylus / Pen Pressure:** Listen to `pointerType === "pen"` and modulate `Intensity *= e.pressure`, enabling pressure-sensitive sculpting on tablets and touchscreen laptops.

## 5. Rigging, Skinning, and Inverse Kinematics (IK)

### 5.1 Industry Standards: Maya 2026, Blender 4.4, and Three.js Internals
- **Autodesk Maya 2025/2026:** The gold standard for character rigging. Features the Attribute Editor Deformer Widget to track skin clusters and blend shapes, Matrix-driven constraints (`offsetParentMatrix`), and the GPU-accelerated **ML Deformer** for real-time evaluation of complex anatomical deformations [8, 15, 16].
- **Blender 4.4/4.5:** Armature objects composed of edit bones (head, tail, roll) and pose bones. Supports Linear Blend Skinning (LBS) and Dual Quaternion Skinning (to eliminate joint volume loss), accompanied by automated bone-heat weight calculation and an interactive Weight Paint brush mode [3, 4].
- **Three.js Core Representation:**
  - `THREE.Bone`: Standard `Object3D` nodes organized in a parent-child hierarchy representing the kinematic chain [17].
  - `THREE.Skeleton`: Manages bone arrays, inverse bind matrices (`boneInverses`), and bone texture transforms [17].
  - `THREE.SkinnedMesh`: Binds a `BufferGeometry` to a `Skeleton`. Every vertex stores two dedicated attributes [17, 18]:
    - `skinIndex`: `THREE.Float32BufferAttribute` (itemSize 4) containing indices of up to 4 influencing bones per vertex [18].
    - `skinWeight`: `THREE.Float32BufferAttribute` (itemSize 4) containing normalized weights ($\sum_{i=0}^3 w_i = 1.0$) [18].

### 5.2 Inverse Kinematics (IK) in the Browser
Forward Kinematics (FK) requires manually rotating every parent bone (shoulder, elbow, wrist) to place a hand. Inverse Kinematics (IK) allows the user to drag an end-effector target in 3D space, with joint rotations solved automatically:
- **`CCDIKSolver` in Three.js:** Three.js includes a native Cyclic Coordinate Descent (CCD) IK solver in `three/addons/animation/CCDIKSolver.js`. It iteratively rotates each bone in a chain from end-effector to root to minimize distance to the target position, supporting joint rotation angle limits (e.g., preventing an elbow from bending backward).
- **FABRIK (Forward And Backward Reaching Inverse Kinematics):** Solves joint positions iteratively using forward and backward geometric projection, offering faster convergence and more natural joint behavior than CCD for limbs and spines.
- **Workflow in KesherAI:** When a user selects a character's hand or foot, an interactive Transform Gizmo attaches to an IK target handle. Dragging the handle solves limb joint rotations in real time at 60 fps.

### 5.3 Weight Painting and Skinning Tools
Manual skin weight authoring requires dedicated tools:
1. **Interactive Weight Paint Brush:** Raycasts onto the `SkinnedMesh`, identifies vertices within the brush radius, and adds/subtracts weight for the actively selected bone.
2. **Heatmap Visualization:** Uses a custom vertex-colored diagnostic shader rendering weights from blue (0.0 influence) through cyan, green, and yellow to red (1.0 full influence).
3. **Weight Normalization:** Enforces that the sum of weights across all 4 bone slots per vertex strictly equals 1.0 after every stroke (`weight = weight / sum`).
4. **Pruning & Smoothing:** Clears insignificant weights ($< 0.01$) to free slots for dominant bones, and applies Laplacian smoothing to eliminate sharp skin tearing during deformation.

## 6. Keyframe Animation, Timeline, and glTF Export

### 6.1 Timeline & Curve Editor Architectures
- **Autodesk Maya 2025/2026:** Overhauled the Dope Sheet and modernized Motion Trails, providing dense block-key manipulation alongside the Graph Editor's Bézier tangency controls (Spline, Linear, Clamped, Flat, Stepped) [8, 19].
- **Blender 4.4/4.5:** Introduced **Slotted Actions**, allowing a single animation action container to hold multiple independent animation slots (e.g., object transforms, bone pose tracks, shape keys/morph targets, material properties) without data fragmentation [2, 3].
- **Web Implementations:**
  - **Theatre.js:** The web industry benchmark for professional animation timelines, featuring dope sheets, keyframing, and multi-track Bézier curves for arbitrary JavaScript/Three.js properties.
  - **`Roboticela/Animator` & `fan-ziqi/robot_viewer`:** Open-source Three.js animation studios on GitHub featuring timeline scrubbing, in/out looping, bone hierarchy authoring, and multi-clip dope sheets [20, 21].

### 6.2 Three.js Animation Subsystem
Three.js has a robust built-in animation runtime:
- `THREE.AnimationClip`: Holds an array of `THREE.KeyframeTrack` objects and a total duration [22].
- `THREE.KeyframeTrack`: Specialized tracks:
  - `VectorKeyframeTrack`: For position and scale (`targetNode.position`, `targetNode.scale`).
  - `QuaternionKeyframeTrack`: For spherical linear interpolation (SLERP) of rotations (`targetNode.quaternion`).
  - `NumberKeyframeTrack`: For morph target weights and material opacity (`targetMesh.morphTargetInfluences[0]`).
- `THREE.AnimationMixer`: The playback driver that blends clips, computes cross-fades, and applies sampled transforms during the render loop (`mixer.update(delta)`).

### 6.3 Docked Dope Sheet and Graph Editor UI for KesherAI
1. **Docked Timeline Panel:** Positioned at the bottom of the viewport, expandable via a toggle button (similar to KesherAI's `material-graph.js` dock). On mobile (390 px), it opens as a swipeable bottom sheet (`sheet-timeline`).
2. **Dope Sheet Mode:** Horizontal tracks displaying keyframe diamonds along a frame ruler (e.g., 0 to 120 frames at 30 fps or 60 fps). Supports box selection, multi-key dragging, duplicate (`Shift+D`), and delete (`X`).
3. **Graph Editor Mode:** Visualizes continuous parameter curves across time with editable Bézier control handles (in-tangent, out-tangent), enabling precise ease-in, ease-out, and overshoot animation.
4. **Auto-Keying Toggle:** When active, moving or rotating any bone or object with the gizmo automatically inserts a keyframe at the current playhead position.

### 6.4 Robust glTF / GLB Export Pipeline
Exporting rigged and animated models to glTF via `three/addons/exporters/GLTFExporter.js` involves strict structural requirements [17, 22]:
- **Hierarchy Integrity:** The root object passed to `GLTFExporter.parseAsync()` must enclose both the `SkinnedMesh` and the complete `Skeleton` bone tree; exporting a disconnected bone hierarchy results in corrupted or empty skeletal tracks [17].
- **Unique Naming:** Every bone must possess a unique `.name` property, matching the target path strings in `KeyframeTrack` (e.g., `"mixamorig:RightArm.quaternion"`) [22].
- **Animation Options:** Animation clips must be explicitly supplied in the exporter options:
  ```javascript
  const glbBlob = await new GLTFExporter().parseAsync(modelRoot, {
    binary: true,
    onlyVisible: true,
    animations: [walkClip, idleClip], // Explicitly passed
    embedImages: true,
  });
  ```
- **PBR Extensions Support:** Preserves `KHR_materials_unlit`, `KHR_materials_transmission`, `KHR_materials_clearcoat`, and texture coordinate transforms (`KHR_texture_transform`).

## 7. AI 3D Generation & Processing Pipeline (2025–2026)

### 7.1 State of the Art: TRELLIS.2 vs Hunyuan3D 2.1
Open-source local 3D generation has advanced dramatically over the last 12 months:

| Capability / Metric | Tencent Hunyuan3D 2.0 / 2.1 | Microsoft TRELLIS.2 |
| :--- | :--- | :--- |
| **Model Architecture** | Flow-matching Diffusion Transformer (DiT) [23] | 4B Sparse O-Voxel VAE + DINOv3 [24, 25] |
| **Input Modalities** | Text prompts, single image, multi-view images [23] | Single reference image [24, 25] |
| **Output Assets** | Watertight geometry mesh (.obj/.glb) [23] | Full PBR mesh (.glb) + 3D Gaussians [24, 25] |
| **Material Quality** | Albedo only (requires separate paint stage) [23] | **Native PBR (Albedo, Roughness, Metallic)** [24, 25] |
| **Generation Speed** | ~45–90s on RTX 3090 (geometry only) [23] | ~60–120s on RTX 3090 (complete PBR asset) [24, 25] |
| **ComfyUI Integration** | Native nodes (Comfy-Org/Hunyuan3D) [26] | Native nodes (Comfy-Org/TRELLIS.2) [24, 26] |
| **VRAM Footprint** | ~14–18 GB VRAM [23] | ~18–22 GB VRAM (fits in 24 GB RTX 3090) [25] |

**KesherAI Strategy:** Leverage **Hunyuan3D 2.1** for rapid text-to-shape modeling where geometry control and polycount density matter most, and **TRELLIS.2** for high-fidelity image-to-3D asset generation where realistic PBR materials, reflections, and roughness are needed immediately.

### 7.2 Open-Source AI Auto-Rigging: UniRig
Manual skeletal placement and skin weighting are notoriously time-consuming. In mid-2025, researchers from Tsinghua University and VAST AI Research / Tripo released **UniRig** (*"One Model to Rig Them All"*, arXiv:2504.12451) [27, 28]:
- **Architecture:** Employs an autoregressive *Skeleton Tree Tokenization* method paired with an OPT-based Transformer to predict topologically sound skeletal joint hierarchies from 3D point clouds, followed by a bone-point cross-attention network that outputs skinning weights [27, 28].
- **Versatility:** Unlike rigid legacy tools (e.g., Mixamo) restricted solely to standard bipeds, UniRig generalizes across arbitrary quadrupeds, birds, robotic mechanisms, fantasy creatures, and stylized characters [27, 28].
- **ComfyUI Ecosystem:** The community has wrapped UniRig into native ComfyUI nodes (`PozzettiAndrea/ComfyUI-UniRig`), accepting a `.glb` mesh input and outputting a fully rigged and skinned `.glb` character with standard humanoid or custom bone naming conventions [29].
- **Integration for KesherAI:** Because KesherAI's core server already orchestrates local ComfyUI processes, adding a "✨ Auto-Rig (UniRig)" button in the 3D editor allows users to transform any static AI-generated mesh into a rigged, animatable character directly on their local RTX 3090 GPU in under 30 seconds [28, 29].

### 7.3 Automated Retopology and PBR Texture Baking
AI-generated meshes often feature messy triangular soup topology. A complete AI pipeline requires local cleanup nodes:
1. **Quad Retopology:** Using WebAssembly-compiled **QuadriFlow** or **Instant Meshes** to convert dense triangular meshes into clean, edge-loop-aligned quad topology suitable for character deformation.
2. **Automated UVs & Normals:** Running `xatlas.js` to unwrap the retopologized mesh, followed by baking high-resolution surface details from the original dense mesh onto a normal map (`normalMap`) and ambient occlusion map (`aoMap`).
3. **Texture Painting via Diffusion:** KesherAI already incorporates `model.paint` (4-view projection using SD 1.5 + ControlNet depth). Updating this pipeline to FLUX.1 Fill or Hunyuan3D-Paint provides photorealistic 2K/4K surface textures with aligned PBR material properties.

## 8. Mobile (390 px) and Local-First Architecture

### 8.1 Dual Device Experience: Desktop PC vs Mobile Phone
KesherAI is designed for a single developer working flexibly across devices:
- **Desktop Mode (Workstation):** Multi-pane viewport (Quad view: Top, Front, Left, Perspective), dual-monitor undocking, comprehensive hotkey schemes (Blender G/R/S or Maya W/E/R), deep material graph node editing, and direct local GPU inference execution.

## 9. Phased Implementation Roadmap for KesherAI

KesherAI should execute this expansion in five structured, incremental phases following the repository's small-step verification rules (`pnpm -s typecheck && pnpm -s test`):

```
Phase 1: Procedural Modifier Stack & Manifold-3D WASM
     │
     ▼
Phase 2: Automated UV Unwrapping (xatlas.js) & 2D UV Viewport
     │
     ▼
Phase 3: WebGL Sculpt Mode (BVH Spatial Index & Brush Suite)
     │
     ▼
Phase 4: Rigging, Skinning, IK & UniRig Auto-Rigging
     │
     ▼
Phase 5: Keyframe Animation Timeline & Complete glTF Export
```

### Phase 1: Procedural Modifier Stack & Manifold-3D WASM
- **Scope:** Replace naive group-cloning with a true non-destructive geometry evaluation pipeline.
- **Deliverables:**
  - Integrate `manifold-3d` WASM module for watertight CSG Booleans (`Union`, `Difference`, `Intersection`).
  - Implement Array modifier with radial and curve distribution parameters.
  - Implement Mirror modifier with planar welding.
  - Implement Bevel / Chamfer and Solidify modifiers.
  - Implement Decimate modifier wrapping Three.js `SimplifyModifier`.
  - Add dirty-flag evaluation cache and UI modifier stack manager in the right sidebar.

### Phase 2: Automated UV Unwrapping (`xatlas.js`) & 2D UV Viewport
- **Scope:** Transition from crude box projection to production-grade chart parameterization.
- **Deliverables:**
  - Integrate `xatlas-three` / `xatlas.js` running inside a Web Worker.
  - Implement interactive edge seam marking (`mesh.userData.seams`) in the 3D viewport.
  - Build a docked 2D UV layout viewer showing packed islands and distortion heatmaps.
  - Enable island translation, rotation, and packing controls.
  - Connect UV layout directly to `editor.handoff` with `plugins/image-editor/` for seamless 2D/3D texture painting.

### Phase 3: WebGL Sculpt Mode (BVH Spatial Index & Brush Suite)
- **Scope:** Provide organic mesh shape manipulation directly within the browser.
- **Deliverables:**
  - Integrate `three-mesh-bvh` for $O(\log N)$ local vertex radius queries.
  - Implement core brush algorithms: Grab, Smooth, Inflate/Deflate, Clay, Crease/Pinch.
  - Add floating thumb sliders for brush Radius and Intensity, optimized for mobile (390 px).
  - Add pen-pressure support (`pointerType === "pen"`) for graphics tablets and touch screens.
  - Implement multi-touch gesture listeners (two-finger undo, three-finger redo).

### Phase 4: Rigging, Skinning, IK & UniRig Auto-Rigging
- **Scope:** Enable articulated character deformation and skeletal control.
- **Deliverables:**
  - Implement bone authoring tools: add bone, extrude joint, adjust bone roll, build `THREE.Skeleton`.
  - Support `THREE.SkinnedMesh` binding with normalized `skinIndex` and `skinWeight` buffers.
  - Build an interactive Weight Paint brush mode with color-coded influence visualization.
  - Integrate Three.js `CCDIKSolver` for two-bone limb Inverse Kinematics.
  - Connect to local ComfyUI running `ComfyUI-UniRig` for one-click AI auto-rigging of arbitrary meshes.

### Phase 5: Keyframe Animation Timeline & Complete glTF Export
- **Scope:** Enable temporal authoring and full game-engine asset delivery.
- **Deliverables:**
  - Build a docked Dope Sheet and Bézier Graph Editor panel (collapsible bottom sheet on mobile).
  - Implement timeline playback controls: play/pause, scrub, frame stepping, loop points, auto-keying.
  - Author and evaluate `THREE.KeyframeTrack` tracks driving bone rotations and morph targets.
  - Upgrade `GLTFExporter` integration to package complete binary `.glb` files bundling meshes, PBR textures, skeleton rigs, skin weights, and animation clips.
  - Verify seamless import into Unity 6 and Unreal Engine 5.

## 10. Conclusion

KesherAI's existing 3D editor provides a solid architectural foundation with its lightweight Three.js r181 renderer, Outliner hierarchy, gizmo controls, material graph node system, and game engine scene stand-in synchronization. However, bridging the gap to Blender, 3ds Max, and Maya basics requires transitioning from passive asset inspection to active procedural and temporal geometry authoring.

By anchoring the modifier stack with the watertight **`manifold-3d`** WASM kernel, replacing primitive box projection with **`xatlas.js`** automated chart parameterization, accelerating sculpt brushes with **`three-mesh-bvh`**, implementing standard **`SkinnedMesh`** rigging with **UniRig** auto-rigging in local ComfyUI, and embedding a docked **Dope Sheet timeline** with robust **glTF skeletal export**, KesherAI can deliver a professional-grade 3D creative suite. This pipeline empowers game developers to model, sculpt, rig, texture, and animate game assets locally on an RTX 3090 workstation or remotely from a mobile smartphone without dependency on proprietary cloud services or heavy external DCC software.
