# Bi-Directional Engine Model Context Protocol: Unreal 5.8+ Native MCP and Godot Bridge

## Summary

This research establishes an architectural specification for bi-directional Model Context Protocol (MCP) integration in KesherAI. The objective is twofold:
1. **KesherAI as an MCP Client:** Enable KesherAI's agent loop to directly consume engine capabilities from Unreal Engine 5.8+'s native `ModelContextProtocol` plugin (and community Godot MCP bridges), deprecating the maintenance overhead of bespoke C++ and GDScript RPC bridges.
2. **KesherAI Core as an MCP Server:** Expose KesherAI's headless, engine-closed capabilities—fast offline scene parsing (`.tscn`, `.unity`, `.umap`/`.uasset`), cross-engine material translation (`material-doc`), and indexed asset dependency mapping—to external AI development tools like Claude Code, Cursor, and VS Code.

As game development workflows evolve from isolated chatbots to multi-agent co-development, maintaining isolated, engine-specific bridge protocols (`ws://127.0.0.1:7420/api/unreal/ws`, `ws://127.0.0.1:7420/api/godot/ws`) creates technical debt. Epic Games' introduction of native Model Context Protocol support in Unreal Engine 5.8+ provides a standardized, in-editor JSON-RPC server over HTTP. By interfacing with this protocol while bridging community Godot MCP developments, KesherAI establishes a unified engine tool plane. Furthermore, by addressing concurrent multi-client collisions via optimistic concurrency tokens, transactional undo framing, and three-way AST/scene merging, KesherAI guarantees non-destructive collaboration between external LLMs and local autonomous self-work agents.

### 1.1 Transport Layer: Streamable HTTP/SSE vs. Stdio
The Model Context Protocol specification supports both standard I/O (`stdio`) child-process pipes and Streamable HTTP (JSON-RPC over HTTP POST with Server-Sent Events for streaming and notifications) [4, 9]. 

For Unreal Engine 5.8+, Epic Games selected **Streamable HTTP** as the primary transport:
* **Host & Port:** Defaults to `http://127.0.0.1:8000/mcp` (configurable via `EditorPerProjectUserSettings.ini` under `[/Script/ModelContextProtocolEngine.ModelContextProtocolSettings]`).
* **Why Stdio is Infeasible for Unreal Editor:** In CLI-centric tools (e.g., SQLite MCP, Filesystem MCP), the client launches the server as a child process via `stdio`. However, launching an Unreal Editor instance requires 15–90 seconds of initialization, shader compilation, and 4–16 GB of RAM. An HTTP endpoint allows the existing, user-managed editor process to service multiple concurrent AI agents (Claude Code, Cursor, KesherAI) without process re-instantiation [2, 8].
* **Session Lifecycle:** The MCP HTTP listener is bound directly to the editor's main thread and engine loop (`FHttpServerModule`). The server becomes active once default maps and asset registries complete loading, runs continuously during editing, and automatically terminates when the editor closes [1, 3].

### 1.2 Tool Registration Schema and Progressive Discovery
Exposing the entire surface of Unreal Engine directly through standard `tools/list` payloads creates massive context bloat. Unreal Engine contains over 40,000 reflection functions and thousands of editor operations; serializing their schemas into a single prompt consumes over 250,000 tokens, degrading LLM reasoning and exceeding client token limits [7, 8].

To solve this, Unreal Engine 5.8+ implements **Progressive Tool Discovery** (`bEnableToolSearch`):
1. **Initial Meta-Tool Catalog:** Instead of returning exhaustive schemas, `tools/list` exposes four discovery meta-tools:
   * `list_toolsets`: Returns categories of available tools (e.g., `ActorToolsets`, `BlueprintToolsets`, `PCGToolsets`, `SequencerToolsets`, `MaterialToolsets`, `LevelToolsets`).
   * `describe_toolsets`: Takes a `toolset_name` and returns summaries of member tools.
   * `describe_tools`: Returns the strict JSON Schema for specific target tools.
   * `call_tool`: Invokes the target tool with parameter validation.
2. **C++ Registration:** Native tool libraries inherit from `UModelContextProtocolToolLibrary` (or register through `IModelContextProtocolModule`). Public methods decorated with `UFUNCTION()` are automatically parsed by Unreal's Header Tool (UHT) to generate MCP JSON schemas [6, 7].
3. **Python Registration:** Scripted toolsets inherit from `unreal.ToolsetDefinition` in editor Python environments, allowing teams to dynamically register custom studio pipelines without recompiling C++ binaries [7, 8].

#### Example Unreal MCP Discovery Payload
```json
// tools/call -> list_toolsets
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "toolsets": [
      { "name": "ActorToolsets", "description": "Spawn, select, transform, and inspect level actors and components." },
      { "name": "BlueprintToolsets", "description": "Introspect graphs, add/connect nodes, query pins, and trigger compilation." },
      { "name": "PCGToolsets", "description": "Procedural Content Generation graph overrides, node configuration, and generation." },
      { "name": "SequencerToolsets", "description": "Manage Level Sequences, movie tracks, keyframing, and playback control." }
    ]
  }
}
```

### 1.3 Authentication & Security Model
* **Loopback Binding:** By default, the HTTP listener binds strictly to the IPv4 loopback interface `127.0.0.1`. Remote network interfaces (LAN/WAN) reject incoming connections at the socket level [8, 10].
* **Pre-Shared Bearer Authentication:** For containerized workflows or cross-device setups, Unreal MCP supports an optional `Authorization: Bearer <token>` header specified in `EditorPerProjectUserSettings.ini`:
  ```ini
  [/Script/ModelContextProtocolEngine.ModelContextProtocolSettings]
  bAutoStartServer=True
  ServerPort=8000
  AuthToken="kesher-secure-token-vault"
  ```
* **Read-Only / Destructive Annotations:** Tools provide metadata annotations (`readOnlyHint: true`, `destructiveHint: true`) enabling client-side confirmation guards before executing high-risk mutations (such as deleting level sub-scenes or force-saving modified packages) [9].

### 1.4 Supported Domain Operations
Unreal Engine 5.8+ organizes native MCP operations across core engine domains:
1. **Actors & World Partition:**
   * Querying actors via spatial bounding boxes, tags, or class filters.
   * Spawning actors (`SpawnActor`), applying hierarchical transforms (Location, Rotation, Scale), and attaching components.
   * Managing World Partition data layers and querying loaded grid cells.
2. **Blueprints:**
   * Introspecting Blueprint asset node graphs (`EventGraph`, Function Graphs, Macro Graphs).
   * Adding function calls, event nodes, variable getters/setters, branches, sequences, and casts.
   * Connecting and disconnecting execution and data pins with type validation.
   * Compiling Blueprints with structured error returns (node ID, severity, line/graph context).
3. **PCG (Procedural Content Generation):**
   * Inspecting PCG graph topology and exposed graph parameters.
   * Dynamically overriding parameter values on `UPCGComponent`.
   * Triggering dirtying, background re-generation, and point cache inspection.
4. **Sequencer (Cinematics & Animation):**
   * Creating and binding Level Sequence assets.
   * Adding actor tracks, transform tracks, event tracks, and skeletal animation tracks.
   * Setting keyframes, interpolating curves, and scrubbing playback time programmatically.
5. **Vision & Diagnostics:**
   * Screen capture via `CaptureViewport` returning base64 PNGs for visual inspection loops.
   * Safe execution of editor console commands (`ExecuteConsoleCommand`).

## 2. Godot Engine MCP Analysis and Mapping to KesherAI Bridge

### 2.1 Community Godot MCP Server Ecosystem
Several open-source projects implement MCP for Godot Engine 4.2+:
1. **mkdevkit/godot-mcp:** Uses a dual-component architecture consisting of a Godot editor plugin (WebSocket client) and an external Node.js MCP server (speaking `stdio` to Claude/Cursor) [12]. It exposes over 170 tools covering project settings, scene hierarchies, node CRUD operations, and script editing.
2. **IvanMurzak/Godot-MCP:** A C#/.NET Godot editor addon built for Godot 4.3+ Mono builds [11]. It uses Resource Query Language (RQL) queries and shares a reflection backend with Unity-MCP and Unreal-MCP (`ai-game.dev`) [11, 14].
3. **NPGameDev/godot-mcp-toolkit:** A lightweight GDScript/GDExtension bridge providing direct scene and playtest manipulation [13].
4. **Dokujaa/Godot-MCP:** A Python-based stdio MCP server bridging Claude Desktop to Godot via local TCP sockets [15].

### 2.2 KesherAI's Native Godot Bridge (`kesher_bridge.gd`)
KesherAI already includes a native Godot EditorPlugin (`integrations/godot/addons/kesher_bridge/kesher_bridge.gd`, v0.1.2) [16]. Unlike community projects that force Godot to listen on local TCP ports or require external Node/Python runtime wrappers, KesherAI's bridge uses a **reverse WebSocket architecture**:
* The Godot plugin connects outward to KesherAI Core at `ws://127.0.0.1:7420/api/godot/ws`.
* Godot never exposes open listening sockets on the host machine.
* Every operation executes inside Godot's native `UndoRedo` history stack (`ur.create_action()`), ensuring full Ctrl+Z recovery for the human developer [16].

### 2.3 Protocol Command Mapping
Rather than installing third-party wrapper servers, KesherAI can map community MCP tool conventions directly onto its existing, battle-tested `kesher_bridge.gd` RPC methods:

| Standard MCP Tool Name | Target Engine Operation | KesherAI Native Command (`kesher_bridge.gd`) | UndoRedo Supported |
| :--- | :--- | :--- | :---: |
| `godot_get_scene_tree` | Query full node hierarchy & scripts | `tree` (returns JSON scene tree with depth control) | Read-only |
| `godot_inspect_node` | Read properties & values of a node | `get` (returns property map with editor flags) | Read-only |

### 3.1 Sub-system 1: KesherAI Agent as MCP Client (Downstream Engine Integration)

Currently, KesherAI controls game engines via three separate bespoke communication systems:
1. `unreal-bridge.ts`: WebSocket bridge calling custom C++ functions in `KesherAIBridge` [16, 17].
2. `godot-bridge.ts`: WebSocket bridge dispatching GDScript functions in `kesher_bridge.gd` [16].
3. `unity-bridge.ts`: C# socket receiver in `KesherAI.Bridge.Editor` [18].

#### Transition to Unified Engine MCP Client
Under the new architecture, KesherAI's agent loop treats active game engines as standard MCP servers managed by `McpManager` (`packages/core/src/mcp.ts`):
* **Auto-Discovery:** When KesherAI boots or opens an Unreal project, it checks `http://127.0.0.1:8000/mcp`. If Unreal 5.8+'s native server responds to `ping`, KesherAI registers it as the active engine client.
* **Dynamic Tool Ingestion:** Rather than hard-coding tools like `unreal_add_actor` or `unreal_connect_pins` in `unreal-tools.ts`, KesherAI ingests the toolset definitions directly from the engine's `tools/list` response.
* **Progressive Exploration:** When solving tasks involving complex Blueprints or PCG graphs, the KesherAI agent executes `list_toolsets` and `describe_tools` dynamically, retrieving exact parameter schemas on demand without saturating its prompt context.
* **Compatibility Fallback:** For older Unreal projects (UE 5.1–5.7) lacking native MCP support, KesherAI automatically falls back to its existing WebSocket bridge (`KesherAIBridge`), preserving backwards compatibility.

### 3.2 Sub-system 2: KesherAI Core as MCP Server (Upstream Tool Exposure)

KesherAI already hosts an MCP server at `/mcp` via Streamable HTTP (defined in `packages/core/src/routes/mcp-server.ts`) [19]. External agents like Claude Code, Cursor, and VS Code can connect using:
```bash
claude mcp add --transport http kesherai http://127.0.0.1:7420/mcp
```

To deliver maximum value to external AI tools, KesherAI Core will expose three specialized, engine-closed capabilities that external tools lack:

#### 1. Engine-Closed Scene Reading (`kesher_read_scene`)
External agents (Cursor, Claude Code) cannot easily parse proprietary 3D scene files without launching multi-gigabyte editor binaries. KesherAI's core includes specialized headless parsers:
* Godot `.tscn`: Direct lexical parsing of text-based Godot scene trees.
* Unity YAML: Headless streaming parser (`unity-scene.ts`) that extracts GameObjects, Transform hierarchies, and component GUIDs without Unity running [18].
* Unreal `.umap` / `.uasset`: Binary header parser (`uasset.ts`, `unreal-assets.ts`) that extracts actor classes, transform lists, and package dependencies directly from disk [17].

**MCP Tool Schema:**
```json
{
  "name": "kesher_read_scene",
  "description": "Inspect the hierarchy, nodes, and components of a Godot, Unity, or Unreal scene file directly on disk without launching the game engine.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "path": { "type": "string", "description": "Absolute path to .tscn, .unity, or .umap file." },
      "depth": { "type": "number", "description": "Hierarchy traversal depth (default 5)." }
    },
    "required": ["path"]
  }
}
```

#### 2. Cross-Engine Material Translation (`kesher_translate_material`)
KesherAI features an engine-agnostic PBR material AST parser (`material-doc.js`) that validates nodes, checks for dependency cycles, and converts material node graphs into target engine representations [20]:
* Compiles PBR graphs into Three.js/WebGPU GLSL shader blocks [20].
* Serializes graphs into Unity Universal Render Pipeline (URP) Lit ShaderGraph JSON (`UnityEditor.ShaderGraph.GraphData`) [20].
* Emits Unreal Engine material commands (`unrealMaterialCommand`) [20].

**MCP Tool Schema:**
```json
{
  "name": "kesher_translate_material",
  "description": "Translate a universal PBR node graph into target engine shader representations (Unity ShaderGraph JSON, Unreal Engine material script, or raw GLSL).",
  "inputSchema": {
    "type": "object",
    "properties": {
      "graph": { "type": "object", "description": "KesherAI material document object (nodes and links)." },
      "target": { "type": "string", "enum": ["unity_shadergraph", "unreal_material", "glsl"] }
    },
    "required": ["graph", "target"]
  }
}
```

#### 3. High-Speed Project Asset Dependency Indexing (`kesher_index_assets`)
External coding agents often struggle to locate asset dependencies (e.g., "Find all Blueprints that reference `M_Rock_Inst`") because ripgrep cannot reliably search binary package formats. KesherAI's `unreal-assets.ts` and `find_assets` engine provides:
* Sub-100 ms index lookups across 1,000+ packages [17].
* Hard and soft package import resolution (`uses`, `soft`).
* OneDrive cloud-only file skipping (prevents unintended downloads) [17].

**MCP Tool Schema:**

## 4. Conflict Arbitration & Multi-Agent Concurrency

### 4.1 The Concurrency Matrix
In a bi-directional environment, four distinct actors can mutate project assets concurrently:
1. **External AI Agent:** Claude Code or Cursor executing tools via KesherAI Core MCP server.
2. **Local Autonomous Agent:** KesherAI's self-work loop (`session.ts`) modifying files or issuing bridge commands in the background.
3. **Engine-Native AI:** Another tool invoking Unreal Engine 5.8+'s native MCP server directly.
4. **Human Developer:** The developer interacting directly with the Unreal/Godot editor UI or KesherAI's 3D Stand-in viewer.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        CONCURRENT MUTATION MATRIX                      │
│                                                                        │
│   Actor A (e.g., Claude Code via MCP)   Actor B (KesherAI Self-Work)   │
│             │                                      │                   │
│             ▼                                      ▼                   │
│     [Proposes Move Actor X]               [Proposes Rename Actor X]    │
│             │                                      │                   │
│             └──────────────────┬───────────────────┘                   │
│                                │                                       │
│                                ▼                                       │
│              ┌───────────────────────────────────┐                     │
│              │ Conflict Arbitration Pipeline     │                     │
│              │ 1. Token Check (ETag / Revision)  │                     │
│              │ 2. Scoped Resource Lock           │                     │
│              │ 3. Atomic Undo Transaction        │                     │
│              │ 4. Three-Way Merge Engine         │                     │
│              └─────────────────┬─────────────────┘                     │
│                                │                                       │
│                ┌───────────────┴───────────────┐                       │
│                ▼                               ▼                       │
│       [Clean Merge / Apply]           [Conflict Detected]              │
│       - Applies to Editor             - Revert Transaction             │
│       - Emits notification            - Emit Approval Card to User     │
└────────────────────────────────────────────────────────────────────────┘
```

### 4.2 Four-Layer Arbitration Protocol

To prevent asset corruption, desynchronized memory states, or lost developer work, KesherAI implements a four-layer arbitration strategy:

#### Layer 1: Optimistic Concurrency Control (OCC) with Revision Tokens
Every asset, scene node, and graph element exposed via MCP carries a revision identifier computed from its file modification timestamp (`mtimeMs`), hash, and in-memory change sequence:
```typescript
interface AssetRevisionToken {
  assetPath: string;
  revision: string; // SHA-256 of state or sequence counter
  timestamp: number;
}
```
* When an agent queries an asset or scene via `kesher_read_scene` or engine MCP, it receives the current `revision`.
* When submitting a mutation (e.g., `godot_set_property`, `unreal_edit_blueprint`), the agent must provide an `expected_revision` argument.
* If the engine or another agent has mutated the target since the revision token was issued, the mutation is immediately rejected with a standard JSON-RPC error:
  ```json
  {
    "jsonrpc": "2.0",
    "id": 42,
    "error": {
      "code": -32009,
      "message": "Resource Conflict: Asset '/Game/BP_Player' has been modified by another process. Current revision: 'rev_91b2'. Provided revision: 'rev_74a1'.",
      "data": { "currentRevision": "rev_91b2", "assetPath": "/Game/BP_Player" }
    }
  }
  ```

#### Layer 2: Granular Scoped Resource Locking
For multi-step autonomous tasks (e.g., an agent refactoring multiple interconnected Blueprints or updating a character hierarchy), simple per-operation checks are insufficient. KesherAI Core maintains an in-memory **Resource Lock Table**:
* Locks are acquired at package or scene scope (e.g., `Lock("res://scenes/main.tscn", owner: "claude-code", ttl: 30000)`).
* Locks enforce a strict Time-To-Live (default 30 seconds, renewable) with heartbeat refresh to prevent permanent deadlocks if an external agent crashes.
* While a resource is locked by an external agent, KesherAI's local self-work agent automatically queues dependent tasks or works on unrelated project files.

#### Layer 3: Transactional Undo Framing
Every batch of mutations dispatched to an open game engine must be encapsulated in an atomic editor transaction:
* **Unreal Engine:** Enclosed using `GEditor->BeginTransaction(FText::FromString("KesherAI MCP Edit"))` and `GEditor->EndTransaction()`. If any operation in the batch fails, the transaction is canceled (`GEditor->CancelTransaction()`), instantly reverting the editor memory state without leaving partial edits [16, 17].
* **Godot Engine:** As implemented in `kesher_bridge.gd`, all changes use Godot's `UndoRedo` system (`ur.create_action()`, `ur.add_do_method()`, `ur.add_undo_method()`, `ur.commit_action()`) [16]. This ensures that even if an automated agent makes an unintended edit, the human developer can revert it with a single `Ctrl+Z` in the editor [16].

#### Layer 4: Three-Way AST / Scene Diff Merge
When edits originate from KesherAI's offline 3D Stand-in viewer while the engine was also being modified live, KesherAI uses the three-way merge algorithm implemented in `standin_moves` (`kesher_bridge.gd`) [16]:
* **Base State (`from`):** The initial spatial transform or property value when the offline session began.
* **Live Engine State (`now`):** The current transform or property value in the open engine editor.
* **Target Edit State (`target`):** The transform modified by the user or agent in the stand-in viewer.
* **Resolution Rules:**
  1. If `now == from`, the engine was untouched: apply `target` cleanly.
  2. If `now != from` but `target == from`, no change in stand-in: keep `now`.
  3. If `now != from` and `target != from` across non-overlapping properties (e.g., Actor A moved in Stand-in, Actor B moved in Engine): merge both changes automatically.
  4. If `now != from` and `target != from` on the exact same property: flag as a hard collision. The engine state is preserved, and KesherAI surfaces an interactive Approval Card in the chat UI (`summarizeEvents`, `kesher_approve`) letting the user decide whether to keep the engine version or overwrite with the stand-in version [16, 19].

## 5. Comparative Evaluation: Bespoke Bridges vs. Bi-Directional MCP

| Dimension | Legacy KesherAI Bridge (`ws://...`) | Bi-Directional MCP Architecture |
| :--- | :--- | :--- |
| **Transport Protocol** | Custom JSON packets over WebSockets (`ws://`) | Open standard JSON-RPC 2.0 over Streamable HTTP & stdio [4, 9] |
| **Engine Maintenance** | Requires maintaining 5,000+ lines of custom C++, C#, and GDScript across 3 engines | Direct consumption of first-party Unreal 5.8+ MCP plugins; minimal Godot adapter [1, 16] |
| **External Agent Access** | Closed ecosystem; Claude Code/Cursor cannot access KesherAI engine tools | Full interoperability; Claude Code & Cursor connect directly to `/mcp` [19] |
| **Context Window Consumption** | Fixed tool list dumped into system prompts (~12,000 tokens) | Progressive discovery (`list_toolsets`, `describe_tools`) consumes <1,500 tokens [7] |
| **Offline Engine Support** | Zero; tools fail immediately if editor is closed | Headless parsing of `.tscn`, `.unity`, `.umap`, and PBR material ASTs [17, 20] |
| **Concurrency & Conflict** | First-write wins; risk of silent editor state overwrite | Optimistic tokens, resource locks, atomic undo, and three-way scene merging [16, 19] |
| **Security & Auth** | Local loopback check only | Loopback binding + Bearer Token support + fine-grained approval cards [8, 19] |

## Conclusion

Transitioning KesherAI to a bi-directional Model Context Protocol architecture eliminates the heavy maintenance burden of bespoke engine bridge plugins while establishing KesherAI as the premier game-engine intelligence hub for external coding agents (Cursor, Claude Code, Copilot). 

By acting as an **MCP Client** to Unreal Engine 5.8+'s native `ModelContextProtocol` plugin, KesherAI gains instant, zero-maintenance access to thousands of native engine capabilities across Actors, Blueprints, PCG, and Sequencer. Concurrently, by acting as an **MCP Server**, KesherAI exports its proprietary offline scene parsing, material translation, and sub-second asset indexing to the broader AI ecosystem. Governed by optimistic concurrency tokens, scoped resource locks, and transactional undo framing, this architecture guarantees safe, high-speed, multi-agent co-development across complex 3D projects.

### Open Questions for Future Implementation
* **Dynamic SSE Push vs. Polling:** Unreal Engine 5.8+'s HTTP daemon supports Server-Sent Events (SSE). Evaluating whether KesherAI's `HttpTransport` should maintain persistent SSE streams for live editor event telemetry (e.g., actor selection changes, compilation failures) or continue with low-overhead HTTP POST polling.
* **Shader Graph Version Compatibility:** Unity ShaderGraph JSON schemas change between Unity 2021.3 LTS, 2022.3 LTS, and Unity 6. Expanding `material-doc.js` to serialize version-specific target descriptors (`UniversalTarget` v1 vs v2).
* **Cross-Process Viewport Streaming:** Exploring whether Unreal MCP's `CaptureViewport` can be accelerated via shared memory handles (DXGI shared textures / Spout) rather than base64 PNG serialization for high-framerate vision tracking.
