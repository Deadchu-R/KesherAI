# Deep Research: The Four Editors (Picture, 3D, Sound, Video) to Pro Level

## Summary

This research establishes the comprehensive technical blueprint for advancing KesherAI's four creative studio editors—**Image Editor**, **3D Model Editor**, **Sound Editor / DAW**, and **Video Editor / NLE**—from lightweight canvas prototypes to professional-grade creative instruments. KesherAI's operating envelope is uniquely challenging: an open-source, local-first application built on Electron, React, and a Node.js server, communicating with local AI inference engines (`sd.cpp`, `llama.cpp`, ComfyUI, and ONNX Runtime) on a developer's PC, while maintaining full operational parity when accessed remotely from a mobile smartphone over a constrained 390 px viewport in both Hebrew and English (`L(he, en)`).

Across all four domains, professional tools (*Photoshop, Affinity Photo 2, Krita, Blender 4.x/4.5, 3ds Max 2026, Maya, Ableton Live 12, Reaper 7, DaVinci Resolve 19/20, CapCut*) achieve their performance not through monolithic brute-force computation, but through strict architectural primitives:
1. **GPU-Accelerated Compositing & WebCodecs:** Offloading pixel manipulation, color grading, and geometry deformation to WebGL2/WebGPU shaders, `OffscreenCanvas`, and hardware-accelerated `VideoDecoder` streams, avoiding main-thread JavaScript bottlenecks.
2. **Non-Destructive Graph Stacks:** Implementing non-destructive adjustment layers, modifier stacks (using watertight WASM kernels like `manifold-3d`), audio DSP chains in dedicated `AudioWorklet` threads, and parametric animation curves.
3. **Hybrid Edge-AI Inference:** Partitioning AI tasks between real-time client-side neural execution (e.g., Segment Anything 2.1 and Spotify Basic Pitch running directly in the browser via `onnxruntime-web` with WebGPU/WASM) and asynchronous background process orchestration for heavy generative weights (e.g., FLUX.1 Fill, Hunyuan3D-2, Mel-Band Roformer, and Wan 2.1/2.2 via local ComfyUI/sd.cpp/Python daemon endpoints).

This document details the exact technical anatomy, mathematical equations, data structures, and implementation roadmaps required for KesherAI to deliver studio-grade editing capabilities across all four creative disciplines.

## 1. Part A — Picture Editor to Photoshop/Affinity Level: Layers, Masks, and AI Tools

### 1.1 State of the Art: Industry & Web Benchmarks
To elevate KesherAI's image editor (`plugins/image-editor/`) beyond basic raster manipulation, we analyze four industry leaders:
- **Adobe Photoshop (2025/2026):** Sets the gold standard for non-destructive production pipelines. Built around 32-bit floating-point color pipelines, complex layer hierarchy trees, live clipping masks, smart objects, and deep Firefly/Diffusion generative fill integrations.
- **Affinity Photo 2:** Renowned for its unified memory architecture, instantaneous pan/zoom redraws across multi-gigabyte documents, non-destructive live filter layers, and "Personas" that re-contextualize toolbars for photo development, pixel editing, tone mapping, and export.
- **Photopea (Ivan Kutskir):** The definitive browser-based proof-of-concept. Photopea successfully replicates ~90% of Photoshop's desktop capabilities inside standard web browsers. Crucially, Photopea migrated from an initial CPU-bound pixel array architecture to a full **WebGL-accelerated shader pipeline** (v1.3+). This single architectural shift reduced full-canvas recomposition latency from ~850 ms down to ~55 ms for a 10-layer 2048×1152 canvas [4], enabling 60 FPS brush stroking, real-time layer transforms, and instant adjustment previews.
- **Krita & Krita AI Diffusion (Acly):** The premier open-source digital painting suite. Acly's Krita AI Diffusion plugin demonstrates how to bridge an existing professional canvas directly to a local ComfyUI backend [1, 2]. It bypasses manual file management by streaming selections, masks, and layers over local WebSockets/HTTP, providing inpainting, generative outpainting, regional control prompts, and real-time live painting feedback [2].

### 1.2 Core Architecture: Layer Compositing, WebGL Shaders, & 27 Blend Modes
KesherAI's current image editor relies on the 2D Canvas rendering context (`CanvasRenderingContext2D`) and standard `globalCompositeOperation` directives. While straightforward, this creates two severe technical ceilings:
1. **CPU Memory Thrashing:** Reading and writing full image frames requires repeated `getImageData()` and `putImageData()` roundtrips across the CPU-GPU bus, freezing the main UI thread on canvases exceeding 2048×2048 pixels.
2. **Missing Blend Modes:** Standard HTML5 Canvas 2D natively supports only 11 composite operations (`source-over`, `multiply`, `screen`, `overlay`, `darken`, `lighten`, `color-dodge`, `color-burn`, `hard-light`, `soft-light`, `difference`, `exclusion`). The remaining 16 industry-standard blend modes—including Linear Dodge (Add), Linear Burn, Vivid Light, Linear Light, Pin Light, Hard Mix, Subtract, Divide, Hue, Saturation, Color, and Luminosity—cannot be rendered without custom pixel manipulation loops.

#### The Pro Solution: WebGL2 Multi-Pass FBO Compositor
KesherAI must transition its layer rendering pipeline to a multi-pass WebGL2 or WebGPU compositing graph using Framebuffer Objects (FBOs):
- **Layer Data Representation:** Each layer holds an RGBA texture stored on GPU VRAM, accompanied by an affine transform matrix (scale, rotate, translate), opacity ($0.0 - 1.0$), blend mode enum, clipping flag, visibility state, and an optional 8-bit single-channel ($R8$) mask texture.
- **GLSL Fragment Shader Blending:** All 27 blend modes are computed in a single fragment shader pass. For example:
  - *Linear Light:* $f(B, L) = \begin{cases} B + 2L - 1.0 & \text{if } L > 0.5 \\ B + 2L - 1.0 & \text{if } L \le 0.5 \end{cases}$ (clamped to $[0, 1]$).
  - *Vivid Light:* Combines Color Dodge and Color Burn:
    $$f(B, L) = \begin{cases} 1.0 - \frac{1.0 - B}{2(L - 0.5)} & \text{if } L > 0.5 \\ \frac{B}{1.0 - 2L} & \text{if } L \le 0.5 \end{cases}$$
  - *Luminosity / Color:* Requires converting RGB to CIE LAB or HSL within the fragment shader, transferring the $L$ or $C$ components, and converting back to RGB with out-of-gamut chroma clipping.

### 1.3 Masking Systems
Professional photo manipulation relies on four distinct masking paradigms:
1. **Layer Masks (8-bit Grayscale Alpha Channels):**
   - Implemented as an independent single-channel 8-bit texture ($Luminance$) bound to the layer.
   - During shader compositing: $\text{EffectiveAlpha} = \text{PixelAlpha} \times \text{MaskValue} \times \text{LayerOpacity}$.
   - Painting with pure black ($0$) conceals; painting with white ($255$) reveals. Support for mask inversion (Ctrl+I), feathering via separable Gaussian blur shaders, and non-destructive disable/enable toggling.
2. **Clipping Masks (Affinity / Photoshop Hierarchy):**
   - A layer designated as a clipping mask restricts its visible bounds to the composite alpha channel of the layer directly beneath it (or group base).
   - In the compositor pass: $\text{FragmentColor.a} \leftarrow \min(\text{TopLayer.a}, \text{BaseLayerComposite.a})$.
3. **Vector Masks:**
   - Evaluated from SVG/Bézier path objects. Paths are rendered to an offscreen anti-aliased stencil buffer or evaluated in real time using signed distance fields (SDFs).
4. **Luminance Masks:**
   - Dynamically generated from the tonal values of the underlying artwork, splitting the tonal spectrum into Shadows ($0–64$), Midtones ($64–192$), and Highlights ($192–255$) with smooth cosine falloffs.

### 1.4 Selection Engine & Smart Cutouts
A pro editor requires robust selection algebra combined with zero-latency visual feedback:
- **Selection Data Structure:** The selection is not merely a geometric vector path; it is an 8-bit alpha mask ($0–255$) covering the entire document bounds, allowing partial pixel selections (feathered selections).
- **Marching Ants Shader:** The boundary of any non-zero selection alpha is calculated via a Sobel edge-detection filter or contour pass, rendered to an overlay canvas using an animated dash-offset shader ($\Delta t$ phase shift), yielding the classic marching ants effect at 60 FPS without touching CPU memory.
- **Selection Algebra:** Full boolean set operations executed via pixel shaders:
  - *New:* $S_{\text{new}} = S_A$
  - *Add (Shift):* $S_{\text{new}} = \min(1.0, S_{\text{old}} + S_A)$
  - *Subtract (Alt):* $S_{\text{new}} = \max(0.0, S_{\text{old}} - S_A)$
  - *Intersect (Shift+Alt):* $S_{\text{new}} = S_{\text{old}} \times S_A$
- **Smart Tools:**
  - *Magic Wand & Flood Fill:* Fast GPU-based seed filling or BFS queue with Euclidean distance threshold in CIE $L^*a^*b^*$ color space to account for human perceptual color differences ($\Delta E_{76} < \text{tolerance}$).
  - *Segment Anything 2 (SAM 2.1) in Browser via WebGPU:* Integrating Meta's SAM 2.1 (`sam2_hiera_tiny.onnx`) via `onnxruntime-web` [3, 5]. The heavy image encoder runs once upon image load on the WebGPU device (taking ~250–500 ms on an RTX 3060/4060), caching the high-dimensional image embeddings [3]. When the user hovers or clicks positive/negative points, the lightweight SAM decoder executes in $<15\text{ ms}$, producing crisp interactive segmentation masks in real time directly inside the browser sandbox [3, 5].

### 1.5 Non-Destructive Adjustment Layers
Unlike destructive filters that permanently mutate pixel buffers, adjustment layers act as procedural modifiers affecting all composite pixels below them:
- **Curves & Levels:** Evaluated via a 256-element 1D lookup texture ($R8$) uploaded to the GPU. For Curves, user-defined control points are interpolated using monotonic cubic Catmull-Rom splines, generating a discrete transfer curve for RGB composite and individual R, G, B channels. The fragment shader reads: $\text{color.r} = \text{texture1D}(\text{curveLUT}, \text{color.r})\text{.r}$.
- **HSL Adjustment:** Converts input RGB to cylinder HSL coordinates, applies offsets ($\Delta H, \Delta S, \Delta L$), and converts back to RGB.
- **3D LUT (.cube) Support:** Loads standard 3D color cube files ($33\times 33\times 33$ or $64\times 64\times 64$) into a 3D WebGL texture (`TEXTURE_3D`), enabling cinematic color grading and tone reproduction in a single shader cycle via trilinear filtering.

### 1.6 High-Performance Brush Engine
- **Pointer Events API Integration:** Full support for graphics tablets (Wacom, Apple Pencil via Sidecar/iPad, Surface Pen) utilizing `e.pressure`, `e.tiltX`, `e.tiltY`, and `e.pointerType`.
- **Stroke Interpolation & Spacing:** Raw mouse/pointer move events arrive intermittently (typically 60–120 Hz). To prevent "dotted" artifacts during rapid mouse flicks, the engine interpolates intermediate stamps along the motion vector using cubic Bézier splines, placing circular/textured stamps at a constant distance:
  $$\Delta d = \text{diameter} \times \text{spacingPercentage}$$
- **Brush Dynamics:** Procedural jitter algorithms mapping pressure and speed to diameter ($d = d_{\text{base}} \times \text{pressure}$), opacity, hardness falloff, and angle scatter.
- **LazyMouse / Stabilizer:** A virtual trailing leash algorithm that smooths hand jitter by computing moving exponential smoothing over the last $K$ pointer coordinates:
  $$P_{\text{smooth}} = P_{t-1} + (P_t - P_{t-1}) \times \alpha$$

### 1.7 Local AI Integration: Generative Fill, Object Removal, & Matting
KesherAI's core strength is local model execution without cloud dependencies:
1. **Generative Fill (FLUX.1 Fill / SDXL Inpainting):**
   - The selected canvas region and feathered mask are extracted. An expanded context bounding box (padding by 25–50% to provide surrounding visual context) is cropped and sent via local WebSocket/HTTP to KesherAI's local inference engine (sd.cpp or ComfyUI).
   - The model generates the infilled content; the resulting patch is seamlessly blended back into the canvas using Poisson image blending or soft-feathered edge compositing on a new layer.
2. **Object Removal (LaMa ONNX):**
   - For fast, zero-prompt object cleanup ("eraser" behavior), KesherAI integrates **LaMa (Large Mask Inpainting)** exported to ONNX Runtime. Running locally on the PC GPU, LaMa resolves masked defects in under 80 ms, automatically synthesizing high-frequency background textures without requiring complex text prompting.
3. **Background Removal (RMBG 2.0 / BiRefNet):**
   - KesherAI incorporates BRIA AI's **RMBG-2.0**, powered by the BiRefNet architecture [6, 9]. Processing at $1024\times 1024$ input resolution with standard ImageNet normalization, it generates studio-quality alpha mattes that capture microscopic hair strands, fur, and semi-transparent glass with zero user guidance [6, 9].
4. **Relighting (IC-Light / IC-Light v2):**
   - Implements Lvmin Zhang's IC-Light (Imposing Consistent Light) architecture via ComfyUI nodes, allowing users to apply synthetic directional rim lighting, studio softboxes, or ambient background light matching directly onto isolated subject layers.
5. **Super-Resolution (Real-ESRGAN / Compact):**
   - Real-ESRGAN-x4plus and compact architectures integrated via local ONNX or Vulkan/NCNN binaries, executing non-blurry $4\times$ canvas enlargements.

## 2. Part B — 3D Editor to Blender/Max/Maya Level: Modifiers, Rigging, Animation

### 2.1 State of the Art: Professional Workflows vs Web Three.js Editors
Professional DCC tools (**Blender 4.x/4.5**, **Autodesk 3ds Max 2026**, **Maya 2026**) are characterized by non-destructive procedural pipelines, precise topology management, complex deformation rigs, and curve-based keyframe graphs:
- **3ds Max 2026:** Master of the procedural stack. The Modifier Stack allows arbitrary stacking of Booleans, Smart Extrude, Chamfer, and UVW Map with full parametric history [12, 13].
- **Blender 4.5:** The open-source powerhouse. Features Geometry Nodes, Catmull-Clark subdivision, Dyntopo sculpting, interactive UV packing, and the grease pencil/animation dope sheet [14].
- **Nomad Sculpt & SculptGL:** Stéphane Ginier proved that high-performance digital sculpting with dynamic topology (Dyntopo) and multiresolution subdivision can run at 60 FPS in WebGL and mobile browsers using custom half-edge representations and spatial octrees [15, 16].
- **Spline & Meshy Studio:** Modern web-first 3D applications demonstrating clean Outliner trees, material inspectors, version history strips, and direct text/image-to-3D model generation.

KesherAI currently has a three.js (0.181) editor plugin (`plugins/model-editor/`) with an Outliner tree, Channel Box transform panel, basic transform gizmo, rudimentary Mirror/Array/Smooth shading modifiers, and external texture editing round-trips. To reach DCC level, it must implement a robust non-destructive modifier stack, automated UV workflows, real-time vertex sculpting, bone rigging with skin weights, and keyframe animation tracks.

### 2.2 Scene Graph & Non-Destructive Modifier Stack
In professional DCCs, modifiers do not alter the base mesh topology in-place; they form a directed acyclic evaluation chain:
$$\text{BaseGeometry} \longrightarrow M_1 \longrightarrow M_2 \longrightarrow \dots \longrightarrow M_k \longrightarrow \text{EvaluatedRenderMesh}$$

Each modifier maintains an enabled state, viewport visibility toggle, and serializable parameters. When any parameter changes or the user edits the underlying base cage, the stack re-evaluates downstream nodes:

```typescript
export interface Modifier {
  id: string;
  type: 'boolean' | 'subdivide' | 'bevel' | 'mirror' | 'array' | 'decimate';
  enabled: boolean;
  params: Record<string, any>;
  apply(input: THREE.BufferGeometry): THREE.BufferGeometry;
}
```

#### The Boolean Dilemma: `three-bvh-csg` vs `manifold-3d` (WASM)
CSG Booleans (Union, Difference, Intersection) are the foundation of hard-surface modeling. Research reveals a fundamental divergence between two modern solutions:
1. **`three-bvh-csg` (Pure JavaScript BSP):**
   - Leverages `three-mesh-bvh` bounding volume hierarchies [10].
   - *Advantages:* Pure JS, zero external WASM binaries, fast execution for simple geometries in interactive UI configurators [11].
   - *Failure Modes:* Highly vulnerable to floating-point imprecision. When cutting co-planar faces or slightly non-manifold geometry, it frequently outputs degenerate triangles, open holes, or complete operation failure [10, 11].
2. **`manifold-3d` (Google / Emscripten WASM CAD Kernel):**
   - Originally written in C++ by Emmett Lalish and compiled to WebAssembly [17, 18].
   - *Advantages:* **Guaranteed watertight manifold output.** It handles coplanar faces, self-intersecting meshes, and millions of polygons with absolute topological safety. It is crash-proof and CAD-grade [17, 19].
   - *Recommendation for KesherAI:* Adopt **`manifold-3d` (WASM)** as the primary evaluation kernel for the Boolean modifier, ensuring models remain strictly valid for 3D printing and game engine import (Unreal/Unity).

#### Other Essential Modifiers
- **Subdivision Surface (Subsurf):** Implementation of the **Catmull-Clark** subdivision algorithm. Evaluates quad-dominant faces, adding smoothed edge vertices and face centers, yielding smooth organic surfaces from low-poly control cages.
- **Bevel / Chamfer:** Inserts edge loops along sharp boundaries (angle threshold $> 30^\circ$), chamfering hard edges with configurable segments and profile curvature ($0.5 = \text{circular}$).
- **Array Modifier:** Duplicates the geometry $N$ times with fixed relative offsets $(\Delta X, \Delta Y, \Delta Z)$, rotational steps, or radial distribution around an empty pivot.
- **Mirror Modifier:** Clones geometry across the X, Y, or Z plane with automated vertex merging along the symmetry seam (weld threshold $\epsilon \approx 0.001\text{ m}$).
- **Decimate / LOD:** Simplifies dense meshes down to target triangle budgets (e.g. 10%, 25%, 50%) using the Quadric Error Metric (QEM) simplification algorithm (`meshoptimizer` / `SimplifyModifier`), preserving silhouette edges and UV seams.

### 2.3 UV Unwrapping & UV Canvas
Textures cannot be applied accurately without clean UV coordinates. KesherAI must provide both automatic parameterization and interactive 2D editing:
- **WASM-Powered Auto-UV (`watlas` / `xAtlas-three`):**
  - Ports the industry-standard C++ `xatlas` library to WebAssembly [20, 21].
  - Executed inside a Web Worker to prevent UI freezes:
    1. *Chart Segmentation:* Partitions the 3D surface into developable topological charts based on normal dihedral angles.
    2. *Parameterization:* Computes 2D flat coordinates via Least Squares Conformal Mapping (LSCM) or Angle-Based Flattening (ABF++), minimizing area and angular distortion.
    3. *Chart Packing:* Packs all charts into a unit $[0, 1] \times [0, 1]$ square with configurable gutter padding (e.g., 4 px margin) to prevent mipmap texture bleeding [21, 22].
- **2D UV Canvas Editor:**
  - A split-view 2D viewport displaying the unwrapped UV island polygons over the active texture map.
  - Tools: Seam Marking (marking edges in 3D that split upon unwrap), Island Translation/Rotation/Scale, UV Pinning, and Island Packing.
- **Bridge to Image Editor:**
  - KesherAI's existing bridge (*Edit in the image editor*) sends the 3D part's texture. The enhanced pipeline automatically injects a top non-printable semi-transparent layer containing the wireframe UV contours, allowing the user to paint directly over texture islands, then saves the result back into the 3D scene's PBR material (`map`, `roughnessMap`, `metalnessMap`, `normalMap`).

### 2.4 Real-Time Sculpting Engine
Following Stéphane Ginier's **SculptGL** and **Nomad Sculpt** architecture [15, 16]:
- **Dynamic Topology (Dyntopo):**
  - While standard sculpting deforms existing vertices (causing polygons to stretch and tear when pulling long horns or deep creases), Dyntopo dynamically tessellates the mesh under the brush footprint [15].
  - *Edge Splitting:* If an edge within the brush radius exceeds the maximum detail threshold $L_{\max}$, it splits into two, inserting new vertices and triangles.
  - *Edge Collapsing:* If triangles become smaller than $L_{\min}$, edges collapse, pruning redundant polygon density.
- **Core Sculpt Brushes:**
  1. *Grab / Move:* Pulls all vertices within sphere radius $R$ along the 2D cursor drag vector projected onto the tangent plane.
  2. *Smooth:* Applies iterative Laplacian smoothing, shifting each vertex toward the centroid of its 1-ring neighbor vertices:
     $$V_{\text{new}} = V_{\text{old}} + \lambda \sum_{j \in N(i)} (V_j - V_{\text{old}})$$
  3. *Inflate / Deflate:* Displaces vertices along their interpolated vertex normals: $V \leftarrow V + (\mathbf{n} \cdot \text{strength} \cdot f(d/R))$.
  4. *Clay / Flatten:* Displaces vertices toward an average local planar cap, simulating physical clay deposition.
- **Spatial Indexing & Threading:**
  - Uses a loose spatial Octree to perform localized spatial bounding box queries in $<2\text{ ms}$, restricting vertex updates strictly to triangles intersecting the brush sphere.

### 2.5 Rigging, Skinning, & Inverse Kinematics
To enable game-ready character posing and animation, KesherAI requires full skeletal deformation:
- **Bone Hierarchy & Armature:**
  - Constructed using Three.js `THREE.Bone` nodes structured into an articulated kinematic tree (e.g. `Hips -> Spine -> Chest -> Neck -> Head`).
  - Each bone stores its local transform, rest pose inverse bind matrix (`bindMatrixInverse`), and reference world matrix.
- **Linear Blend Skinning (LBS):**
  - Geometry is encapsulated in a `THREE.SkinnedMesh`.
  - Every vertex possesses two vec4 buffer attributes:
    - `skinIndex`: indices of the 4 influencing bones.
    - `skinWeight`: weights of the 4 influencing bones, strictly normalized such that $\sum_{i=1}^4 w_i = 1.0$.
  - In the vertex shader:
    $$V_{\text{skinned}} = \sum_{i=1}^4 w_i \cdot \mathbf{M}_i \cdot \mathbf{B}_i^{-1} \cdot V_{\text{bind}}$$
- **Automatic Weights (Voxel Heat Diffusion):**
  - Automatic skinning using geodesic voxel binding. The character mesh is voxelized; heat diffusion equations are propagated from each bone segment through the interior volume, assigning smooth, naturally decaying weights to surrounding surface vertices without manual painting.
- **Inverse Kinematics (IK Solver):**
  - Posing characters by rotating individual joints (Forward Kinematics) is tedious. KesherAI integrates **CCDIKSolver** (Cyclic Coordinate Descent) and FABRIK (Forward And Backward Reaching Inverse Kinematics).
  - Pinned IK Targets on hands and feet allow the user to grab a character's hand and drag it in 3D space; the solver automatically computes joint rotations for the wrist, elbow, and shoulder in real time.

### 2.6 Keyframe Animation & glTF Export
- **Animation Track Data Structure:**
  - Evaluated using Three.js `THREE.AnimationClip` containing discrete tracks:
    - `THREE.VectorKeyframeTrack` (Position / Translation)
    - `THREE.QuaternionKeyframeTrack` (Rotation, interpolated via Spherical Linear Interpolation / SLERP)
    - `THREE.NumberKeyframeTrack` (Morph Targets / Shape Keys for facial expressions)
- **Timeline & Dope Sheet UI:**
  - Displays a global playhead, time ruler (frames/seconds), play/pause transport, loop modes, and diamond keyframe markers per channel.
  - Curve Editor view: Editable Bézier tangents for velocity and acceleration curves (ease-in, ease-out, linear, constant).
- **Universal glTF 2.0 / GLB Export:**
  - Uses Three.js `GLTFExporter` with binary output (`.glb`).
  - Serializes the entire asset: clean polygonal geometry, PBR materials, embedded textures, armature bone trees, skin weights, animations, and blend shapes into an engine-agnostic asset importable directly into Unreal Engine 5, Unity 6, Godot 4, or Blender.

### 2.7 Local AI 3D Pipelines

## 3. Part C — Sound Editor to DAW Level: Instruments, Hum to Instrument, Mixing

### 3.1 State of the Art: DAW Paradigms
Professional Digital Audio Workstations (**Reaper 7**, **Ableton Live 12**, **FL Studio 24**, **Logic Pro 11.2**, **BandLab**) are built upon three core operational requirements:
1. **Zero-Dropout Audio Scheduling:** Ensuring audio never glitches or crackles regardless of UI rendering load or background processing.
2. **Flexible Multitrack Routing:** Supporting arbitrary combinations of audio tracks, MIDI virtual instrument tracks, auxiliary effect sends, and sub-mix buses routed to a master fader.
3. **Expressive Pitch & Timbre Manipulation:** Capturing acoustic voice input (humming, singing, beatboxing) and accurately translating it into quantized musical notation or transformed instrument timbres [32, 33].

KesherAI currently features a basic single-track audio editor (`plugins/sound-editor/`) capable of waveform trimming, whisper speech transcription, and primitive monophonic YIN pitch tracking with static SoundFont samples. To become a true web-native DAW, KesherAI must re-architect its audio engine around the `AudioWorklet` standard, multitrack timeline routing, polyphonic pitch tracking, studio DSP effects, and local neural stem separation.

### 3.2 Web Audio Engine Architecture: AudioWorklet & Low-Latency Threading
The standard Web Audio API `ScriptProcessorNode` is completely deprecated and unusable for pro audio because it executes on the browser's main UI thread, causing severe audio dropouts whenever the DOM renders or garbage collection triggers.

#### Pro Architecture: Dedicated `AudioWorklet` Processors
KesherAI must run all synthesis, mixing, and DSP within a dedicated **`AudioWorklet` thread**:
- **Real-Time Render Quantum:** The browser's audio subsystem invokes the worklet's `process(inputs, outputs, parameters)` callback strictly every 128 audio samples (~2.9 ms at 44.1 kHz, ~2.6 ms at 48 kHz).
- **Zero-Allocation Audio Loops:** The DSP callback must never allocate JavaScript objects (`new Float32Array`) or trigger garbage collection. All buffers, circular delay lines, and filter states are pre-allocated during initialization.
- **Lock-Free IPC via SharedArrayBuffer:** Communication between the React UI timeline and the audio rendering thread utilizes `SharedArrayBuffer` with `Atomics` or lock-free ring buffers (SPSC - Single Producer Single Consumer queues). The UI pushes playback commands and parameter changes without ever pausing the audio hardware clock:


### 3.3 Multitrack Timeline & Automation Envelopes
A DAW requires concurrent playback and processing of multiple independent audio and MIDI channels:
- **Track Types:**

  - *MIDI / Instrument Tracks:* Sequence time-stamped MIDI events (Note On, Note Off, Velocity, Pitch Bend, CC values) routed into virtual instrument synths or soundfonts.
  - *Aux / Bus Tracks:* Receive audio sent from multiple channel strips (e.g., Drum Bus, Vocal Reverb Send).
  - *Master Bus:* Master fader with final stereo limiter and True Peak meter.
- **Non-Destructive Clip Editing:**
  - Equal-power crossfading at clip boundaries to eliminate audio pops and clicks:
    $$\text{Gain}_{\text{fade-out}}(t) = \cos\left(\frac{\pi t}{2}\right), \quad \text{Gain}_{\text{fade-in}}(t) = \sin\left(\frac{\pi t}{2}\right)$$
- **Parametric Automation Envelopes:**
  - Every track exposes sub-lanes for parameter automation (Track Volume, Stereo Pan, Filter Cutoff). Control points are interpolated smoothly using `AudioParam.setValueCurveAtTime()` or cubic Hermite spline interpolation directly inside the AudioWorklet.

### 3.5 Hum/Whistle to Instrument: Pitch Tracking to MIDI & Timbre Transfer
Turning vocal humming or whistling into expressive musical instruments is one of KesherAI's flagship capabilities. Doing this at a pro level requires two distinct technical paths:

#### 1. Audio to MIDI: Spotify Basic Pitch vs Monophonic YIN
- **Monophonic YIN / CREPE:**
  - For rapid, low-latency monophonic vocal tracking (a clean whistle or single hummed note), the YIN autocorrelation algorithm computes exact pitch fundamental frequencies ($F_0$) in $<10\text{ ms}$.
- **Spotify Basic Pitch (`@spotify/basic-pitch`):**
  - For complex, polyphonic vocal lines, guitar strumming, or beatboxing, KesherAI integrates Spotify's open-source **Basic Pitch** neural network [34, 35].
  - *Key Engineering Requirement:* Basic Pitch operates strictly at a **22,050 Hz** internal sample rate [34, 37]. 
  - *Implementation:* When a recorded audio clip is selected, KesherAI resamples the `AudioBuffer` to 22.05 kHz using an `OfflineAudioContext`, and offloads the tensor inference to a **Web Worker** running `@spotify/basic-pitch-ts` [34, 36].
  - *Output:* Basic Pitch outputs note start times, durations, amplitudes, and—crucially—**continuous pitch bend arrays** [35, 38]. These pitch bends are mapped directly into MIDI pitch wheel automation, preserving natural vocal vibratos, slurs, and microtonal inflections when played back by virtual guitars or violins [38].
- **Key Detection & Musical Quantization:**
  - Automatically identifies the musical key and scale (C Major, A Minor, Pentatonic) using the **Krumhansl-Schmuckler pitch-class profile correlation algorithm**.
  - Provides a single-click "Snap to Key" and "Quantize to Beat" (1/8, 1/16, triplets) slider.

#### 2. Neural Timbre Transfer (DDSP)
- Rather than quantizing audio into MIDI notes and triggering a synthesizer, Google Magenta's **DDSP (Differentiable Digital Signal Processing)** takes the user's raw vocal audio pitch and loudness envelopes to directly drive a neural synthesizer. The resulting violin, saxophone, or flute performance retains 100% of the user's natural breathing dynamics, slides, and vibrato.

3. **Convolution Reverb:**

4. **Stereo Ping-Pong Delay:**

### 4.2 WebCodecs & WebGL Multitrack Video Pipeline
Standard HTML `<video>` elements are incapable of powering a professional multi-track timeline: they suffer from non-deterministic seek latencies ($100–300\text{ ms}$), lack frame-accurate stepping, and cannot synchronize multiple overlapping video tracks without severe stutter.

#### Pro Architecture: WebCodecs + WebGL2 Compositor
KesherAI must utilize the **WebCodecs API** (`VideoDecoder`, `VideoFrame`) available natively in modern Chromium and Electron [44, 45]:
1. **Container Demuxing:** The video file container (MP4, WebM, MOV) is demuxed in JavaScript using `mp4box.js` or native Electron worker streams into discrete encoded video chunks (`EncodedVideoChunk`).
2. **Hardware Video Decoding:** Chunks are submitted to `VideoDecoder`. Hardware-accelerated GPU decoders output zero-copy `VideoFrame` instances directly in GPU memory [44, 47].
3. **Zero-Copy WebGL Texture Upload:**
   - Rather than reading pixels back to CPU memory, the `VideoFrame` is uploaded directly to a WebGL2 texture via:
     `gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, videoFrame);`
   - Frames are rendered to screen at 60 FPS with frame-accurate precision ($\pm 0$ dropped frames) [45, 47].
4. **Dual Preview vs Render Pipeline:**
   - *Viewport Preview:* Real-time playback and scrubbing executed entirely inside the browser via WebCodecs and WebGL shaders.
   - *Final Production Export:* Handed off to KesherAI's local **FFmpeg** binary (`child_process.spawn('ffmpeg')`), assembling the exact edit decision list (EDL) with GPU acceleration (`h264_nvenc`, `hevc_nvenc`, or Apple Silicon `h264_videotoolbox`), guaranteeing mathematically lossless frame-accurate export.

### 4.3 Keyframing & Animation System
Professional motion graphics and video editing require animating clip transform properties over time:
- **Animatable Properties:** Position $(X, Y)$, Scale $(S_x, S_y)$, Rotation Angle ($\theta$), Opacity ($\alpha$), Crop Margins (Top, Bottom, Left, Right), and Audio Volume.
- **Keyframe Data Structure:**
  ```typescript
  export interface Keyframe<T> {
    time: number;          // Presentation timestamp in seconds
    value: T;              // Numeric or vector value
    interpolation: 'linear' | 'hold' | 'bezier';
    tangentIn?: [number, number];   // Normalized Bézier control handle
    tangentOut?: [number, number];  // Normalized Bézier control handle
  }
  ```
- **Bézier Tangent Interpolation:**
  Between two keyframes $(t_0, v_0)$ and $(t_1, v_1)$, the normalized progress $s = \frac{t - t_0}{t_1 - t_0}$ is mapped through a cubic Bézier polynomial curve:
  $$B(s) = (1-s)^3 P_0 + 3(1-s)^2 s P_1 + 3(1-s) s^2 P_2 + s^3 P_3$$
  This enables smooth kinematic motion: gentle ease-in, energetic ease-out, elastic bounces, and linear speed ramps.
- **Spatial vs Temporal Decoupling:**
  Separates the spatial motion path (the 2D curve a clip travels across the screen) from its temporal speed curve (how fast it moves along that path).

### 4.4 Shaders, Transitions, & Colour Grading
1. **Lift / Gamma / Gain (3-Way Color Wheels):**
   - The cornerstone of cinematic color grading (DaVinci Resolve style). Evaluated per-pixel in a WebGL fragment shader:
     - *Lift (Shadows):* Adjusts the black level and shadow tones.
     - *Gamma (Midtones):* Controls the power-law curvature of midtones without clipping blacks or whites.
     - *Gain (Highlights):* Multiplies the overall signal, primarily affecting highlights.
     - *Mathematical formulation:*
       $$C_{\text{out}} = \text{Gain} \times \left( C_{\text{in}} \times (1 - \text{Lift}) + \text{Lift} \right)^{\frac{1}{\text{Gamma}}}$$
2. **3D LUT Loader (.cube Format):**
   - Reads standard Hollywood `.cube` lookup tables ($33\times 33\times 33$ or $64\times 64\times 64$).
   - Uploaded to a 3D WebGL texture (`TEXTURE_3D`). During shader execution, `texture(lut3D, inputColor.rgb)` applies cinematic film emulation (e.g. Kodak 2383, Teal & Orange) in a single GPU cycle via hardware trilinear interpolation.
3. **GL Transitions Library:**
   - Integrates the open-source **`gl-transitions`** shader library [2, 46]. Over 80 professional transitions (Crossfade, Directional Wipe, Radial Blur, Page Curl, Glitch, Whip Pan, Doorway) executed by feeding outgoing texture $A$, incoming texture $B$, and transition progress $p \in [0.0, 1.0]$ into a fragment shader [2, 46].

### 4.5 Titles, Motion Graphics, & RTL/Hebrew Typography
Typography in video editing is notoriously fragile, especially when handling right-to-left (RTL) languages like Hebrew:
- **The Hebrew Bidirectional (Bidi) Engine:**
  - Standard Canvas/WebGL text rendering reverses Hebrew punctuation, scrambles numbers, and corrupts mixed-language text strings (e.g. Hebrew sentences containing English names or timestamps).
  - KesherAI integrates the **Unicode Bidirectional Algorithm (UAX #9)** via `bidi-js` and the native JavaScript `Intl.Segmenter` API. Glyphs are resolved into visual order before being rendered onto texture canvases, guaranteeing flawless rendering of mixed Hebrew-English titles and subtitles.
- **Title Styling & Kinetic Motion:**
  - Rich text formatting: Custom typography, fill color, outline stroke with thickness, drop shadow with blur/offset, and solid/translucent background pill boxes.
  - Motion templates: Fade-in, typewriter letter reveal, upward slide, and animated lower-third banners.

### 4.6 Intelligent Audio Ducking (Sidechain Envelope Follower)
In professional content creation, background music must automatically lower its volume whenever speech occurs:
- **Implementation Algorithm:**
  1. *Voice Activity Detection:* The speech track (Track A1) is analyzed using RMS energy thresholding or Whisper speech segment timestamps.
  2. *Envelope Generation:* When speech is present ($E_{\text{speech}} > \text{Threshold}$), a ducking envelope $D(t)$ drops from $1.0$ ($0\text{ dB}$) down to target attenuation (typically $-12\text{ dB}$ to $-18\text{ dB}$, or $0.25–0.12$).
  3. *Attack & Release Smoothing:*
     $$\text{Gain}_{\text{music}}(t) = \text{Gain}_{\text{music}}(t-1) + \alpha \cdot (D(t) - \text{Gain}_{\text{music}}(t-1))$$
     where $\alpha_{\text{attack}}$ ramps down smoothly in $\sim 150\text{ ms}$, and $\alpha_{\text{release}}$ recovers background music volume over $\sim 800–1200\text{ ms}$ once speech concludes, preventing jarring volume jumps.
