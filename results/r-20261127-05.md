# Working with a Local AI App from Inside the Claude App

**Summary**  
KesherAI can expose its local MCP server to the Claude interface through three complementary paths: (1) **MCP Apps** — interactive `ui://` HTML views rendered inline in any Claude client that supports them, declared via `_meta.ui.resourceUri`; (2) **Claude Desktop extensions** (`.mcpb`, formerly `.dxt`) — one-click installable bundles that package a local stdio server with manifest, signing, and auto-update; (3) **Custom connectors** on a remote Cloudflare Worker — OAuth-protected, owner-only, free on paid Claude plans. The best “work from Claude” experience combines a small, search-driven toolset with task boards, approval dialogs, model-job previews (image/audio/video), chat browsers, and quota dashboards — all behind owner-only auth and explicit approvals. Core costs are zero for local stdio + Cloudflare free tier + custom connectors on paid Claude; only verified directory listings or org-gated UI capabilities (side panel, entry points, embedded sites) require paid/verified tiers.

## 1. MCP Apps — Interactive `ui://` Views Inside the Conversation

**What they are**  
An MCP App is an interactive HTML view that the MCP server returns as a `ui://` resource; the Claude app renders it inline (or in a side panel / full screen) inside the chat. The view can contain buttons, forms, live-updating charts, iframes embedding the developer’s own website, and can send messages back to Claude or register **app tools** that let Claude mutate the view (e.g., filter a list, select rows) [1].

**Declared via**  
`_meta.ui.resourceUri` on the tool result (the MCP Apps SDK handles this). The server must be reachable as a **remote connector** for app tools, entry points, and embedded websites to work [1].

**Capabilities (what the view can do)**  
- Side panel / full-screen modes  
- Entry points: open from the Artifacts page, pin to sidebar  
- App tools: Claude calls tools that update the view (sort, filter, select)  
- Messages: view → Claude (e.g., “user clicked Approve, here’s the payload”)  
- Embedded websites: `<iframe>` loading the product’s editor/dashboard  
- Downloads: save a file from the view to the user’s device [1]

**Limits & sandbox**  
- CSP / sandbox applies; no arbitrary script execution outside the view  
- Size: practical bundle ≤ few MB (loaded over the connector)  
- **Organization access required** for side panel, entry points, app tools, embedded sites in custom connectors — not every org has it [1]  
- **Verified listing** required for directory connectors to get entry points / embedded sites; Community listings don’t get them even if they worked in custom-connector testing [1]

**Which Claude clients render them**  
- **Claude Desktop**: runs example servers locally via `npx` (stdio) and renders MCP Apps inline [1]  
- **Web (claude.ai)**: renders when the connector is remote (Worker/tunnel)  
- **Mobile**: not explicitly documented; assume web parity if the connector is remote, but no first-party confirmation in sources

**Products shipping MCP Apps (examples from the official repo)**  
| Example | What it does |  
|---------|--------------|  
| Customer Segmentation | Scatter charts + clustering analysis |  
| Map | Interactive 3D globe (CesiumJS) |  
| ShaderToy | Real-time GLSL shader compilation & display |  
| Sheet Music | ABC notation rendering with audio playback [1] |  

**What’s unknown**  
- Exact CSP directives, max bundle size, mobile rendering matrix, and whether phone clients support side panel / entry points.

## 2. Claude Desktop Extensions (`.mcpb` / former `.dxt`)

**One-click install of a local MCP server**  
A `.mcpb` bundle packages the server binary/scripts, a `manifest.json` (name, version, tools, permissions), and optionally a signature. The user drags the file onto Claude Desktop → installs in one click, no manual `claude_desktop_config.json` editing [2][3].

**Manifest & packaging**  
- `manifest.json` declares tools, required permissions (file system, network), and entry points  
- Products like **Notion, Figma, Blender, Unity, Unreal** ship bridges as `.mcpb` so users get “Ask Notion / Figma / Blender” tools instantly [3]  
- Signing: not strictly required for local installs, but recommended for distribution; auto-update via signed manifests [3]

**Updates**  
- Signed bundles can check for updates on startup; unsigned require re-drag [3]

**Claude Code plugins / marketplaces**  
- Separate ecosystem: VS Code / JetBrains extensions that register MCP servers for the **Claude Code** agent (terminal-based). Not the same as Desktop extensions, but another distribution route for developer-facing tools [3][4].

**What’s unknown**  
- Exact manifest schema, signing key format, update server protocol, and whether `.mcpb` can declare MCP App views (likely yes if the bundled server serves them over stdio + tunnel).

## 3. Recommended Tool / View Set for “Work from Claude” (KesherAI Profile)

**Goal**: keep the tool list small so Claude picks the right one; use **toolsets / search** to fan out.

| Category | Tools (few, high-leverage) | MCP App Views (inline UI) | Auth / Safety |
|----------|----------------------------|---------------------------|---------------|
| **Task board** | `list_tasks`, `create_task`, `update_task` | Kanban board (drag-drop → `update_task` via app tool) | Owner only; write actions need approval |
| **Approvals** | `request_approval`, `list_pending` | Modal dialog with Approve/Reject buttons → sends message to Claude | No secrets in output; only owner sees |
| **Model jobs** (image/music/video) | `generate_image`, `generate_audio`, `generate_video`, `job_status` | Preview gallery with play/Download; live progress bar | Owner only; quota-checked |
| **Chats** | `list_chats`, `read_chat`, `search_chats` | Chat browser with inline render of artifacts | Owner only |
| **Quotas / usage** | `get_quotas` | Dashboard (tokens, GPU sec, storage) | Read-only |
| **Design previews** | `render_design` (Figma-like) | Embedded iframe of KesherAI design editor | Owner only; iframe sandboxed |

**Keeping the tool list small**  
- Expose **one search tool** (`search_all`) that routes to the right domain  
- Use **toolsets** (MCP feature) to group tools by capability; Claude sees only the active set [4]  
- Register **app tools** on views so Claude can drive the UI without new chat tools [1]

**Auth & safety**  
- Custom connector = OAuth (owner only) [1][KesherAI context]  
- Local stdio server = no network exposure; approvals enforced in the local server  
- Never return secrets/API keys in tool output; views fetch only display data [1][2]

## 4. Cost Table

| Component | Free tier | Paid / gated |
|-----------|-----------|--------------|
| **Local stdio server** (Electron + Node) | ✅ Free — runs on user’s machine | — |
| **Cloudflare Worker** (remote MCP server / OAuth) | ✅ Free tier (100k req/day, 10ms CPU) | Paid Workers plan if exceeded |
| **Custom connector** (owner-only, on claude.ai) | ✅ Free on **paid Claude plans** (Pro/Team/Enterprise) | Not available on Free plan [1] |
| **MCP App views** (inline, side panel, entry points, embedded sites) | ✅ In custom connector *if org has access* | Org access + Verified listing for directory distribution [1] |
| **Desktop extension (`.mcpb`)** | ✅ Free to build & distribute | — |
| **Verified directory listing** | ❌ | Requires Anthropic review + paid/verified status [1] |
| **Claude Code marketplace** | ✅ Free to publish | — |

**Bottom line**: KesherAI’s owner-only, local-first architecture fits entirely in the **free column** (local stdio + Cloudflare free tier + custom connector on the owner’s paid Claude plan). Only if KesherAI wants *other users* to install via the directory with side-panel/entry-point/iframe features does it need a Verified listing.

## 5. Language and Weight

| Dimension | Recommendation |
|-----------|----------------|
| **Worker vs. local server** | Keep the **local stdio server** as the source of truth (models, knowledge, GPU). The Cloudflare Worker is only a thin OAuth + proxy layer for the custom connector; it forwards tool calls to the local server via a secure tunnel (Cloudflare Tunnel or `ngrok` during dev). |
| **View bundle size** | Target **< 2 MB gzipped** (JS + CSS + WASM if any). Load via the Worker (static assets on R2 / Pages) so the `ui://` resource is fast on all clients. |
| **Every platform incl. phone** | - Desktop: full MCP App support (side panel, entry points) via custom connector + local tunnel [1]  <br>- Web: same, no tunnel needed once Worker is live  <br>- Mobile: unconfirmed; assume web parity for inline views, but side panel / entry points may not render. Test early. |
| **Language** | TypeScript end-to-end (Worker, local server, MCP App SDK). Share types via a `packages/shared` workspace. |

## Conclusion

KesherAI can deliver a **first-class “work from Claude” experience today** without waiting for directory approval: ship a `.mcpb` Desktop extension for one-click local install, run a Cloudflare Worker as a custom connector (OAuth, owner-only) for web/phone access, and build MCP App views for task boards, approvals, model-job previews, chat browsers, and quota dashboards. The tool surface stays tiny via `search_all` + toolsets; safety comes from local enforcement, approvals, and zero-secret tool outputs. All core pieces run on free tiers (local stdio, Cloudflare free, custom connector on the owner’s paid Claude plan). The only unknowns are mobile MCP App rendering fidelity and the exact org-access gating for side-panel/entry-point/iframe features — both testable in a day.
