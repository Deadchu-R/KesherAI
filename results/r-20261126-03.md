## Research report
# Research Report: Optimization and Language Selection for KesherAI Components

This report details the architectural and language evaluation for every component of KesherAI to achieve maximum speed and minimal RAM/CPU consumption on a Windows PC equipped with an RTX 3090, Ryzen 9 9950X3D, and 24GB+ VRAM, without undertaking a full rewrite. Findings are structured around component themes, accompanied by a ranked shortlist and concrete future tasks.

---

## 1. Application Shells & UIs

| Component | Current Language | Bound Type | Alternative Language & Expected Gain | Cost & Complexity | Similar Open-Source Examples |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`apps/desktop`** | TypeScript / Electron | RAM / I/O | Tauri / Rust (Sidecar or native view). Minimal speed gain for UI, but saves ~300-500MB RAM over Chromium/Electron. | **High cost**: Full rewrite of desktop container. **Windows**: Good. **AI Agent Skill**: High. | VS Code, Obsidian, Ollama desktop |
| **`apps/web`** | TypeScript / React | CPU (DOM/Render) | Rust / WASM or SolidJS. Minor speed gain for rendering loops. | **High cost**: Rewriting UI framework. **Windows**: N/A (browser). **AI Agent Skill**: High. | OpenUI (found that keeping parsing in TS avoided WASM boundary tax) [1] |
| **`apps/android`** | TypeScript / React Native | CPU / RAM | Native Kotlin/Swift or Rust via UniFFI. Minimal benefit for UI glue. | **High cost**: High platform complexity. **Windows**: N/A. **AI Agent Skill**: Medium. | Expo-based mobile applications |
| **`apps/hub`** | TypeScript / Cloudflare Workers | I/O Bound | Rust (Workers) or Go. Negligible gain for lightweight edge routing. | **Low-Medium cost**: Rewrite Cloudflare entry points. **Windows**: N/A. **AI Agent Skill**: High. | Cloudflare Workers in Rust |
| **`apps/browser-extension`** | TypeScript | I/O / DOM | Stay TypeScript. No alternative makes it clearly faster. | **Zero cost**. **Windows**: N/A. **AI Agent Skill**: High. | Standard browser web extensions |

*Uncertainties:* While Electron uses significant RAM, moving to Tauri requires rewriting native window integration plugins. OpenUI research demonstrates that moving parsers *out* of WASM back into TypeScript avoided the heavy boundary-crossing tax, advising caution before arbitrarily adopting WASM/Rust for UI-adjacent logic [1].
