## Goal
Roee has Unity projects where many scenes are empty and wants to know how full a scene is before loading it. Add packages/core/src/unity-scene-stats.ts: parse a .unity file (Unity YAML, "--- !u!<classId> &<fileId>" documents) without Unity: count GameObjects (!u!1), prefab instances (!u!1001), MonoBehaviours (!u!114) and resolve their m_Script guid to a script path through the project's .meta files (cache a guid→path index per project, built lazily, max 50k files), lights (!u!108), cameras (!u!20), renderers (!u!23/!u!137), terrains (!u!218). "empty" = no objects beyond one camera + one light. Stream the file (scenes can be 100+ MB): read line by line, stop counting details past 200k objects. Expose it in the existing unitySceneList route (packages/core/src/routes/unity-scene.ts) as stats per scene next to sizes, cached by path+mtime+size. Rules: research first how Unity Hub, Unreal Content Browser/"Open Level" and tools like UnityYAMLMerge / UAssetAPI / CUE4Parse read these files (write 5–10 lines into docs/RESEARCH_LOG.md), then build. Read-only on the game project (never write into it). Readable, documented (JSDoc) code; node:test tests next to the code with small fixture files you create; Hebrew+English texts with L(he,en); 390px phone layout; works from the phone through the hub (no PC-only APIs in the web part). Update docs/WORK_LIST.md section "Scene previews" (create it).
