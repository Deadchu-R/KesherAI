## Goal
Research only (no code). KEEP IT UNDER 1,200 WORDS.
KesherAI (Electron + Node/TypeScript, llama.cpp built in) has a cloud hub (Cloudflare Worker + a web page the user opens in the KesherAI phone app) that relays tasks to the user's PCs. The user wants a chat in the hub whose only job is task management: he writes (Hebrew or English) "add a task to…", "split this into steps", "move X before Y", "give the small ones to the local model", and a SMALL model running on the PC's CPU only (no GPU, llama.cpp `-ngl 0`, loaded on demand and unloaded after idle) answers and changes the task list (task inbox / shared board: add, edit, reorder, set priority, split into sub-tasks, assign an executor).
Find, end to end:
1. How competitors do AI task management in chat: Todoist Assist, Linear (AI triage / "Linear Agent"), Notion AI, Motion, Taskade, Asana AI Studio, ClickUp Brain, Vibe Kanban / Claude Squad / Conductor (task splitting for coding agents). What the chat can do, how it shows proposed changes (preview + confirm vs. apply + undo), how it splits a task, how it avoids duplicates.
2. Which small models (≤4B, GGUF) run acceptably on a desktop CPU (e.g. Ryzen 9 9950X3D, and a weak laptop) with reliable tool calls / JSON in Hebrew and English: Qwen3.5 2B/4B, Gemma 3/4 small, Phi-4-mini, Llama 3.2 3B, SmolLM3, Granite. Tokens/s on CPU, RAM, Hebrew quality, function-calling accuracy (BFCL or similar).
3. How to make a small model's tool calls reliable: llama.cpp GBNF grammar / JSON-schema constrained output, few tools with tight schemas, a fixed action list (add/edit/move/split/assign/priority/delete-with-confirm), retrieval of only the relevant tasks into the prompt, a fallback to a bigger model when unsure.
4. Latency: keep-warm vs. load per message, prompt caching (llama.cpp slot save/restore, cache_prompt), streaming the answer to the phone through a relay.
5. Safety: the chat may only touch tasks (no code, no shell), deletes need a confirm, nothing secret goes to the hub.
Include a "Language and weight" part covering every platform (Windows/macOS/Linux, x86 with AVX2/AVX-512, Apple Silicon, ARM laptops, Android phones running the model themselves) and what to measure first. End with a "## Tasks" section of 5-8 concrete tasks (S/M/L).

## Acceptance
Competitor table, model shortlist with CPU numbers and Hebrew/tool-call notes, reliability techniques, latency plan, safety notes, Language and weight, and the Tasks section.
