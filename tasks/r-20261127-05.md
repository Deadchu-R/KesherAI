## Goal
Research only (no code). KEEP IT UNDER 1,200 WORDS.
KesherAI (local-first AI desktop app, Electron + Node) already has: a remote MCP server on its Cloudflare hub (custom connector for claude.ai, OAuth for the owner only, tools: chat, read, list chats, approve) and a local MCP server on the PC (list models, ask a model, search knowledge, generate image, transcribe). The user wants to WORK on KesherAI from the Claude app's own interface (web, desktop, phone), like other products did, free first.
Find end to end how others did it:
1. MCP Apps (the MCP UI extension: tools that return an interactive `ui://` HTML view the Claude app renders inline): which products ship them (examples), what the views can do (buttons calling tools, forms, live updates), limits (size, sandbox, CSP, which Claude clients render them: web, desktop, mobile), and how they're declared (`_meta.ui.resourceUri`).
2. Claude Desktop extensions (.mcpb / former .dxt): one-click install of a local MCP server, manifest, how products like Notion/Figma/Blender/Unity/Unreal bridges package them, signing, updates; and Claude Code plugins/marketplaces as another route.
3. Which tools and views give the best "work from Claude" experience for an app like this: task board, approvals, model jobs (image/music/video with previews), chats, quotas, design previews; how they keep the tool list small (search/toolsets) so Claude picks the right one; auth and safety (owner only, approvals for actions, no secrets in tool output).
4. Cost: what is free (custom connectors on paid Claude plans, Cloudflare free tier, local stdio), what needs anything paid.
Include a "Language and weight" part (Worker vs. local server, view bundle size, every platform incl. phone) and end with a "## Tasks" section of 5-8 concrete tasks (S/M/L).

## Acceptance
Examples with what they do, MCP Apps capabilities and limits per Claude client, desktop extension packaging, recommended tool/view set, cost table, Language and weight, Tasks.
