## Goal
Roee wants collaborators on a KesherAI game project to need NO game engine installed at all. Only his main PC has the Unity/Unreal/Godot versions and the KesherAI plugins. Collaborators edit through KesherAI's stand-ins (scene/level views, code, data) and sync key files; the main PC applies the changes through the plugins (Undo when the editor is open, headless when closed) and sends results back (pictures, compile and play results).
Research end to end how others handle collaboration and engine-less or light clients: Unity Version Control (Plastic SCM) and its Gluon artist mode, Perforce + Unreal Multi-User Editing and Unreal's One File Per Actor, Diversion, Anchorpoint, Godot's text scenes and merge, Git LFS locking, Unity Scene merge (UnityYAMLMerge), cloud-editor tools (e.g. Bezi, Coplay, web-based level editors). For each: what a collaborator must install, how conflicts and locks work, which files move, how changes land in the real project, what breaks. Then: which file kinds can be safely edited without the engine (Unity YAML scenes/prefabs/ScriptableObjects, C#/C++ sources, Unreal .umap/.uasset need the editor), and a recommended design for KesherAI (sync channel: git or KesherAI's own hub; locks; conflict handling; how the main PC applies and reports back).

## Report
English, about 1500 words: 1) Table: tool | collaborator installs | files that move | conflicts/locks | how changes land; 2) Which files are editable without the engine, per engine; 3) Recommended design for KesherAI in steps (S/M/L each); 4) Risks; 5) Numbered sources with links.
