## Goal
Today an Antigravity task runs inside KesherAI's own process (packages/core/src/inbox-runner.ts talks ACP to `agy acp`, packages/core/src/acp.ts). When KesherAI updates or restarts, the task dies. Roee wants a side process that keeps agent tasks running through updates.

Build an "agent host": a small Node process (packages/core/src/agent-host/*.ts, its own entry, no Electron, no UI) that:
1. Is started detached by KesherAI when an inbox agent task starts (if not already running), and stays alive on its own when KesherAI quits or updates (the updater uses a detached script the same way — see packages/core/src/updates.ts ~line 457–513 for the pattern; the app's install dir is replaced by an update, so the host must run from a copy outside the install dir, e.g. the user data folder, written at start with its version).
2. Owns the ACP session with agy for the task: starts it, sends the prompt(s), the research/code nudges, the model choice and fallback, applies the inbox policy (inbox-policy.ts) to permission requests, and writes every step/event to an append-only journal file per task (JSON lines) in the KesherAI data folder.
3. Listens only on 127.0.0.1 on a random port written to a lock file with a random token; KesherAI connects with that token to watch steps live, stop, answer, or attach after a restart (reads the journal from where it left off).
4. When the task ends, writes the result, and exits when no task runs for 2 minutes. One task at a time (same as now). Heartbeats every 10 s into the lock file; KesherAI marks the task "stuck" only if heartbeats stop.
5. KesherAI side: inbox-runner delegates running to the host; on start it looks for a live host and re-attaches to running tasks (they keep their status "running", steps and phone progress continue). If the host itself is gone, the existing "cut off by a restart → back in line" path applies (commit 3833a49).
6. The update flow: an update no longer has to wait for an agent task (remove the agent-task block in /api/updates/apply added in 3833a49 only when the host is used); the host keeps the old version until its task ends, then exits; the next task starts the new host.
Keep it light (no polling loops faster than 1 s, no big deps), Windows-first (paths, detached spawn with windowsHide), secure (token, localhost only, no secrets in the journal). Add unit tests for the journal reader, the lock/heartbeat logic and the attach logic with a fake ACP agent.
Update docs/WORK_LIST.md (Morning 22.11) with what is done and left.
