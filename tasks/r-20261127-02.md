## Goal
Research only (no code). KEEP IT UNDER 1,200 WORDS.
KesherAI (Electron + Node, runs local AI models on the user's graphics card with llama.cpp and ComfyUI) already has a graphics-card guard: pause new local work, unload idle models, a temperature limit, and "free the card while Unity/Unreal Play runs". The user wants it automatic for anything heavy: when a game (e.g. Slay the Spire 2 on Steam) or a heavy program starts, KesherAI should notice and apply a profile (unload the big model, pause local work, cap GPU/CPU/RAM use, or move chat to a small CPU-only model), and undo it when the app closes.
Find, end to end:
1. How existing tools detect games and heavy apps: Windows Game Mode / Game Bar (GameConfigStore, the "is this a game" signal), NVIDIA App / GeForce Experience, AMD Adrenalin game profiles, Razer Cortex, Process Lasso (ProBalance, per-process rules), Steam (running app id via registry or steamapps), MSI Afterburner/RTSS, Discord's game detection, Linux GameMode (Feral) and macOS Game Mode. What signals they use: process lists (known-game databases), fullscreen/exclusive-fullscreen windows, per-process GPU usage (Windows GPU performance counters / NVML process list / AMD equivalents), launcher state.
2. How they let users edit profiles (per-app rules, allow lists), how they avoid false positives (browsers playing video, an IDE compiling), and how fast they react / undo.
3. Which profile actions make sense for KesherAI: unload vs. keep in RAM (reload time), cap llama.cpp threads/GPU layers, move chat to a small CPU model, pause the task inbox's local work only (cloud agents keep running), and lower ComfyUI priority.
Include a "Language and weight" part for every platform (Windows/macOS/Linux, NVIDIA/AMD/Intel/Apple GPUs, CPU-only): which parts are cheapest in Node vs. a small native helper (e.g. a Rust/C++ process watcher), polling interval and its cost, and what to measure first. End with a "## Tasks" section of 5-8 concrete tasks (S/M/L).

## Acceptance
Detection signals per platform, profile editing patterns, false-positive handling, recommended KesherAI actions, Language and weight, and the Tasks section.
