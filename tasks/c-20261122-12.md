## Goal
One combined research task in parts. Do the parts in order and write each part into the report file as soon as it is done (create the file after part A, then add to it), so nothing is lost if time runs out. To look at KesherAI's code use your file tools or simple read-only commands.

### Part A — Engine-less collaboration — collaborators without Unity/Unreal/Godot, the main PC applies through the plugins
Roee wants collaborators on a KesherAI game project to need NO game engine installed at all. Only his main PC has the Unity/Unreal/Godot versions and the KesherAI plugins. Collaborators edit through KesherAI's stand-ins (scene/level views, code, data) and sync key files; the main PC applies the changes through the plugins (Undo when the editor is open, headless when closed) and sends results back (pictures, compile and play results).
Research end to end how others handle collaboration and engine-less or light clients: Unity Version Control (Plastic SCM) and its Gluon artist mode, Perforce + Unreal Multi-User Editing and Unreal's One File Per Actor, Diversion, Anchorpoint, Godot's text scenes and merge, Git LFS locking, Unity Scene merge (UnityYAMLMerge), cloud-editor tools (e.g. Bezi, Coplay, web-based level editors). For each: what a collaborator must install, how conflicts and locks work, which files move, how changes land in the real project, what breaks. Then: which file kinds can be safely edited without the engine (Unity YAML scenes/prefabs/ScriptableObjects, C#/C++ sources, Unreal .umap/.uasset need the editor), and a recommended design for KesherAI (sync channel: git or KesherAI's own hub; locks; conflict handling; how the main PC applies and reports back).

### Part B — Live co-editing of one game scene (presence, live moves, locks) with the engine only on the main PC
Roee wants collaborators to edit the same Unity/Unreal scene at the same time and see each other, through KesherAI's engine-less scene stand-in (three.js), while only his main PC has the engine and applies the result through the KesherAI plugins. Research end to end: Unreal Multi-User Editing (Concert: transactions, locks, presence, how changes merge and persist), Roblox Team Create, Figma multiplayer (server-authoritative last-writer-wins per property), Unity's attempts (Scene Fusion), Godot collaboration plugins, CRDT libraries for scene graphs (Yjs, Automerge) vs operation streams; transport (WebSocket via a cloud hub vs LAN/WebRTC), presence UI (avatars, cameras/frustums, selection colours), per-object soft locks while dragging, undo per user, latency handling, and how the main PC turns the live session into real engine changes safely (batching into transactions, approval, checkpoints).

### Part C — Deep research — every Unity Muse tool and how to bring each into KesherAI
Roee wants a deep look at all of Unity Muse's tools and how KesherAI could offer each of them (local-first where possible, Hebrew + English, for a game developer). Cover every Muse capability and its current state (Muse may have been folded into "Unity AI" / Unity 6 AI Assistant — say what exists now, what was renamed or retired, and when): Muse Chat (project-aware assistant), Muse Sprite, Muse Texture, Muse Animate, Muse Behavior (behavior trees), Muse Sketch/level prototyping, code generation and Unity AI Generators (sprites, textures, sounds, animations, materials), Sentis/Inference Engine, and any newer Unity AI tools. For each: what it does, inputs/outputs, how it plugs into the editor (windows, asset types it creates), what model/tech is behind it if known, price/limits, and user reviews (what works, what does not). Then for each, how KesherAI can do it: which local or free models (e.g. ComfyUI/sd.cpp workflows, Qwen-Image, TRELLIS for 3D, motion models for animation, audio models), how results land in a Unity project through KesherAI's Unity package (com.kesherai.bridge) or without Unity open (KesherAI writes assets/YAML), and what is hard.

### Part D — Play a game web build on the phone (UE 5.9 Web, Unity WASM64)
Roee wants to play his Unity/Unreal game's web build on his phone through KesherAI (served from his home PC or the hub): current state of Unreal's web export (UE 5.9 or newer, third-party like SimplyStream/Tapple), Unity WebGL/WebGPU and WASM64, sizes, mobile browser limits, streaming vs download, and how KesherAI should build, host and open it on the phone securely.
KesherAI context: open-source local-first AI desktop app (Electron + React web UI, Node server, local models via llama.cpp / sd.cpp / ComfyUI), Hebrew + English, used by a game developer on a home PC and from his phone. Research end to end how the best tools do it (official docs, changelogs, repos, reviews from the last 12 months), then what KesherAI should build first.
