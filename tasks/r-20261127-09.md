## Goal
Research only (no code). KEEP IT UNDER 1,500 WORDS. Public sources only.
KesherAI is a local-first desktop AI app (Electron, local models via llama.cpp, plus cloud providers) with chats that can use a browser pane, the user's Chrome (extension), the computer (UI automation), files and code. The owner wants its chats to work "just like Claude" (claude.ai with tools, Claude Code, ChatGPT agent mode, Gemini agent mode, Manus).
Find, end to end, the user-visible behaviours that make those agent chats feel capable and trustworthy: a live task list, step folding, check-back timers, asking a multiple-choice question, permission cards (once / always per site), sign-in hand-off, take-over of the browser, progress notifications to the phone, artifacts/side panels, parallel helpers, memory, scheduled tasks, connectors (MCP), files sent to the user, resuming after a restart. For each: how it looks, when it triggers, what the user can do, and the rule of thumb behind it. Then the top 10 behaviours a weaker LOCAL model (Qwen 27B / 9B class) most often gets wrong in such loops and the known fixes (tool routing, smaller tool lists, plan-first, verifier step, retries).
Include a "Language and weight" part (what runs best where: Node/Electron main vs renderer vs a small native helper) and end with "## Tasks": 8-12 concrete tasks (S/M/L) for KesherAI.
