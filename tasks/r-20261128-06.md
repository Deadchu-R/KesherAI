## Goal
RESEARCH task (no code changes) for KesherAI, a local-first AI desktop app with a task inbox that runs coding/research tasks on several executors: a local model (llama.cpp on the PC's GPU), OpenCode Go (paid, daily cap), GhostCLI (free models, rate limits/cooldowns), Gemini (free API, research only), Antigravity (Google, quota, runs on the user's Run tap), and Claude (the user's subscription, never automatic). Today the order and the executor/model per task are picked by fixed rules (quota failover, privacy: sensitive tasks never go to providers that train on data).
Feature Roee wants: a dedicated "dispatcher" — a SMALL model running on the CPU (must not load the PC: ~1-4B, a few threads, paused while a game runs) — that (a) orders the queue, (b) picks the executor AND the model for each task with a one-line reason, (c) moves tasks when a provider runs out, and (d) has its own chat on the Tasks page (desktop and phone) where the user can ask "why is this waiting?", "move X to Y", "what runs next?", and approve proposals.
Answer end to end, with sources:
1. How others route tasks/prompts to models and agents: RouteLLM, Not Diamond, OpenRouter Auto, Martian, LiteLLM routing, Unify; agent task assignment in Devin, Factory, Cursor background agents, GitHub Copilot coding agent, OpenHands; what signals they use (task size, kind, past success per model, cost, latency, quota left) and how they explain the choice.
2. Can a 1-4B CPU model do this well? Classifier vs generative picker vs rules + small model for tie-breaks/explanations; JSON-constrained output (GBNF); measured accuracy and latency of small models (Qwen3.5 1.5B/2B/4B, Gemma 3 1B/4B, Phi-4-mini, SmolLM3) for routing/classification on CPU (tokens/s on a 16-core desktop CPU, RAM).
3. What data to keep: per executor/model success rate by task kind, minutes, tokens/cost, failure reasons — and how to learn from it cheaply (bandit / simple scoring) without a big model.
4. The chat on the Tasks page: what such an ops chat should answer and do; safe actions with Apply/Cancel; examples from competitors (Linear agents, Jira AI, GitHub Copilot Workspace).
5. Language and weight: which runtime runs the small model lightest per platform (llama.cpp CPU threads, ONNX Runtime, MLX on Apple, Windows ML/DirectML NPU), RAM and CPU % to expect, what to measure first.
Output: a short report + 6-10 concrete tasks (dispatcher service, scoring data, chat on the desktop Tasks page reusing the hub task chat's Apply/Cancel proposals, settings, phone), written to go into docs/RESEARCH_LOG.md.
