## Goal
Roee wants a node-based interface for materials and shaders inside KesherAI (its three.js 3D editor), good for both Unity and Unreal. Research end to end: Unity Shader Graph (node set, .shadergraph JSON format, URP/HDRP targets, Sub Graphs), Unreal Material Editor (node set, material functions/instances, how a material is created through Python/C++ — MaterialEditingLibrary), Blender shader nodes, three.js TSL/NodeMaterial (WebGPU/WebGL node materials), Godot visual shaders, MaterialX (as a neutral interchange), web node-graph libraries (Rete.js, LiteGraph, React Flow) and AI helpers (text → material graph, image → PBR maps). Answer: a node set and graph format KesherAI should use internally (MaterialX-like?), live preview in three.js, and how to export a graph to a real Unity Shader Graph asset and to a real Unreal material (through the KesherAI Unity package and Unreal plugin, headless when the engine is closed), what can't map 1:1 and how to show that, and how the chat/AI can build and edit graphs.
To look at KesherAI's code (plugins/model-editor, integrations/unreal, the Unity package), use your file tools or simple read-only commands.

## Report
English, about 2000 words: 1) Table: node system | node set | file format | scripting/API | what maps to others; 2) Recommended design for KesherAI (internal format, editor UI library, preview, Unity export, Unreal export, AI) with S/M/L steps; 3) Mapping table of the 40 most common nodes across three.js TSL / Unity Shader Graph / Unreal Material; 4) Risks; 5) Numbered sources with links.
