## Goal
RESEARCH task (no code changes) for KesherAI, a local-first AI desktop app that is an MCP client (stdio + HTTP transports, protocol 2025-06-18) and has its own skills, slash commands, sub-agents and tool hooks. Goal (Roee): every connector and plugin that works on Claude should work in KesherAI.
Answer end to end, with sources (official docs: modelcontextprotocol.io spec incl. authorization, Anthropic docs for Claude connectors / remote MCP, Claude Desktop extensions (.mcpb / formerly .dxt), Claude Code plugins and marketplaces (.claude-plugin/plugin.json, skills/SKILL.md, commands, agents, hooks, .mcp.json)):
1. Exactly what a Claude remote connector needs from a client: Streamable HTTP (and legacy SSE), OAuth 2.1 flow (protected resource metadata, authorization server discovery, dynamic client registration, PKCE, refresh tokens, redirect URIs for a desktop app and for a phone), tool annotations, resources/prompts, elicitation, sampling.
2. Desktop extensions (.mcpb): the manifest, how Claude Desktop installs and runs them (Node/Python/binary), user config and secrets.
3. Claude Code plugins: the plugin layout and marketplace format; how skills, commands, agents, hooks (event names, inputs/outputs) and plugin MCP servers load; what a non-Claude client must map each one to.
4. What other clients did to be "Claude-compatible": Cursor, VS Code Copilot, Windsurf, Goose, LibreChat, Open WebUI, LM Studio, Zed — which parts they support and the pitfalls.
5. A test plan: first with KesherAI's own Claude connector (hub /mcp with OAuth), then 5 popular connectors and 3 popular plugins.
6. Language and weight: what runs where (the PC's Node server vs a worker; Python/uv for Python servers), cost and isolation (sandboxing third-party servers), per platform.
Output: a short report + 8-12 concrete tasks, written to go into docs/RESEARCH_LOG.md.
