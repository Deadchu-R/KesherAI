## Goal
Write docs/research/browser-computer-control.md: how existing tools let an AI agent (1) control and DEBUG a web browser and (2) control the whole computer, end to end, so KesherAI can offer both (in the user's own Chrome through an extension, in KesherAI's built-in browser, and on the desktop).

## Look at (primary sources: official docs, repos, announcements)
- Browser: Claude in Chrome (extension tools: tabs, navigate, read page / accessibility tree, find, click/type, form input, console messages, network requests, JS, screenshots, GIF recording, per-site permissions), Chrome DevTools MCP (Google), Playwright MCP (Microsoft), browser-use, Stagehand, OpenAI Operator/Atlas agent mode, Gemini in Chrome / Project Mariner, Comet (Perplexity).
- Computer: Anthropic computer use (screenshots, click/type, per-app access, app tiers for browsers and terminals, safety rules), OpenAI computer-using agent, UI-TARS / Agent S / OS-Copilot (open source), Windows UI Automation and macOS Accessibility APIs, local vision models that can drive a desktop.

## For each
What it can do, how it talks to the browser/OS (CDP, extension messaging, accessibility tree vs pixels), how it asks for permission and keeps the user safe (passwords, payments, prompt injection from page text), what runs locally vs in the cloud, licence, and which parts work with LOCAL models.

## End with
A short recommendation for KesherAI: what to reuse (open-source libraries/protocols), what to build, the order of steps (S/M/L), and the safety rules to copy. Plain English, sources as links.

## Out of scope
Code changes.

## Report
Three lines: the recommendation, the top 3 sources, anything uncertain.
